# GPU geospatial function coverage matrix

Audit date: October 23, 2026. Baseline: the current working tree, including uncommitted expansion
work. This is a maintainer inventory, not a released-API guarantee. The [coverage backlog](./geospatial-coverage-backlog.md)
owns priorities, dependencies and acceptance criteria; this matrix owns the function/option status.
The [parallel implementation record](./geospatial-coverage-parallel-implementation.md) maps the original 78
IDs to current source, delivered models and verification. Those selected operation rows have
bounded implementations and recorded evidence; this does not imply complete upstream-library parity.

October 25 follow-up: [Kepler analysis coverage](#kepler-analysis-coverage-2026-10-25) adds six
KG items. Five now have bounded implementations; SQL remains partial. See the
[implementation and verification record](./kepler-analysis-implementation.md).

The GPU implementation survey (local research log, not checked in)
maps selected backlog items to primary GPU code, algorithm papers and CPU semantic references.
It supplies integration/portability findings and proposed benchmarks; it does not promote function
status or replace the [recorded verification](./geospatial-toolkit-expansion-follow-up.md).
See the [roadmap index](./README.md) for document ownership and historical context.

## How to read this matrix

- **Implemented**: the specific bounded operation in the row has an implementation/contract in this
  tree. It does not mean every option of the named reference API is supported or freshly verified.
- **Partial**: relevant behavior exists, but a named mode, semantic guarantee, integration step or
  evidence requirement is missing. The row states what still needs work.
- **Planned**: the target behavior is a backlog proposal. Reusable primitives do not make that
  behavior available. No public API names are being reserved by this document.
- **Excluded**: intentionally outside this compute backlog; the reason and boundary are explicit.

Inventory: **142 reviewed rows**: 135 implemented subsets, 1 partial,
0 planned and 6 excluded. All **84 backlog IDs** appear; suffixes split options
that must be promoted independently. `B-` IDs record selected existing baselines and `X` IDs record
exclusions. These counts are inventory counts, **not a percentage of upstream functionality**.

The denominator is this selected function/option inventory, not all APIs in all inspiration libraries.
An unlisted function is **unassessed**, not implicitly implemented or excluded. The existing
[public cross-reference](../../docs/api-reference/experimental/gpu-spatial-analysis-cross-reference.md)
supplies broader baseline discovery, but source contracts take precedence over stale summary rows.
Further packages and functions can be added when a consumer or audit identifies a meaningful gap.

Evidence links distinguish source/contract presence from reference generators. A linked generator
by itself does not establish execution or certify every option, GPU backend or scale. Direct upstream calls and independent composed references are different evidence;
the statistics record now distinguishes the earlier composed generalized GWR/panel references from separately executed pinned mgwr/spreg fixtures. The initial research-only
audit ran no numerical tests or benchmarks. Subsequent implementation records report their own
executed evidence; this status reconciliation does not rerun or replace it. Before promotion,
record reference version, fixture cases, executed GPU tests/device and measured capacity separately.
External links are discovery references reviewed during research; pin versions at implementation.
The subsequent [first implementation tranche](./geospatial-coverage-tranche-one.md) records executed
pinned generators, numerical GPU execution and bounded measurements separately. Its five rows
now describe implemented subsets. The later [parallel implementation record](./geospatial-coverage-parallel-implementation.md)
adds source-backed coverage for all remaining IDs and separately staged advanced modes; exclusions,
unsupported numerical models and unmeasured workloads remain explicit.

The six added areas are RS11 seasonal breaks, IN07 natural-neighbor interpolation, ST10 spatial
cross-validation, ST11 calibrated interaction, PP05 balanced probability sampling and UR05 obstacle
visibility. Their initial models now have scoped implementations. Natural-neighbor coordinates,
flow constraints, sampling designs and visibility metrics retain separate rows so a first
implementation is not reported as complete family coverage.

reference version, supported modes, coordinate/time models, null/tie/boundary rules, capacity and
convergence behavior. Attach source/contract, pinned generator/fixture, GPU execution evidence and
