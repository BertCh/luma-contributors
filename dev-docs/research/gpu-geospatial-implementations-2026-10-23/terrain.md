# Terrain and hydrology GPU prior art

Research date: 2026-10-23. Scope: current working tree, not a shipped-version claim. Read AGENTS.md, the coverage backlog, expansion/follow-up roadmaps, and implementation files. This is background research only: no repository edits, formatting, dependency installation, or tests. Feasibility and acceptance proposals below are engineering judgments; none of the external implementations was executed.

## Baseline that must survive the research

[modules/graph/src/gpu-terrain/hydrology/gpu-terrain-flow.ts](../../../modules/graph/src/gpu-terrain/hydrology/gpu-terrain-flow.ts) already supplies D8, D-infinity, Freeman/Quinn MFD, filling and flat resolution. Zero-epsilon filling uses tiled spill labels, a Boruvka spanning tree, Euler-tour rooting and bottleneck propagation ([terrain-flow-spill-fill.ts](../../../modules/graph/src/gpu-terrain/hydrology/terrain-flow-spill-fill.ts), [terrain-flow-spill-tree.ts](../../../modules/graph/src/gpu-terrain/hydrology/terrain-flow-spill-tree.ts)). Ordinary unweighted D8 cell accumulation already uses Euler-tour tree contraction with logarithmic pointer-jumping rounds ([terrain-flow-euler-tour.ts](../../../modules/graph/src/gpu-terrain/hydrology/terrain-flow-euler-tour.ts)). Weighted D8 and branching accumulation use deterministic donor pulls, single-word atomic value/readiness publication and bounded downstream walks ([terrain-flow-passes.ts](../../../modules/graph/src/gpu-terrain/hydrology/terrain-flow-passes.ts), [terrain-flow-routing.ts](../../../modules/graph/src/gpu-terrain/hydrology/terrain-flow-routing.ts)). Consequently, “add GPU filling/flow accumulation” would duplicate existing work.

The gaps are branching consumers (TE02), deliberate terrain modification (TE01), persistent nested sink structure (TE03), composed basin summaries (TE04), registration (TE05), and seamless domain partitioning (TE06). Internal workgroup tiles in filling do not make the public single-raster operator a cross-input-tile hydrology implementation. `GPUTerrainFlowDistance` follows D8 directions. Viewsheds already offer marching and bit-identical min/max-pyramid skipping; cumulative viewsheds and point horizons also exist.

## Seven candidates

### 1. FastFlow: compare weighted D8 strategies, not the existing unweighted algorithm

**IDs:** TE02 performance prerequisite; baseline accumulation validation. **Evidence class:** actual CUDA/PyTorch GPU implementation plus algorithm paper. [Jain et al. 2024, author archive](https://pubs.cs.uct.ac.za/id/eprint/1774/) describes logarithmic flow routing and depression routing; the [paper PDF](https://people.cs.uct.ac.za/~Jgain/wp-content/papercite-data/pdf/jain2024.pdf) gives algorithms and implementation discussion. It explicitly discusses avoiding host/device control-flow transfers and using fixed iteration schedules. The [author's FastFlowX package](https://pypi.org/project/fastflowx/) identifies its 2026 CUDA extension as the maintained successor. Original [FastFlow source](https://gitlab.inria.fr/landscapes/fastflow) and [FastFlowX source](https://gitlab.inria.fr/landscapes/fastflowx) returned Anubis access denial here.

**License:** FastFlowX package metadata declares `LicenseRef-Inria-NonCommercial`; the inaccessible original repository's license was not verified. Treat the publication as algorithmic evidence and the executable as a separately licensed comparator, not permissively reusable source.

**Fit:** benchmark its weighted single-receiver algorithm against luma's current deterministic pull on long stems, branching forests and repeatedly changing runoff. Reuse command-graph nodes, scans and existing Euler-tour resources; do not assume a forest algorithm handles MFD reconvergence. WGSL needs separate dispatches for global phases, explicit scratch budgeting and deterministic reduction choices. Floating sums can change with grouping even when mathematically equivalent. Acceptance: weighted CPU oracle, outlet mass balance, reproducibility and forced exhaustion. Require measured improvement over current weighted D8 before adopting another path.

### 2. WatershedAnalysis: GPU MFD dependency and transport comparator

**ID:** TE02. **Evidence class:** actual CUDA/OpenACC source, accompanying [2019 paper](https://www.mdpi.com/2220-9964/8/9/386) and [author repository](https://github.com/drstojanovic/WatershedAnalysis). Directly inspected [Kernels.cu](https://raw.githubusercontent.com/drstojanovic/WatershedAnalysis/master/Kernels.cu): it has both repeated flow-transfer steps and an indegree-driven graph version, with eight fractions per cell. **License:** no license verified; availability does not authorize copying.

**Fit:** extend consumers around `getTerrainFlowRoutingWGSL` in [terrain-flow-routing.ts](../../../modules/graph/src/gpu-terrain/hydrology/terrain-flow-routing.ts), which already computes fractions without storing eight float arrays. A transported scalar can use the existing donor-ready pull with fractional contributions. Expected downstream distance needs a reverse recurrence over finalized receivers; minimum/maximum distance have different reductions. Fractional catchments require outlet-specific probability outputs and explicit capacity, not one integer basin label.

Do not translate its ordinary value write followed by atomic indegree decrement literally: cross-address publication assumptions require review under WGSL's memory model. Use separate dispatch phases or luma's same-word readiness approach. Its materialized fractions cost 32 bytes/cell before other arrays, so benchmark recomputation versus storage. Acceptance: split/rejoin diamonds, zero-weight branches, mass conservation, fractional outlet totals and cycle/exhaustion status. Benchmark narrow rivers and broad divergence separately; iterative flow transfer can scale with path length and performs repeated arithmetic on already transported mass.

### 3. Whitebox least-cost breaching: bounded, explicit elevation editing

**ID:** TE01. **Evidence class:** CPU Rust implementation/oracle; no GPU implementation claim. The actual [BreachDepressionsLeastCost source](https://raw.githubusercontent.com/jblindsay/whitebox-tools/master/whitebox-tools-app/src/tools/hydro_analysis/breach_depressions_least_cost.rs) identifies Lindsay/Dhun inspiration, bounded pit-to-lower-cell searches and alternative cut-cost objectives. Its source header and [repository license](https://github.com/jblindsay/whitebox-tools/blob/master/LICENSE.txt) both identify MIT.

**Fit:** place a separate producer before `GPUTerrainFlow`; reuse raster-grid ground distances, cost-distance relaxation/path tracing and masks. Proposed output ports: edited surface, modification mask, cut depth, unresolved-pit count/status and required capacity. Stream burning should be separately selected and retain provenance.

The source explicitly uses float64 output to maintain very small descending increments; float32 WGSL cannot promise equivalent epsilon behavior. Initially specify a representable increment or retain a separate routing gradient, and compare costs/cuts at the declared tolerance. Independent simultaneous pit searches can overlap and alter one another's destinations; define deterministic conflict resolution or serialize bounded batches instead of silently claiming CPU-equivalent global optimality. Acceptance: embankment, deep real basin, competing pits, nodata wall, cut-depth/length exhaustion and equal-cost ties. Benchmark by pit density and window radius, reporting search scratch and modified volume rather than raster dimensions alone.

### 4. Depression hierarchy: retain nested basins and compute storage curves

**ID:** TE03. **Evidence class:** algorithm paper plus CPU C++ reference, not demonstrated GPU code. [Barnes, Callaghan and Wickert 2020](https://esurf.copernicus.org/articles/8/431/2020/) develops nested depressions; inspected [RichDEM hierarchy source](https://raw.githubusercontent.com/r-barnes/richdem/master/include/richdem/depressions/depression_hierarchy.hpp) explicitly stores children, parent, spill links, pit/outlet cells and double-precision volume fields. [RichDEM license](https://raw.githubusercontent.com/r-barnes/richdem/master/LICENSE.txt): GPL-3.0; use as an external oracle, with independent first-party implementation and attribution as appropriate.

**Fit:** extend the existing spill-edge/tree machinery and inspect [terrain-peak-prominence-tree.ts](../../../modules/graph/src/gpu-terrain/terrain-features/terrain-peak-prominence-tree.ts) as a related merge-tree primitive. A minimum spanning tree/bottleneck fill surface alone does not establish the required depression merge hierarchy. Preserve cell ownership and spill elevations; sort elevations by basin, then segmented scans yield stage-area-volume samples. Expose explicit node/edge capacities.

Equal saddles require deterministic tie policy or topology-equivalent comparison. Parent and child areas must not double-count nested cells. Use relative elevations for float32 volume calculations to reduce cancellation, with an error budget against float64. Acceptance: nested bowls, flat saddles, sealed basins, ocean links and known analytic volumes. Benchmark hierarchy construction separately from repeated stage queries. [Fill-Spill-Merge](https://github.com/r-barnes/Barnes2020-FillSpillMerge) is useful future consumer evidence; dynamic flood simulation remains outside TE03's contract.

### 5. Barnes parallel accumulation: cross-tile boundary summaries

**ID:** TE06, with EC02 seam-contract relevance. **Evidence class:** CPU/MPI distributed algorithm and source, not CUDA. [2017 paper](https://rbarnes.org/sci/2017_parallel_flow_accum.pdf) and [archived author repository](https://github.com/r-barnes/Barnes2016-ParallelFlowAccum) partition precomputed non-divergent flow, solve local contributions and exchange boundary dependencies. **License:** standalone repository license not verified; RichDEM's separate GPL declaration must not be silently substituted for this archive.

**Fit:** represent owned interiors, halo reads and boundary receiver IDs explicitly. Reuse tile metadata/ownership patterns from [gpu-raster-cross-tile-components.ts](../../../modules/graph/src/gpu-raster/gpu-raster-cross-tile-components.ts); its connectivity equivalences are not hydrology direction dependencies. Proposed phases: local routing/accumulation, compact boundary graph, global boundary solve, then local correction and reach-ID stitching. Keep decoded input chunks and persistent tile outputs separate from explicit packing.

Start with a supplied globally valid D8 direction field, then tackle cross-tile depression preprocessing separately. Tile graphs can have cycles even where cell flow is acyclic because paths can leave and re-enter tiles; avoid one topological node per tile. Acceptance: meandering seam crossings, corner diagonals, long cross-tile flats, masked seams and one outlet spanning many tiles; whole-domain equality and exactly-once runoff contributions. Benchmark seam complexity, resident memory and repeated rainfall updates. Extend to branching only after the D8 contract is demonstrated.

### 6. xDEM Nuth–Kääb: stable-ground registration first

**ID:** TE05. **Evidence class:** CPU numerical oracle/workflow, not GPU prior art. [Official worked example](https://xdem.readthedocs.io/en/stable/basic_examples/plot_nuth_kaab.html) fits horizontal/vertical shifts on stable ground and assesses median/NMAD; [coregistration catalogue](https://xdem.readthedocs.io/en/stable/coregistration.html) distinguishes this from ICP and blockwise models. [License](https://xdem.readthedocs.io/en/stable/license.html): Apache-2.0.

**Fit:** use existing terrain derivatives, raster resampling, masks, grouped/robust statistics and small linear solves in bounded iterative graph passes. Publish fitted shifts, valid stable sample count, residual summaries, iteration/convergence and conditioning status. Begin with vertical-shift baseline, then one explicitly named Nuth–Kääb model; broader registration parity is unnecessary.

Coordinates should be local and centered, with consistent horizontal/vertical units. Flat or single-aspect ground makes horizontal shift estimation weak or singular; do not turn a failed fit into a zero correction. Acceptance: planted subpixel shifts, outliers, changed surfaces excluded by mask, varying slopes, rank deficiency and resampling boundaries. Compare parameters and holdout residuals to a pinned xDEM release. Benchmark many repeated DEM pairs and fit/apply costs separately. Spatially correlated differencing uncertainty is an additional deliverable, not implied by residual NMAD.

### 7. Circuitscape: resistance connectivity as a solver consumer

**ID:** EC03. **Evidence class:** CPU Julia implementation/oracle; official documentation describes CPU threading and sparse solvers, not an established WebGPU implementation. [Project](https://github.com/Circuitscape/Circuitscape.jl), [solver documentation](https://docs.circuitscape.org/Circuitscape.jl/stable/compute/) and [official download/license statement](https://circuitscape.org/downloads/) verify the implementation and MIT designation. This is a lower-priority prototype.

**Fit:** build a grounded conductance Laplacian and use [modules/graph/src/gpu-core/gpu-conjugate-gradient-program.ts](../../../modules/graph/src/gpu-core/gpu-conjugate-gradient-program.ts) plus [gpu-sparse-matrix.ts](../../../modules/gpgpu/src/gpu-data/gpu-sparse-matrix.ts); compute current from potential differences. Start with one source/sink pair on a small connected raster, explicit 4/8 neighbors and resistance-to-conductance rules. No new general solver abstraction is needed.

Check the true residual and current conservation independently of the iterative solver's convergence flag. Strong conductance contrasts challenge float32; Circuitscape explicitly warns that tightening tolerance does not remove arithmetic error. Ground disconnected components individually, report unreachable pairs, and bound simultaneous right-hand sides to control memory. Acceptance: series/parallel resistor networks, barriers, narrow corridors and extreme contrasts against double-precision Circuitscape. Benchmark topology/preconditioner setup separately from repeated pairs; do not transfer its hundreds-of-millions-cell CPU claims to browsers.

## Additional inexpensive scope and deferred comparison

TE04 can compose current watershed/reach outputs with grouped elevation quantiles, physical lengths and slopes. Use pinned GRASS/pysheds outputs plus independent reductions; label the oracle composed. Do this before a new terrain kernel if a consumer needs basin dashboards.

Viewshed optimization has no new TE backlog ID: [rfshed CUDA source](https://raw.githubusercontent.com/mi-v/rfshed/main/cuvshed/cuvshed.cu) uses angular/range samples and horizon projection; [MIT license](https://raw.githubusercontent.com/mi-v/rfshed/main/LICENSE) verified. Its [README](https://github.com/mi-v/rfshed) acknowledges approximation. Useful as a speed/error comparator, not a replacement for luma's existing bit-identical pyramid path. Test narrow ridges, grazing sightlines, nodata, observer changes and curvature; report false-visible/false-hidden rates.

## Shared gates and recommendation

[WGSL specification](https://www.w3.org/TR/WGSL/) is the portability authority: baseline float atomics/float64 and global in-dispatch barriers must not be assumed. Reuse explicit command-graph phases and existing gated continuation/status conventions; no hidden host convergence reads or fallback. Preserve unknown/unresolved results.

Prioritize TE01, a narrow TE02 transport consumer, and TE04 compositions; prototype TE06 boundary solving and TE03 hierarchy next. TE05 is a separate robust-fit workflow; EC03 remains application-led. For every candidate measure compile, upload, GPU execution, optional readback, peak scratch and repeated-update costs on 256², 1024² and largest fitting grids. Include adversarial long paths, skew and capacity failure; publish precision/conservation errors beside throughput. CUDA and CPU timings are comparative context, never browser speedup evidence.
