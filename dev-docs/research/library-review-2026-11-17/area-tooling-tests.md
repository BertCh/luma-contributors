# Tooling, tests, build, packaging and repository health

**Release verdict — hold the public analysis release from this checkout.** All 11 analysis export entries have their declared ESM, CommonJS and declaration files on disk. Those files are stale: 156 current TypeScript sources have no corresponding emitted JavaScript, including a module re-exported by the public `analysis-core` barrel. The workspace export check can pass against an older, internally consistent build. The package also labels Arrow optional while four built entry points import it, and its MIT-only metadata omits licenses identified in shipped source. Lenses should stay private. I found two separate defects in its built lazy loaders.

**The first testing fix is small and consequential.** Two numerical oracle checks accept NaN where the expected value is finite. A shared comparator already in the repository handles this correctly. For the maintainer’s memory problem, the strongest evidence points to the size and concurrency of compiler programs: analysis tests directly reference **223 MB of JSON**, the main test typecheck includes all workspace sources, and its runner overrides the caller’s heap setting with 16 GB. I found no measurement that singles out a particular generic type.

## Findings

### TOOL-01 Numerical oracle checks accept NaN against finite expectations [P1] [testing]

- **Evidence.** Network accessibility throws only when `Math.abs(value - expected[index]) > tolerance`. With `value = NaN`, that condition is false. Six call sites use this helper for gravity, ratios, catchments and related results. Neighbor search repeats the condition for distances and weights, and a missing array element also produces NaN under subtraction. Across analysis, 81 spec files define a local function whose name begins `assert`, `expect` or `compare` followed by `Close`, `Near`, `Approx` or `Float`; I confirmed the defect in the two named specs. [gpu-network-accessibility.spec.ts:51](../../../modules/analysis/test/gpu-network/network-accessibility/gpu-network-accessibility.spec.ts#L51), [gpu-network-accessibility.spec.ts:269](../../../modules/analysis/test/gpu-network/network-accessibility/gpu-network-accessibility.spec.ts#L269), [gpu-neighbor-search-u5.spec.ts:40](../../../modules/analysis/test/gpu-spatial-analysis/neighbor-search/gpu-neighbor-search-u5.spec.ts#L40), [gpu-neighbor-search-u5.spec.ts:141](../../../modules/analysis/test/gpu-spatial-analysis/neighbor-search/gpu-neighbor-search-u5.spec.ts#L141)
- **Why it matters.** These comparisons can certify a broken numerical output even when topology and array lengths remain correct. This finding concerns the JavaScript oracle; it makes no claim about current GPU results.
- **Proposed change.** Extract `expectNumericArrayClose` from `compareParity`. Check length, compare nonfinite values explicitly, then apply the caller’s existing tolerance. Pin finite-versus-NaN, missing row, equal infinity and expected-NaN cases. Migrate the two confirmed sites first. **S, nonbreaking.** [parity-wp6-compare.ts:20](../../../modules/analysis/test/oracles/parity-wp6-compare.ts#L20)
- **Confidence:** high.

### TOOL-05 A dead watcher can report a successful current typecheck [P1] [tooling]

- **Evidence.** `typecheck-status` treats a log as settled when it ends with `Found … errors. Watching for file changes.` and its mtime is older than 1.5 seconds. It never verifies the watcher PID or ties a completed cycle to the current edits. The existing November 11 log still ends `Found 0 errors`. The watch command redirects to a shared path and has no single-instance guard. [scripts/typecheck-status.mjs:15](../../../scripts/typecheck-status.mjs#L15), [scripts/typecheck-status.mjs:24](../../../scripts/typecheck-status.mjs#L24), [package.json:29](../../../package.json#L29), [.typecheck/watch.log:3865](../../../.typecheck/watch.log#L3865)
- **Why it matters.** An old clean log satisfies the success condition indefinitely. Two invocations can start two compilers and overwrite the same log. These mechanisms explain a false success and a route to memory contention; I did not establish how earlier orphan processes were created.
- **Proposed change.** Give the watcher a small supervisor with a per-checkout lock, PID/start token, completed-cycle identifier and signal forwarding. Have `status` reject a dead owner or a cycle predating the requested edits. Preserve filtered diagnostics, and label filtered success explicitly. **S–M, nonbreaking for valid runs.**
- **Confidence:** high.
