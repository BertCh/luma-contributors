# Dataframe, point cloud and computation record (2026-11-19)

The review covered 193 TypeScript source files, 47 command-node producers and 202 specs in the assigned test directories.  
Of the thirteen earlier DPC findings, twelve are fixed and one is resolved by the documented decision to require Arrow. The strongest regression pins cover lossy decimal conversion, snapshot bounds, execution identity and point-cloud origin handling. Two documentation closures have no automated prose pin.  
Seven new wrong-result findings were reproduced on the CPU in public helpers or their generated output. One further public call visibly fails on valid Arrow input. Seven additional wrong-result leads have a source trace and a discriminating GPU probe.  
The first alpha fixes should preserve the missing-cell sentinel during CPU key packing, preserve per-node pipeline specialization in computation records, and make Arrow preparation independent of inherited object properties.  
The first device checks should use a constant indicator column, a finite mean whose sum overflows float32, and a variogram with one excluded high-valued row. Each has an independent numerical answer and a small fixture.  
All eleven point-cloud producers now expose their output objects. The November 18 no-colors change also has writers for every legal output subset inspected. Neither observation establishes numerical correctness for every port.

## Method

The area lead was `gpt-6.2-astra`. Six `gpt-6.1-sol` reviewers covered classification and standardization, groups/joins/forests/indicators, pair enumeration and capacity, temporal/cube/Arrow preparation, point cloud, and computation records/wide readback. I read all six reports, including their coverage exclusions, and checked the cited source for every proposed wrong result or visible failure. The review used the checkout at `bd8279a4`, the working-copy roadmap, and `bdc715ea` as the comparison base. Findings describe this checkout. The separate KI staging tree has its own implementation and verification record.

The slices read the classification, standardization, group, join, forest, indicator, calendar, period, time-filter, cube and Arrow preparation implementations. The point-cloud slice read all eleven producer implementations, origin, grid, attribute, covariance and ICP helpers. The pair slice read the shared grid, empirical pair path, count publication, parameter packing, fit budgeting and compatibility forwarding. The recording slice followed graph description, annotations, capture identity, snapshot bounds, resource ownership, decimal upload and readback. It sampled the wider record type/printing surface and generated numeric kernels. The remaining point-pattern, distance-function, optimizer and eigensolver internals received selective reading. Specs were read for their inputs, assertions and oracle provenance. The 202 files are an inventory, not a claim of 202 full spec reads.

I examined the path-scoped `git log --stat` and `git diff bdc715ea..HEAD`, including shared graph support, barrels, construction snapshots and pipeline test utilities. The four source roots changed in 66 files, with 2,741 insertions and 922 deletions. I followed missing cell and period values into grouping and joining, time validity into cube inputs, classifications into colors and counts, keyed grid construction into pair publication, and source annotations into record validation. I checked the full `73e8f638` change, the join status snapshot, and the installed alpha.16 public graph types and factory behavior relevant to this area.

CPU probes piped TypeScript through the installed `esbuild` into `node --input-type=module -`. Imports targeted individual source files. Executions included real Arrow tables, decimal formatting and narrowing, cell-period packing, parameter packing, point-cloud origin and WGSL generation, record annotation/validation, encoded pass description, and failure-injected timing allocation. Additional probes called production CPU operations, selected test oracles, and explicitly identified float32 arithmetic models. Host graph declarations and descriptors can establish construction behavior. None of these probes dispatched WGSL. No test, gate, build, browser, benchmark or network lookup ran. The successful November 18 gate steps are historical evidence.

### DPC-101 — Missing cells become groupable keys

`packGPUCellPeriodKey(0xffffffffffffffffn, 0, 3, 'ones')` returned hex `fffffffffffffffc`. The helper describes itself as the CPU equivalent of `GPUCellPeriodKeys`. A missing input needs an absent result or the unchanged reserved key. The control `packGPUCellPeriodKey(0x123fn, 1, 3, 'ones')` returned `123d` as expected. A negative period also escaped the host guard and returned `-1n`.

The public GPU input explicitly reserves both all-ones words for “no cell”. The shader initializes both output words to all ones and excludes that cell before changing bits. Group statistics skips only the reserved key and key join likewise treats the reserved pair as missing. The host has produced the wrong key before any submission. A group appearing downstream remains a device prediction. See `modules/analysis/src/dataframe-analysis/value-cube/gpu-cell-period-keys.ts:86`, line 295, `modules/analysis/src/dataframe-analysis/group-statistics/gpu-group-statistics.ts:227` and `modules/analysis/src/dataframe-analysis/key-join/gpu-key-join.ts:147`.

## Limits of this report

No shader was executed. The seven GPU W leads are candidates for qualification, not seven measured GPU defects. The additional Metal division hypothesis has weaker evidence and is excluded from that count. Allocation-boundary probes used metadata or injected small state. They did not allocate billion-row datasets, run distributed point-cloud jobs or measure adapter limits.

The review assessed pair enumeration, membership, binning and capacity. Statistical estimands, external K/Diggle equivalence, all optimizer interiors and the broader spatial points findings have separate owners. Forest controls cover sampled formats and missing-value routes. They do not constitute native external parity for every supported model. Full binary point-cloud fixture regeneration, all record exporters, every ontology alias, every package consumer and every test assertion were outside the read set.

The code and test counts distinguish public source presence, construction behavior and numerical evidence. A docs section, catalog entry, kernel-audit case or November 18 gate result cannot substitute for the specific readbacks listed above. No repository change, test run or release qualification is claimed by this report.
