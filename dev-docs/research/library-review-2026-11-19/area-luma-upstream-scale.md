# luma.gl integration and GPU scale (2026-11-19)

The landed library uses published luma.gl entry points throughout the inspected source. The five grid readers now use the alpha.16 coordinate function, and the former private copies can stay retired. The bump tests exercise all five readers, but use the same index builder as the reference even for density and flow.  
One scale failure was reproduced through the public API. A binary transform rejects 33,554,432 spatial-weight rows in two valid chunks because it checks the size of a global buffer that this operation never allocates.  
Of 498 public command-node producers, 90 have a chunked or tiled primary route. None of the 498 provides host paging of its primary input. Chunked inputs can still require a single allocation proportional to the total row count.  
Three numerical findings warrant GPU readback. One concerns the local column profile and two concern published primitives considered for adoption. None is an observed alpha.16 GPU wrong result.  
Public segmented reduction is a small adoption for ungated calls. Public PCG is a substantially different migration. On a two-row system its declaration already exceeds the local command budget at the local default iteration count.  
Two failure-injection probes also reproduced lost GPU resource ownership. Before publishing, fix the chunk rejection and cleanup paths, run the three small numerical probes at the end-of-iteration gate, and qualify the exact luma.gl version named in the release record.

### Which inputs actually scale

In the census, **packed** includes resident grids, textures, full-column views and producers driven by dimensions or parameters. **Chunked** means the primary dataset can arrive in separate bindings. **Tiled** means at least one public mode also bounds significant scratch by a work tile or batch. The terrain exception uses resident tiles. Neither resident tiles nor chunk descriptors imply streaming from host memory. The following roster defines the non-packed classifications. ## Limits of this report

The evidence establishes one public host-side rejection and two resource-cleanup failures. It establishes neither an alpha.16 GPU wrong result nor a current performance or memory benchmark. Historical Apple/Metal behavior, prior gate passes and the supplied publication dates have distinct evidentiary status from the CPU probes run here.

The export and primary-route censuses are substantially more complete than the allocation census. This report does not give an exact peak allocation, bind-group count, scratch lifetime or maximum input for every specialization of all 498 producers. The 466 unresolved binding-array sites, published primitive internals and optional output combinations prevent that conclusion. The worked limits are reproducible under their stated dimensions and options. They do not promise successful allocation on a loaded adapter.

The six slices sampled shader bodies, tests, copied-code candidates and consumer call sites. Detailed temporal algorithms, every CPU/GPU twin, every raster and network dispatch specialization, real device-loss recovery and all consumer readback costs were not read or measured exhaustively. Fixed-commit website counts used Git reads only. The unexecuted probes and partial coverage are the reasons the roadmap retains device qualification, route-specific resource planning and named upstream acceptance fixtures.
