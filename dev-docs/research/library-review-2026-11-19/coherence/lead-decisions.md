# Lead decision on items the routers set aside as "breaking"

These findings were set aside because fixing them changes what existing calls return. Under
decision 9 of COMMON-W3.md that is a correctness fix: plan and implement them (wave 4), in every
form, recorded as behaviour fixes. For DEF-08: require a finite nonnegative `beta` for the
exponential and power decay modes (explicit `beta: 0` stays valid). For DEF-13: one default
iteration budget for both forms, the GPU class's; a caller wanting the longer reference budget
passes it. For FLT-04: default `centerCoordinates` to true.

Options: retain the documented implicit zero rate, or require a finite nonnegative `beta` for those two modes while preserving explicit `beta:0` and binary `{threshold}` or `{costLimit}` calls. Reviewer recommends: use the discriminated settings union in both packers and probe weights at costs `[1,9]` with omitted and explicit `beta:1`. In-repository call sites: 51 direct packer calls. Two inline literals omit the rate in a rate-dependent mode, at `modules/analysis/test/gpu-network/network-accessibility/gpu-network-accessibility.node.spec.ts:325` and `modules/analysis/test/gpu-network/network-cost-weights/gpu-network-cost-weights.node.spec.ts:90`.
