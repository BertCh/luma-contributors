# w2-trajectory-pointcloud

## 1. Done
1. Trajectories. `GPUTrajectoryEncounters` and `GPUTrajectoryClosestApproach` take only `mask`; `trackValid` prop, `resolveTrajectoryTrackMask` and the "both given" check are gone. Validation messages now say `mask` (`<id> mask length must equal trackCount` / `... the track count`). Kernel-internal prop names `trackValid` in `encounter-kernels.ts` / `closest-approach-kernels.ts` stay (private, shader binding name). `GPUTrajectoryThinning`: `output.mask` alias and check removed; the class reads and validates `output.validity` and messages name `output.validity`. Hampel/outlier `flags` untouched.
2. `GPUDatumGridTransform.mask` is now required (no `validity` alias); `GPUPointCloudStatisticalFilter.validity` required (no `mask` alias). Both checks "both given" removed; a short `mask must be given` / `validity must be given` requirement remains so an untyped caller gets a named message, not a TypeError.
3. Point-cloud row direction. `PointCloudRasterGrid` has only `origin`, `cellSize`, `width`, `height`: no affine, no signed cell height, so the direction cannot be derived and a contradiction cannot be detected. Default is now `'south'` (new `getPointCloudRowDirection(grid)` in `pointcloud-grid-index.ts`, used by `getPointCloudCellSource`, Surfaces and SMRF grid index; Height and Ground use the cell source). Documented in the type TSDoc and `docs/api/pointcloud-analysis.md`. To match the terrain rule the grid would need an `affine` (or a signed `cellSize`/`cellHeight` whose sign means south) from which the class reads the direction and rejects an explicit contradiction.
   Specs: `gpu-pointcloud-row-direction.spec.ts` rewritten: Surfaces (north, south, default; pinned literals `[1,2,3,11,12,13,21,99,23]` north and `[21,99,23,11,12,13,1,2,3]` south), Height cell/bilinear/IDW in all three (hand-worked values plus independent JS bilinear and IDW oracles; per-point result identical in every direction, terrain laid out with `arrangeRasterRows`), Ground in all three (half-covered grid plus a spike, so a flipped layout fails). `gpu-pointcloud-smrf.spec.ts`: every oracle scenario now runs for north, south and default; classes identical, `groundSurface` compared row-mirrored for south/default. `gpu-pointcloud-advanced.spec.ts`: the three Height tests (tilted plane, IDW near centres, overflow recovery) run in all three directions. New helper `test/gpu-pointcloud/row-direction-fixtures.ts`. Evidence of the change: before editing specs 11 tests failed with exactly row-mirrored `groundSurface`, Surfaces output and Height values; after, the same inputs give the mirrored outputs.
4. Consumers updated in modules/docs/tests: kernel-audit cases (`cases-cells-and-joins.ts` `mask`; `cases-movement-semantics.ts` thinning `validity`; `cases-pointcloud-and-datum.ts` filter `validity`, datum `mask`), `modules/lenses/test/computation-lenses/kernel-records.spec.ts` (filter `validity`), `global-coordinates*.spec.ts`, `gpu-datum-grid-transform.node.spec.ts`, `geospatial-validation.node.spec.ts`, `gpu-pointcloud-analysis*.spec.ts`, `gpu-pointcloud-advanced.spec.ts`, encounters/closest-approach specs, contract-completion spec (alias tests replaced by "no longer accepted" tests), `docs/api/gpu-spatial-analysis/operators-lines.md`, `docs/api/geospatial.md`, `docs/api/pointcloud-analysis.md`. Nothing in `modules/lenses/src`, `modules/kepler` uses the changed names.
