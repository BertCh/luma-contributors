# Regional airline flow and cut reference

This note records the independent CPU reference used to check the GPU flow scene. The executable reference is [aviation-capacity-flow-reference.mjs](./aviation-capacity-flow-reference.mjs), with its generated results in [aviation-capacity-flow-reference.json](./aviation-capacity-flow-reference.json).

The scene ranks airports inside `[-125, 25, -105, 50]` by the bundled all-source incoming-plus-outgoing scheduled-count sum, keeps the top 24 with stable source-index ties, and retains 338 observed directed pairs among those airports. The count field is the BTS On-Time Reporting Carrier scheduled-flight count. The bundled manifest explicitly says cancelled flights are included in that count; the data covers reporting operating carriers and is not a complete national or marketing-carrier total. The directed arcs are therefore used only as illustrative integer link budgets. They do not estimate realized operation, physical capacity, passengers, or bookable connections.

The GPU problem adds a virtual source and sink to the 24 mapped airports. Single-pair mode connects those gates to the selected airports using 1,000,000-unit gate budgets, which exceed the whole regional link total. Balanced mode calls `prepareGPUNetworkFlowDemands` with a 24-element demand vector: SEA and PDX each supply half the requested flow, while LAX and SAN each demand half. This helper creates the same two virtual gate nodes and four terminal edges. Virtual nodes and edges are not drawn or counted among the airport records. A cut equality is a certificate over the augmented graph. In a fixed-budget run that fulfills its request, the solver stops early and does not seek a maximum-flow cut.

For delay-weighted runs, each original link cost is `round(max(0, meanDepDelayMinutes))`; early departures have zero cost. The integral objective is the sum of allocated link units times these rounded minutes. It is an abstract proxy score, not expected traveler delay. At the default Western network and 100% budget share, the CPU reference gives SEA→SAN maximum flow 4,203 with equal cut capacity, 1,000-unit minimum-score allocation score 6,790, and balanced SEA/PDX→LAX/SAN allocation score 4,479. Maximum-flow results at 50% and 25% shares are 2,097 and 1,045, each with equal cut capacity. A 4,000-unit minimum-score request at 25% share serves 1,045 units, leaves 2,955 unserved, certifies a cut of 1,045 and has exact score 21,281.

The underlying data catalog describes its source as the U.S. Bureau of Transportation Statistics On-Time Reporting Carrier data. BTS documentation for the reporting program and table coverage is available at [On-Time Reporting Carrier Data](https://www.transtats.bts.gov/TableInfo.asp?QO_fu146_anzr=b0-gvzr&gnoyr_VQ=FGJ). The implementation uses the bundled snapshot rather than fetching live data.
