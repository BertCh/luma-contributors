# Bounded control-wiring review

This initial CPU-only review checks newly added compile-mode controls and display selectors after the block and population control defects were reported. It does not execute the GPU, certify every transition, or alter runtime source. The final numerical acceptance ledger remains provisional.

The shell forwards user changes and scene writes marked `notify` to `instance.setOption(id, value, snapshot)` in `src/shell/story-view.ts` around lines 1916–1925. The `apply: 'compile'` annotation alone does not recreate a scene. Accordingly, the review traced the actual scene controller, wrappers, compile-key sets, option keys, parameter writes, layer requests and stored callbacks. Missing literal comparisons inside one method were treated only as candidates. The shared Deck host also sets `_animate: true` while the map is active (`deck-host.ts:293,830`), and `analysis-effect.ts:86` invokes the active controller’s `encode` on each frame. Pausing a scene timeline does not stop this render loop. Therefore a dirty-buffer update does not require a separate layer refresh merely to execute; CPU-created layer props still require their appropriate refresh path.

## Concrete finding sent to the owner

`osm-history-contributors.compute.ts:611` includes the z-score probe layer only when the CPU variable `probeSourceRow >= 0`. The `years`, `kind` and `inspect` update branches at lines 521–543 update that variable and its GPU index buffer but originally did not call `ctx.requestLayers()`. Summary publication updates charts and readouts only. The host rereads `getLayers()` on explicit `updateLayers` at `deck-host.ts:479`, not on every animated frame.

A transition from an inspected contributor/window with no matching row to one with a valid row therefore leaves the previously absent probe layer absent until another display change refreshes layers. The reverse transition leaves a layer whose index is now the unavailable sentinel. This mismatch was reported and the parent authorized a bounded correction. Two `requestLayers()` calls now follow `writeProbeIndex` in the affected filter/inspect branches. The real absent → valid → absent UI harness measures actual WebGPU render draws bound to the probe-index buffer; wave 15 passes the three-state sequence with actual draw deltas 0 → 4 → 0 across four frames each. Contributor #1 has 0 → 50,014 → 0 sampled rows and the middle probe is source row 16. The first attempt omitted the necessary creation-year precondition and timed out without browser/GPU errors; both reports are retained in [data-osm-wave15-acceptance.json](data-osm-wave15-acceptance.json). Compute scheduling is unchanged.

The broader suspicion that OSM dirty-only branches might stop computing while playback is paused was rejected after examining the shared continuous render loop. Import-wave width and temporal bucket/cell-mode changes affect existing GPU-backed outputs; the lack of `requestLayers` there does not itself establish a defect.

Earthquake query, county query, earthquake standardization, fire topology and sinusoidal projection showed matching control-update paths in the independent reviewer’s source check. This remains a bounded source review, not a whole-application control coverage claim. The reported block/population corrections and unresolved numerical failures retain their separate acceptance status.
