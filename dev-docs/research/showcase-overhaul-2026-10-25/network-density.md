# Chicago network density and inhomogeneous K: research and assumptions

## Source data

The story uses the bundled `chicago-roads` OpenStreetMap drivable network and `chicago-places` Overture Places snapshot. The road snapshot contains 29,557 nodes and 77,140 directed arcs and is described as the largest strongly connected component. The places snapshot contains 105,808 mapped points, confidence at least 0.5, with broad categories including retail, restaurants/cafés, and grocery. These are source-manifest facts; counts are not estimates of all businesses or customer visits. See the [OpenStreetMap copyright and licence notice](https://www.openstreetmap.org/copyright) and [Overture Places attribution](https://docs.overturemaps.org/attribution/places).

## Method references

- Okabe, Satoh and Sugihara (2009), [A kernel density estimation method for networks, its computational method and a GIS-based tool](https://doi.org/10.1080/13658810802475491), develops network-distance kernel intensity estimation and discusses the bias of a naive kernel on a network, including excess density near vertices.
- Ang, Baddeley and Nair (2012), [Geometrically Corrected Second Order Analysis of Events on a Linear Network, with Applications to Ecology and Criminology](https://doi.org/10.1111/j.1467-9469.2011.00752.x), proposes geometric correction for network K and extends the method to inhomogeneous intensity. It motivates treating first-order intensity variation separately from residual second-order interaction.
- The [spatstat.linnet reference manual](https://spatstat.r-universe.dev/spatstat.linnet/doc/manual.html) documents linear-network inhomogeneous K and the Ang correction. It is an implementation reference; the contributor implementation is evaluated on its own documented formula and status outputs.

## Analysis choices

- The study network is the largest connected component of an induced downtown Chicago road subgraph. Its bounding box is explicit in the scene and its network length is computed from retained undirected street edges. The source graph is symmetrized, so OSM one-way restrictions are not represented; nonpositive-length edges are omitted instead of being assigned an artificial minimum. Routing runs over the complete retained graph with no cost limit. A non-converged cost matrix or invalid node-density status withholds the density map; a capped or disconnected distance is never treated as a zero contribution. Zero leave-one-out event intensity withholds inhomogeneous K while preserving a valid density map.
- Mapped places are filtered to the projected bounding extent of the retained study-network nodes and selected broad category, then assigned to the nearest retained street intersection within the displayed snap limit. The original place points and assigned network nodes are shown separately, and the reported median/maximum displacement makes this vertex snap visible. Repeated assignments to the same intersection remain distinct events.
- Network KDE uses the contributor's triangular shortest-path kernel. For each event, its kernel is normalized by the integral over the full retained network, approximated by node-based edge-length quadrature: each unique undirected edge contributes half its length to each endpoint. Thus the node quadrature weights sum to the retained network length. This is a trapezoidal approximation on the simplified graph, not a continuous exact integral or a claim about unbiasedness for every network process.
- The intensity estimated at each event is read from a GPU KDE query at its assigned node with that event excluded. The extra query has zero quadrature weight, so it does not change the normalizer. This leave-one-out estimate also handles multiple events snapping to the same node. Inhomogeneous K then uses complete event-to-node shortest-path matrices, the event intensities, explicit radii, and the contributor's Ang geometric correction with network-length normalization. This is descriptive evidence about interaction after an estimated first-order baseline; it is not a significance test or a causal statement.
- Overture coverage reflects source aggregation and mapping. Counts are not business census, footfall, demand, nor ground truth. The analysis does not correct for uneven Overture capture within the local network.

## Reproducible local audit

The chosen geographic study box is `[-87.67, 41.85, -87.61, 41.91]`. The independent CPU reference `retail-network-intensity-reference.mjs` reads the same bundled binary columns, projection, edge-pair rules, induced subgraph, largest-component rule, deterministic shuffle, snap filter and Dijkstra costs. It yields 2,509 retained nodes, 4,077 unique undirected edges and 484,581.4 m of network length. At the default 80 m snap limit, eligible counts are 2,929 restaurants/cafés, 179 grocery places, 2,270 retail places and 5,378 combined places; even grocery has 125 eligible events at the exposed 50 m minimum. The selected sample is 96 per category, seed 1. The reference explicitly preserves float32 projected coordinates, the retained-node extent, and category-concatenation order for the combined sample; changing any of these can change a seeded sample.

The same reference computes complete event-to-node distances and leave-one-out triangular KDE intensities. Zero-intensity event counts for restaurant/café, grocery, retail and combined are 22/27/28/30 at 300 m, 10/11/14/10 at 600 m, and 1/1/6/5 at 1,000 m. At 1,500, 2,000 and 3,000 m every sampled event has positive leave-one-out intensity across all four categories. The scene defaults to 2,000 m while retaining shorter bandwidths to show when K is undefined. For every category and all six bandwidths, CPU quadrature integration recovers 96 events to floating-point precision.

The reference also evaluates the uncorrected ordered-pair sum at 1,500 m radius and all three documented denominators. For the default retail sample at 2,000 m KDE bandwidth, K is approximately 66.241 km with network-length normalization, 47.766 km with inverse-intensity-sum normalization and 34.444 km with squared inverse-intensity normalization. These uncorrected values are not compared with the Ang complete-random identity. `check-retail-network-reference.mjs` checks eight category/bandwidth support-and-mass cases, three independent uncorrected K endpoints, and valid status/identity visibility for three Ang normalization variants. Production GPU verification is pending.
