# Upstream workarounds register

Status date: 2026-11-19. Integration target: published `@luma.gl/*@10.0.0-alpha.16`.

This register tracks gaps against [upstream-first-plan.md](./upstream-first-plan.md) and [upstream-proposals.md](./upstream-proposals.md). Analysis paths omit `modules/analysis/src/`; bare filenames share the preceding directory. Recheck symbols before retirement. The luma.gl fork that preceded this repository (commit `e0ed33791`; code public on `BertCh/luma.gl`, branch `reference/map-contributors-pre-split-code`) holds working code and tests for many of the "what luma.gl needs" entries; [research/fork-comparison-2026-11-13](./research/fork-comparison-2026-11-13/README.md) maps each to its fork path.

## How to read the table

| Status | Meaning |
| --- | --- |
| dropped | The capability is unavailable or limited. |
| workaround | Local code supplies a missing API; delete when available. |
| accepted regression | We accept published performance/scale limits. |
| local kernel | Local code overlaps a published class whose contract lacks required options (section 4); delegate when compatible. |
| consumer-owned | Application, lens or dependency packaging work, outside the active upstream workaround list. |
| frozen | Upstream API request paused pending measurements; a consumer may already have a local adaptation. |
| dated qualification | A recorded device/version result, not a current capability or throughput guarantee. |
| unmeasured | No current comparative throughput result. |

“What luma.gl needs” states what permits restoration/delegation; work proceeds without waiting for upstream.

### Bump behavior and qualification risks

- **Interior grid boundaries are device-sensitive:** the nominal CPU reference evaluates every
  operation with round-to-nearest binary32. WGSL permits 2.5 ULP division error and either adjacent
  rounding result, so the published builder need not choose the same interior cell. For x=40 in
  [0,41] with 41 columns, the lead's Metal run selected column 39 while the nominal CPU model gives
  40. Independent rational/NumPy quotient enumeration permits [39,40]; this is consistent with the
  accuracy contract, without establishing the GPU's exact instruction sequence. The Kepler GPU
  regression now requires both the independently bounded cells and exact same-device public-builder
  agreement. It retains exact counts/sums and the CPU test still rejects the old physical-cell floor.
  See [WGSL floating-point accuracy](https://www.w3.org/TR/WGSL/#floating-point-accuracy).
- **Grid arithmetic adapted:** alpha.16 uses direct arithmetic for ordinary zero-crossing bounds
  and rescales only when `maximum > 3.402823466e+38 + minimum`. All five local functions were
  removed in favor of the public export. For x=-177 in [-180,180], 360 columns, encounters,
  region statistics and interpolation change from cell 2 to 3; density and flow remain at 3.
  In the nominal float32 model, x=0 in [-3e38,3e38] maps to 180 (old density/flow: 0).
  Density and flow CPU test oracles now round uploads and each grid operation to float32,
  including the overflow guard. The other three oracles are brute-force and have no grid
  formula or production CPU twin to change. Node pins and fixed expected-cell references pass;
  `modules/analysis/test/analysis-core/grid-coordinate-bump.spec.ts` supplies 30 headless cases
  covering the five actual reader kernels, a published `GPUGridIndex` builder, active flow dimensions,
  positive/zero-crossing bounds, exact edges, inclusive maximum, upload rounding and overflow.
  Encounters now scan a conservatively rounded coordinate range instead of an adjacent-cell
  half-shell: even the same builder formula can assign exact-distance neighbors two columns
  apart. Higher-track filtering and wrapped-cell deduplication retain one visit per unordered pair.
  Review 2 replaces world-coordinate slack with search reach and rounding padding in cell units,
  bounded independently of translation. Partial-longitude grids also reject raw longitude
  separation above 180 degrees before the great-circle distance test, so padding cannot admit
  a seam-crossing pair in only one track order.
  Region/IDW range padding can hide the mismatch, so the headless cases additionally probe
  the function extracted from each reader's generated shader and check the occupied builder cell.

#### Public density literal formatting

The published grid count/atomic-sum formatter emits
invalid WGSL such as `3e+38.0` for integer-valued scientific notation. `GPUPointDensity`
initializes a supported `float32x4` bounds view through one conditional `-grid-bounds` compute
node on that path and passes it to both builders; ordinary literal paths are unchanged. Node
parses both accumulation modes, and the public headless regression requires counts `[0,1]`
and sums/values `[0,7]` at the inclusive maximum. The lead's v2-2 verification passed these
public paths. Review 2 additionally snapshots bounds once and mutates the caller's literal
tuple in the same headless cases; that extension awaits the lead's next run.
[Proposal 1's separate formatter correction](./upstream-proposals.md#separate-open-correction-large-literal-bounds-formatting-luma-112)
requires both published builders to compile raw literal bounds at ±2e38 and ±3e38 before
retiring this workaround; a shared resident bounds comparison cannot qualify that fix.

#### Alpha.16 GPU qualification (Metal, 2026-11-18)

- **Grid overflow probe, all five readers — resolved:** the first run passed 25 of 30 cases, with all five
  runtime-bound overflow probes returning 0 instead of 180. The expected value remains 180:
  f32 bounds are ±3.0000000054977558e38, exceed the overflow-guard threshold, normalize to ±1,
  and give `(0 - (-1)) / (1 - (-1)) * 360 = 180`. No edge branch applies. The fixture readers and
  published builders use literal bounds, while the old surrogate probe loaded them from storage.
  That changes specialization of the extreme divisions. The new probe matches literal bounds and
  flow's actual active-dimension view and writes a completion marker beside a poisoned coordinate
  word. On overflow it now reads the fixture's `GPUGridIndex` builder's occupied cell on the same device, asserts
  reader/builder agreement, and records the CPU model's 180 separately. Both all-three agreement
  and device agreement differing from the model pass; reader/builder disagreement fails with all
  three cells and the classified outcome in the message. The other 25 cases remain unchanged.
  The first diagnostic rerun stopped at the reserved WGSL binding name `diagnostic`; it is now
  `probeResults`, and a Node AST check validates every fixture binding with validateWGSLIdentifier.
  A separately stamped runtime-bound probe remains diagnostic. `f32(1 / 3e38)` is subnormal
  (about 3.333334e-39), so reciprocal rewriting/flush is a plausible Metal explanation for runtime
  scaled bounds becoming zero; this is not established without the new GPU diagnostic results.
  Submission precedes readback, and buffer mapping waits for the queued staging copy. No upstream
  WGSL was forked or modified. The rerun passed all 30 cases: reader and builder agree on the
  device in every case. This fixture does not qualify production density's separate
  `GPUGridBinning`/`GPUGridAggregation` pairings; their later qualification is recorded above.
- **Cost-distance continuation round count — scheduling-dependent diagnostic:** alpha.16 had
  2 failures in 10 reported runs (167/163 versus one-shot 168), compared with alpha.14 0 in 9
  (seven isolated and two full runs). A subsequent 20 reruns all passed; the earlier
  intermittent observations remain recorded, with no production fix claimed. File:
  `modules/analysis/test/gpu-raster/cost-distance/gpu-cost-distance-continuation.spec.ts`.
  Final costs match the independent float32 Dijkstra surface. Readback audit:
  `submitGraph` submits before either status read; upstream WebGPU `readAsync` submits a staging
  copy on the same queue and awaits `mapAsync`; the continuation loop awaits both reads before
  resubmission. No missing queue-wide `onSubmittedWorkDone` dependency is established. Caller-owned
  state/working values are imported buffers; continuation stamps are a sub-view of that state,
  not scratch recycled between executions. Declared read/write resources order resets, rounds,
  group gates and finalization; per-dispatch bindings are supplied again each encode.
  Sufficient cause: `raster-relaxation.ts` reads neighboring costs and stamps and
  writes them in place within one dispatch; sweep `storageBarrier()` is only workgroup-scoped.
  The existing CPU oracle explicitly chooses a slow legal visibility order. A new diagnostic
  model over three 16-cell tiles proves forward live visibility can converge in 2 rounds while
  reverse/snapshot visibility takes 4, with identical exact costs. The cost-distance follow-up
  additionally reproduced 168 versus 163 rounds on the original spiral in a float32 visibility
  model, both matching the independent Dijkstra surface digest
  `9f69bcb1193b92ff9b9727f5771f091eb359e7870c22c14170e85d22f6274526` (33,984 finite cells).
  This establishes a sufficient cause, not the exact historical Metal workgroup order.
  The current regression checks independently correct costs, status/state agreement and every
  submission's iteration budget; natural schedules need not have equal counts. Forced visibility
  controls keep their exact count expectations. The follow-up records earlier passing lead GPU
  controls; revised headless correctness cases and the separate timing benchmark still need the
  lead's GPU run. No production GPU relaxation arithmetic or graph topology changed.

#### Other API qualification notes

- **Compile metadata:** alpha.16 defaults to no kernel metadata collection. `compile()` and
  `compileAsync()` now accept `{kernelMetadata: 'layout' | 'source'}`. The Kepler overrides at
  `modules/kepler/src/session/metered-command-graph.ts` now accept and forward these options
  unchanged to `super`, while continuing to record physical transient bytes. The Node regression
  covers both methods and metadata modes; the recorder combines opt-in public facts with its
  factory and explicit annotation tables.
- **Record metadata and timing (ROAD-106 / ROAD-111):** precedence is field by field for
  defined values: explicit annotations, then factory annotations, then public preflight facts.
  Compile `'layout'` collects entry point, workgroup size and declared binding
  name/type/group/location; `'source'` also collects WGSL. Local `sourceText` independently
  controls retention and cannot recover source from layout-only collection. The 513-row radix
  route has eight metadata-bearing nested scans among 24 nodes; its sixteen sort-owned nodes
  lack those facts. Declared slots imply neither specialization constants nor resource/view
  links. Unknown ownership permits lower-bound bytes only when an estimate exists; otherwise
  `bytes: 0, bytesKind: 'unavailable'` is a placeholder. These resource-information limits,
  formula/provenance/loop semantics and intermediate capture gaps remain separate from the
  retired graph `recording` signature adaptation.
  `GPUComputationNodeMetrics.gpuTimeMs` is always milliseconds: measured `2` and `0` survive
  without endpoints, while unavailable duration stays absent. Endpoint-only `10/12 ms`
  produces relative `gpuBegin/gpuEnd = 0/2` with `timebase: 'ms'` and no invented duration.
  See [the recording guide](./upstream-first-recording.md#snapshots-and-timings) for fixtures.
- **Histogram qualification (LUMA-101):** use `collectHistogramEdgeEvidence` in
  [draft 02](./upstream-drafts/02-histogram-edges-and-domains.md#minimal-reproduction-using-published-packages)
  for both literal and GPU-view domains. The predecessor of `1` (`0x3f7fffff`), `1`
  (`0x3f800000`) and successor (`0x3f800001`) over `[0,49]` with 49 bins must produce
  `[1,2]` followed by 47 zeros. This rejects a correction that moves the predecessor up a bin.
  The integer `0..49` fixture expects 48 ones then two; `[0,41,82,123]` expects `[1,1,2]`.
  Historical **alpha.12** equal-edge `[2,1,1]` and wide-view all-in-bin-zero observations do
  not qualify alpha.16. The collector covers six edge fixtures in each form; run draft 02's
  separate `reproduceHistogram` invocation for the wide case in **both** literal and view forms:
  values `[0,1,-5e37,5e37]`, domain `[-1e38,1e38]`, 16 bins. Retain both 16-bin vectors with
  package version, adapter/backend and browser/version; expect
  `[0,0,0,0,1,0,0,0,2,0,0,0,1,0,0,0]` in each form. Retain every bin for every edge fixture
  and form with the same provenance. Alpha.16
  remains **unverified pending readback**; the second-adapter run is also outstanding.
- **Bounds-query qualification (LUMA-103):** use proposal 1's
  [public investigation and runner](./upstream-proposals.md#1-one-grid-cell-coordinate-formula-public-as-wgsl).

- **Inspection previews:** public `GPUCommandGraphInspector` and
  `GPUCommandGraphEncoding.readResource` (`@luma.gl/graph/gpu-core`) can inspect current

- **Expressions:** `GPUExpressionOperation` in `@luma.gl/graph/gpu-core` supports

- **Segmented reduction adoption:** the public implementation clamps offsets to input length,
  returns zero for empty segments even for min/max, forbids output/input buffer identity, and

## 5. Upgrade procedure for each `@luma.gl` alpha bump

1. Record the installed candidate version for each `@luma.gl` package, its package root and the dated evidence obtained for that version. Read release notes and compare public entry-point exports/declarations. The audit above concerns installed `10.0.0-alpha.16`; the 2026-11-18 Metal results qualify only the stated grid/cost-distance probes, not a complete release or throughput gate.
2. From the repository root, run the maintained [upstream inventory tools](../scripts/upstream/README.md): `node scripts/upstream/exports.mjs <node_modules/@luma.gl> <out.json>`, `node scripts/upstream/usage.mjs <exports.json> <usage.json> <report.json>` and `node scripts/upstream/diff.mjs <old.json> <new.json> <old @luma.gl root> <new @luma.gl root>` (quote roots containing spaces). Keep both inventories, installed roots and measured versions; exclude `_internal`. Usage counts the exact imported entry; `usedThroughOtherEntries` reports equivalent re-exports separately. With both roots, `CHANGED DECLARATIONS` identifies changed declaration-text hashes under shared names, and `CHANGED STRING VALUES` identifies changed exported strings or plain-object string properties, including WGSL. `UNLOADED ENTRY` means runtime comparison could not load that entry: inspect the error and leave its coverage unknown. No changed hash is a numerical parity result; names alone miss all these changes. Dated research scripts are historical snapshots, not upgrade dependencies.
3. Select routes from actual downstream usage and adoption candidates, then inspect their public implementation and generated WGSL, including the paired builder/reader, packer/shader or producer/status consumer, even when both hash sections report zero. Declaration/string hashes do not inspect class methods or private generated WGSL: an implementation-only eligibility change in similarity search can change classifier votes while both hashes stay unchanged. Use changed hashes as additional inspection leads. Reading installed implementation files for evidence does not authorize importing private paths or copying upstream code. Check requested APIs against this candidate, including `GPUScatter` (public at alpha.16), raster validation, query shader-plan and predicate-pass helpers. Record exact entry, selected route, limits, contract differences and the source/Node/GPU evidence actually obtained, with unrun probes explicit. Delegate eligible rows only after non-trivial parity coverage; retire each adaptation separately. PCG requires compatible scheduling/status and continuation, and classifier search requires finite-score/tie/vote qualification.
4. Follow the exact integration-pin list and qualification prerequisite in the [release package guide](./release-package.md).
