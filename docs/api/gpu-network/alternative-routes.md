# Alternative routes

`GPUAlternativeRoutes` finds up to `routeCount` shortest simple **edge** paths for each
source/target query. Construction records a GPU command graph; routing, queue control and
output publication stay on the GPU. It does not read results back to choose a CPU fallback.

The search is uniform-cost best-first search over simple path prefixes. A binary min heap
in GPU storage orders prefixes by accumulated float32 cost, then by lexicographic CSR edge
sequence (a proper prefix sorts first). With nonnegative weights a prefix is a lower bound
on every extension, including under float32 rounding. Therefore each destination removed
from the heap is the next requested route, and the search can stop after `routeCount`
destinations without enumerating all more expensive routes. The heap is per query; queries
run independently. This is not Yen's algorithm and has no polynomial worst-case bound.

- Directed CSR topology; parallel CSR edges are distinct routes.
- No repeated vertices, even through zero-cost cycles or self loops.
- Equal-cost routes use CSR edge sequence order, independent of heap insertion order.
- Negative, NaN and infinite weights and out-of-range neighbors are impassable on both backends.
  GPU also rejects float32-overflowed accumulated sums. No negative-weight guarantee is offered.
- Invalid source/target IDs return zero routes with `complete = 1`. Source equals target
  returns exactly the singleton vertex route, with cost zero and no edges.
- Path capacity is `nodeCount` vertices per output route; simple paths always fit. The last
  edge slot and all unused slots contain `0xffffffff`; missing lengths are zero and costs
  are infinity. Counts never exceed `routeCount`.

See [traversal phases, limits and usable results](./concepts.md#traversal-phases-limits-and-usable-results)
for phase completion and stopped results.

`maximumExpansions` (default 100,000, range 1–10,000,000) bounds examined CSR slots per query per encoding.
`maximumFrontierSize` (default 1,024, range 1–65,536) bounds simultaneous pending prefixes per query.
An examination includes rejected invalid/cyclic edges. Popping a destination does not consume
an examination. If either capacity would be exceeded, the search stops immediately and
sets `complete = 0` while work remains; it never discards a pending path and continues to claim
completeness. Using the last allowed examination alone is not a stop: the next heap pop may be
the destination and needs no examination.
`counts[query]` bounds the usable prefix under the backend's arithmetic. GPU orders by accumulated
float32 cost and lexicographic CSR edge sequence. CPU orders by float64 cost, then CSR edge
sequence, and rounds costs to float32 only at publication. Thus CPU routes costing 2^24 and
2^24+1 can publish the same 2^24 payload while retaining their internal cost order. A retained CPU
route with two 2.5e38 edges publishes Infinity; use `counts` and lengths to distinguish it from
padding. Already published routes remain a sorted, certified prefix in the backend's internal order,
but the requested top-k result is incomplete. Empty incomplete output does not imply
unreachability. `complete = 1` means either k routes were found or the frontier was exhausted,
so fewer than k routes certifies that no additional admissible simple paths exist.

The CPU function and operation honor explicitly supplied `maximumExpansions` and
`maximumFrontierSize` with the same stopping and `complete` semantics. Omitted CPU budgets
remain unbounded; GPU defaults and device shape caps still apply to the GPU contributor.

Limits remain 256 vertices and 32 requested routes. Heap scratch storage requires
`4 * queryCount * maximumFrontierSize * (2 + 2 * nodeCount)` bytes, plus
`4 * queryCount * (4 + 2 * routeCount)` metadata bytes. Construction rejects scratch exceeding
the device's `maxStorageBufferBindingSize`. The search uses seven storage bindings and two
private node-sized arrays; heap swaps copy a full path record, so queue operations cost
`O(nodeCount * log(maximumFrontierSize))`. These bounds are not throughput claims. Large
frontiers, many cheap dead ends and zero-cost plateaus can still be expensive. Increasing
capacity does not guarantee completion.

Every execution rebuilds queue state from current GPU endpoints and topology/weights, and
clears outputs. Reusing the compiled graph after weight updates preserves no stale routes.
Both operation forms capture search budgets at construction. Mutating the caller's props later
cannot raise `maximumExpansions` or `maximumFrontierSize`, including when an operation is lowered
again. Each named getter is read once per construction; the CPU descriptor receives those same
captured values. A two-edge chain constructed with one allowed examination remains incomplete with zero
retained routes after such a mutation.

Independent fixtures are generated by
[`alternative-routes.py`](https://github.com/visgl/luma-contributors/blob/master/modules/analysis/test/oracles/alternative-routes.py)
using NetworkX 3.5 `all_simple_edge_paths` on a multigraph, followed by complete cost/CSR-edge
sorting. Dyadic fixture costs have exact float32 sums. Node tests audit generated kernels,
private memory and device binding bounds; queued headless correctness tests compare every route vertex,
edge and cost, ties, zero-cost cycles, multiedges, missing-route padding, queue/budget
truncation, same-graph updates and nonfinite/overflowed costs. These tests do not establish
a broad performance envelope.

## Reading retained routes

`getGPUAlternativeRoutesOutputLayout({queryCount, routeCount, nodeCount})` describes the five
padded columns and per-query `complete` flags. `decodeGPUAlternativeRoutes` accepts their typed
arrays, `Uint8Array` byte readbacks or `ArrayBuffer` values, including byte subviews. It rejects
partial elements or missing words and returns copies without padding. Query `count` bounds the
readable retained-route prefix. A zero-query batch returns no query rows or flags.

```ts
import {computeAlternativeRoutesOnCPU, decodeGPUAlternativeRoutes}
  from '@luma-contributors/analysis/gpu-network';
const output = computeAlternativeRoutesOnCPU({
  topology: {offsets: Uint32Array.of(0, 1, 1), neighbors: Uint32Array.of(1), weights: Float32Array.of(2)},
  sources: Uint32Array.of(0, 1), targets: Uint32Array.of(1, 0)
}, {routeCount: 1});
const decoded = decodeGPUAlternativeRoutes(output, {queryCount: 2, routeCount: 1, nodeCount: 2});
console.log(decoded.queries[1]); // {count: 0, routes: [], complete: true}
```

This query's zero routes are certified independently. A retained prefix can instead have
`complete: false` when its search budget is exhausted. K-shortest uses a separate batch status;
its decoder does not manufacture per-query certificates from that batch flag.
