Alternative routes

GPUAlternativeRoutes finds up to routeCount shortest simple edge paths for each source/target query. Construction records a GPU command graph; routing, queue control and output publication stay on the GPU. It does not read results back to choose a CPU fallback.

The search is uniform-cost best-first search over simple path prefixes. A binary min heap in GPU storage orders prefixes by accumulated float32 cost, then by lexicographic CSR edge sequence (a proper prefix sorts first). With nonnegative weights a prefix is a lower bound on every extension, including under float32 rounding. Therefore each destination removed from the heap is the next requested route, and the search can stop after routeCount destinations without enumerating all more expensive routes. The heap is per query; queries run independently. This is not Yen's algorithm and has no polynomial worst-case bound.

  • Directed CSR topology; parallel CSR edges are distinct routes.
  • No repeated vertices, even through zero-cost cycles or self loops.
  • Equal-cost routes use CSR edge sequence order, independent of heap insertion order.
  • Negative, NaN and infinite weights, out-of-range neighbors, and float32-overflowed path sums are impassable. No negative-weight shortest-path guarantee is offered.
  • Invalid source/target IDs return zero routes with complete = 1. Source equals target returns exactly the singleton vertex route, with cost zero and no edges.
  • Path capacity is nodeCount vertices per output route; simple paths always fit. The last edge slot and all unused slots contain 0xffffffff; missing lengths are zero and costs are infinity. Counts never exceed routeCount.

maximumExpansions (default 100000, maximum 10000000) bounds CSR edge examinations per query. maximumFrontierSize (default 1024, range 1–65536) bounds pending path prefixes. An examination includes rejected invalid/cyclic edges. Popping a destination does not consume an examination. If either capacity would be exceeded, the search stops immediately and sets complete = 0; it never discards a pending path and continues to claim completeness. Already published routes remain a sorted, certified prefix under the above weight contract, but the requested top-k result is incomplete. Empty incomplete output does not imply unreachability. complete = 1 means either k routes were found or the frontier was exhausted, so fewer than k routes certifies that no additional admissible simple paths exist.

Limits remain 256 vertices and 32 requested routes. Heap scratch storage requires 4 * queryCount * maximumFrontierSize * (2 + 2 * nodeCount) bytes, plus 4 * queryCount * (4 + 2 * routeCount) metadata bytes. Construction rejects scratch exceeding the device's maxStorageBufferBindingSize. The search uses seven storage bindings and two private node-sized arrays; heap swaps copy a full path record, so queue operations cost O(nodeCount * log(maximumFrontierSize)). These bounds are not throughput claims. Large frontiers, many cheap dead ends and zero-cost plateaus can still be expensive. Increasing capacity does not guarantee completion.

Every execution rebuilds queue state from current GPU endpoints and topology/weights, and clears outputs. Reusing the compiled graph after weight updates preserves no stale routes.

Independent fixtures are generated by alternative-routes.py using NetworkX 3.5 all_simple_edge_paths on a multigraph, followed by complete cost/CSR-edge sorting. Dyadic fixture costs have exact float32 sums. Node tests audit generated kernels, private memory and device binding bounds; real headless tests compare every route vertex, edge and cost, ties, zero-cost cycles, multiedges, missing-route padding, queue/budget truncation, same-graph updates and nonfinite/overflowed costs. These tests do not establish a broad performance envelope.
