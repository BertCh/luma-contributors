GPU Network

:::caution Experimental @luma-contributors/analysis/gpu-network is an initial, experimental entry point. APIs may change between releases without a deprecation period. :::

Overview

@luma-contributors/analysis/gpu-network provides analysis contributors for networks stored as CSR adjacency, passed as one topology: GPUNetworkTopology (offsets, neighbors, weights, optional nodePositions): weighted reachability and isochrones (isoband or cell-outline polygons), path extraction, service areas, neighborhoods, snapping, cost matrices, accessibility scores, subgraph filters, coarsening, network statistics, node-aligned analytics columns, origin-destination flow aggregation, edge bundling, adjacency-matrix images, and network construction and analysis from line data (noding, turn-restricted line graphs, map matching, network K function). Each contributor declares resources and command nodes into a caller-owned GPUCommandGraph through getCommandNodes(graph) (GPUCommandNodeProducer). It never compiles, submits, encodes, or reads back.

See network structure, alternative routes, edge centrality and spatial topology extensions for the bounded expansion APIs, their result contracts and reference checks.

When to use it

Use GPU Network for map and road-network tasks that need bounded, renderable results: isochrone bands that recolor as a cost limit moves, a path that follows a dragged endpoint, a statistics panel or analytics columns for deck.gl styling, or aggregated flows and bundled edges for drawing.

The generic graph algorithms live in GPU Graph, and the network contributors build on them rather than replace them:

  • GPUNetworkAnalyticsColumns publishes degree, in-degree and weak component columns on the caller's CSR views with analysis-owned kernels, then normalizes the columns for styling. Published luma.gl graph algorithms (GPUGraphAlgorithmsPageRank, GPUGraphAlgorithmsCoreNumber, GPUGraphAlgorithmsLabelPropagation, GPUGraphAlgorithmsModularityOptimization) accept only physical GPUGraphAlgorithmsTopology, so call them yourself when you need ranking, core numbers or communities, or their raw outputs and convergence status.
  • GPUNetworkStatistics reduces a CSR to one summary row (counts, components, degree histograms, optional modularity) for a stats panel.
  • GPUNetworkReachability is a multi-source, cost-limited shortest-path search with isochrone bands and cycle-safe predecessors, all written to caller-owned views. Use GPUGraphAlgorithmsSingleSourceShortestPath when you need plain bounded shortest paths from one source and the GPU Graph topology and status contracts.
  • GPUGraphAlgorithmsForceLayout and GPUGraphAlgorithmsSpatialForceLayout position nodes; GPUEdgeBundling then turns the straight edges into renderable polylines.

Quick start

Use the complete GPU walkthrough for device creation, buffer imports, submission, typed readback and cleanup. For reachability, replace its point-density inputs with this complete three-node directed CSR fixture. The only edge is 1 → 2 with cost 2; node 0 is isolated.

export const reachabilityInputs = {
  topology: {
    offsets: Uint32Array.of(0, 0, 1, 1),
    neighbors: Uint32Array.of(2),
    weights: Float32Array.of(2)
  },
  startNodes: Uint32Array.of(1),
  costLimit: Float32Array.of(10),
  costBreaks: Float32Array.of(0, 2, 5, 10)
};

Import every array once, then create scalar uint32 views for offsets, neighbors and start nodes, and scalar float32 views for weights, cost limit and cost breaks, with lengths equal to their array lengths. Pass the three topology views together as topology to GPUNetworkReachability, and the remaining views as startNodes, costLimit and costBreaks. Set maximumIterations: 4 for this fixture.

Allocate the following outputs in separate buffers and pass their views as output:

Port Format and rows Expected readback
costs float32, 3 [Infinity, 0, 2]
bands uint32, 3 [0xffffffff, 0, 1]
bandCounts uint32, 4 [1, 1, 0, 0]
status.converged uint32, 1 [1]
status.iterationLimitReached uint32, 1 [0]

There is exactly one start slot. Every slot is active when startCount is omitted; if reserving spare slots, supply a one-row uint32 startCount view containing 1. Spare zero-filled slots would seed node 0 too. Cost breaks must be initialized in ascending order in the edge-weight units; a node belongs to the first break greater than or equal to its cost, or 0xffffffff beyond the final break. Node 0 stays unreachable and contributes to no band.

Compile, encode, submit and read these buffers with the walkthrough's lifecycle. Check iterationLimitReached with the costs: when it is 1, propagate incompleteness, suppress dependent results, or continue/fall back rather than treating unreached nodes as proof of no route.

Limits and compatibility

  • GPU Network is experimental and WebGPU-only.
  • CSR graphs use packed views only. Edge weights must be non-negative where a contributor takes costs.
  • Each contributor's TSDoc lists its non-goals. The GPU Core maintainer roadmap (dev-docs/roadmap.md) tracks what is still open.
