GPU Network operators

GPUNetworkReachability

Compute travel-time costs, bands and predecessors from one start intersection over a directed road network.

::lens{scenario=gpu-network.network-reachability rung=result caption="Follow travel times across 1,199 intersections; the farthest is about 262.7 seconds from the start."}

Maximum: output.costs has at most getGPUNetworkReachabilityMaximumNodeCount(device) (16777216 on a default device) rows, laneCount * nodeCount, because the frontier queues take 8 bytes per row.

Single- or multi-source shortest-path costs over a directed CSR road network with isochrone bands, band counts, predecessors, and a convergence flag. Relaxation is chaotic Bellman-Ford over a compact GPU frontier queue with a round-stamped visited set: each of the maximumIterations rounds is one indirect dispatch sized by the previous round's pushes, so converged frames dispatch nothing and nothing is read back. Within a round each workgroup chains up to localIterations (default 32) hops through workgroup memory, so a path of h hops needs about ceil(h / (0.7 * localIterations)) + 4 rounds (the budget of recommendReachabilityIterations, which GPUNetworkServiceAreas and GPUNetworkIsochrones share); costs are identical for every setting. Predecessors are cycle-safe: the smallest strictly cheaper tight in-neighbor, or across equal-cost (zero-weight) edges the smallest tight in-neighbor one BFS level closer to a strict entry or a source, found in up to maximumTieIterations extra rounds (default 4). maximumIterations counts rounds, one graph node each, not hops. With the default localIterations, a budget of about h / 22 plus a few rounds suffices; 48 covers the demo networks. The optional output.unresolvedCount (one uint32 row, requires output.predecessors) counts reached nodes that still have no predecessor because the tie phase stopped at maximumTieIterations; 0 means every reached node has its tie-rule predecessor, and status.converged is unchanged. recommendReachabilityIterations() suggests a first-guess maximumIterations from the network size, and adaptReachabilityIterations() grows or shrinks it from the last frame's output.status.iterationCount and output.status.converged readback. startCount is a number (compiled in) or a one-row view (per frame). Build CSR on the GPU with GPUCOOToCSR; a reverse CSR gives "cost to reach" isochrones. The contributor and both operation forms capture named constructor budgets and port/status maps once, including inherited getters. Later props mutation cannot raise the validated round limit; activeIterations remains a per-frame buffer control clamped to that limit. Each round reads its index from its own 256-byte dispatch slot ([x, y, z, round]), never from the WGSL text, so every round of a phase shares one pipeline: one reachability compiles one relax and one tie-level pipeline at any maximumIterations, and so do the label rounds of GPUNetworkServiceAreas.

The optional output.status.relaxationCount and output.status.reachedEdgeCount (two uint32 rows each, a 64-bit count as low and high words) are an inflation probe. relaxationCount is every edge scanned by every relax visit, including the chained hops and all lanes; reachedEdgeCount is the out-degree sum of every node with a finite final cost, the edges a label-setting Dijkstra scans once. getGPUNetworkReachabilityInflation(relaxationCount, reachedEdgeCount) returns their ratio (1 is work-efficient, NaN when nothing was reached). Delta-stepping or near-far is only worth building when the measured inflation exceeds 3. The counters add one atomic per workgroup per round, so leave them off in production.

graph.add(new GPUNetworkReachability({
  topology, startNodes: starts.importToGraph(graph), costLimit: costLimit.importToGraph(graph),
  costBreaks: costBreaks.importToGraph(graph), maximumIterations: 48,
  output: {costs, bands, bandCounts, status: {converged}}
}));

GPUNetworkCentrality

Measure outward closeness of sampled pivot intersections from weighted road searches over the network and its transpose.

::lens{scenario=gpu-network.network-centrality rung=result caption="Compare 8 sampled pivots; each reaches 1,199 intersections, and the highlight has the highest closeness."}

Radius-bounded betweenness and closeness centrality of a directed weighted CSR network, exact from every node as a pivot or estimated from a sample. It needs the network and its transpose (topology and reverseTopology, the same edges reversed with bitwise-identical weights, for example from GPUCOOToCSR; an undirected network that lists both directions with equal weights may pass one topology twice) and the pivotNodes to measure from. Outputs (at least one): betweenness (per node), closeness, harmonicCloseness and reachedCounts (per pivot), and status.converged.

Optional one-row uint32 output.status.iterationLimitReached records any reachability, path-count or dependency phase that exhausted its round budget. It can be requested without converged or zeroWeightCycle. A detected zero-weight cycle alone clears converged and sets zeroWeightCycle, while leaving iterationLimitReached = 0; more rounds cannot fix that cycle. If different batches encounter both conditions, both diagnostic flags can be 1. A zero limit flag alone does not certify defined betweenness; request converged or zeroWeightCycle as well. The contributor publishes incumbent centralities on a round-limit exit and rewrites every requested port on each encoding. The graph operation has the same ports; the exact CPU twin never sets iterationLimitReached, including on a zero-cycle result. Status views must use separate physical buffers from inputs and other outputs, even when imported with different graph IDs.

Pivots run laneCount at a time (default recommendLaneCount(), about 1M expanded nodes per batch; closeness outputs are bit-identical for every lane count). Each batch runs one lane-expanded GPUNetworkReachability (costLimit is the radius, maximumIterations and localIterations as there; the defaults are 64 and 16). Closeness comes straight from those costs: one workgroup per lane reduces the reached count, cost sum and harmonic sum in a fixed order. Betweenness adds Brandes' (2001) accumulation on the tight edges, those with cost[u] < cost[w] and cost[u] + weight == cost[w] in f32, exactly as the relaxation computes it. The sigma phase (path counts) is a push-ready, pull-sum frontier schedule: a node is queued when its last tight predecessor releases it through an atomicSub on a counter that starts at its tight in-degree, then sums its predecessors' sigma in reverse-CSR order. The delta phase mirrors it from the nodes without tight out-edges, summing sigma(v) / sigma(w) * (1 + delta(w)) in forward-CSR order. Each batch adds the lane-ordered sum of its deltas (skipping each lane's own pivot) times betweennessScale to the output, zeroed once, so results are deterministic for a given laneCount. Both phases use maximumIterations rounds each, one pipeline for every round and batch. Scratch memory is the frontier state, three laneCount * nodeCount word arrays, and a packed copy of both CSRs made once per encoding.

Compile cost: every round of every batch is an unrolled command node, so the graph holds about batchCount * phases * min(maximumIterations, nodeCount) nodes, where phases is 1 for the reachability search alone and 3 with betweenness (search, sigma and delta), plus a few nodes per batch. The exact count is the read-only property estimatedCommandNodeCount, and the constructor throws above 32,768 nodes (for example 64 batches x 3 phases x 1,000 rounds would be about 192,000). Exact all-pivot betweenness on graphs above roughly 15,000 to 20,000 nodes with the default laneCount now exceeds the cap, so large graphs need sampled pivots, a lower maximumIterations or a higher laneCount. A graph continuation (re-entering the graph until convergence, which would remove the need to unroll rounds) would remove the limit, but the published luma.gl compiler does not provide one yet. Per-dispatch gating exists but does not reduce the node count.

Conventions (oracle test/oracles/network-centrality.py, networkx 3.7):

  • Betweenness equals networkx.betweenness_centrality(G, weight='weight', normalized=False) on a DiGraph when every node is a pivot, and betweenness_centrality_subset(G, sources=pivots, targets=list(G), ...) for a sample, times betweennessScale. Endpoints are not counted and no 1/2 factor is applied (halve the result for an undirected graph that lists both directions). For estimates from a sample use betweennessScale: nodeCount / pivotCount.
  • Distances run outward from the pivots. networkx's closeness_centrality and harmonic_centrality on a DiGraph use incoming distances, so the oracle compares with closeness_centrality(G.reverse(), u=pivot, wf_improved=False) and harmonic_centrality(G.reverse(), [pivot]). Swap topology and reverseTopology to get networkx's incoming convention. closeness is (r - 1) / S for r reached nodes (the pivot included) and cost sum S, 0 when S is 0; the Wasserman-Faust factor is not applied.
  • costLimit (a one-row per-frame view) is an inclusive radius: nodes beyond it and paths longer than it are not counted. networkx has no radius option; the oracle uses an explicit Brandes over a cutoff search that equals networkx when the radius is infinite.
  • Edges of weight exactly zero between two nodes of equal cost are tight and are counted like any other edge on a shortest path: on s -1-> a -1-> m -0-> t -1-> u the pivot s gives a, m, t the dependencies 3, 2, 1, as networkx does. A positive weight below half an ulp of the cost, which float32 absorbs (1 at a cost of 2^24, 3 mm at 100 km in metres), is never tight: the edge is left out of the path counts, a node reached only across it is a root with one path, and the run still converges. Counting zero-weight edges needs the zero-weight tight edges to form no cycle. With a cycle (an undirected zero-weight edge listed in both directions is one) the number of shortest paths is not defined (networkx requires positive weights for the same reason): status.zeroWeightCycle is 1, status.converged is 0 and the betweenness values are incomplete. Give such edges a positive weight or merge their end nodes. Self-loops are never on a shortest path. Harmonic closeness skips nodes of cost 0, and parallel edges count as separate paths.
  • Out-of-range pivots are ignored and their per-pivot rows are 0. status.converged is 1 when every batch's reachability and, with betweenness, both phases finished within maximumIterations and ordered every reached node.
  • Path counts (sigma) are a float32 mantissa with a separate base-2 exponent: exact below 2^24 paths per pair, rounded to 24 bits beyond, and never out of range (the corner-to-corner count of a 67 x 67 unit lattice exceeds the float32 maximum). Delta rounds once per division (within 2.5 ULP in WGSL), addition and multiplication and once per added term, all terms positive, so a node's relative error is at most h (7 + K) 2^-24 for a longest tight chain of h hops and largest tight out-degree K, plus (pivotCount + 2) 2^-24 for the sum over pivots.
  • The sigma and delta phases run one hop per round (localIterations applies to the search only), so a node's sum reads its predecessors' values only after a dispatch boundary; each phase needs about h + 1 of the maximumIterations rounds for a longest tight chain of h hops.
const centrality = new GPUNetworkCentrality({
  topology,
  reverseTopology,
  pivotNodes: pivots.importToGraph(graph),
  costLimit: radius.importToGraph(graph),
  betweennessScale: nodeCount / pivotCount,
  output: {
    betweenness: betweenness.importToGraph(graph),
    closeness: closeness.importToGraph(graph),
    status: {converged: converged.importToGraph(graph)}
  }
});
graph.add(centrality);

GPUNetworkCentralityScheduleStep

::lens{scenario=gpu-network.network-centrality-schedule-step rung=result caption="Compare eight sampled pivots in the first fixed-capacity schedule batch."}

planNetworkCentralitySchedule({pivotCount, laneCount}) lazily partitions pivot rows into fixed-lane submissions. Compile one step, upload each batch into its pivot buffer, pad the final batch with 0xffffffff, update the one-word reset view, and submit the same graph on the same queue. Set reset nonzero only on the first submission of a run. Node/edge betweenness and status accumulate on GPU; per-pivot outputs describe the current batch and must be copied or consumed before the next submission.

For sampled estimates keep betweennessScale = nodeCount / originalPivotCount across all steps. Each batch must still converge within maximumIterations. createNetworkCentralityContinuation provides host-controlled continuation for longer paths. Do not interleave runs sharing output buffers; inspect the final accumulated status before consuming the result.

Continuation accepts each planner descriptor directly: upload that step's pivots, then await runner.runBatch(step). The planner emits reset: 1 for the first batch and reset: 0 for later batches. The runner also accepts booleans: true/1 replaces totals and status (the default when reset is omitted); false/0 adds node/edge totals, takes the minimum converged, and retains earlier failure and approximation flags. Its per-pivot outputs still describe only the current batch.

GPUNetworkPathExtraction, GPUNetworkServiceAreas, GPUNetworkNeighborhood, and GPUNetworkAnalyticsColumns

Network analysis over the same directed CSR road network as GPUNetworkReachability.

  • GPUNetworkPathExtraction walks a reachability predecessor array from per-frame targets. It publishes ordered (source to target) node lists and resolved CSR edge lists as GPUCompactOutputs, together with per-target offsets, costs, and found flags. Each walk is bounded by a compile-time maximumPathLength, so bounded or cyclic walks terminate and set optional output.status.candidateOverflow on both node and edge ports. Final overflow reports only the respective output capacity. The CPU twin and operation forms use the same explicit budget and separate flags; the default budget is 1024. The per-target lineOffsets, pathCosts and pathFound are in output, and targetCount is a number or a one-row view. Pass the search's output.status.converged flag as predecessorsComplete: when it is 0 no target is reported found, because a chain may end at a node the truncated search never linked rather than at a source.

    Routing readouts must check search convergence and candidateOverflow before treating an empty path as unreachable. After a converged search, each target with pathFound=1 keeps its certified cost even if another target loses its walk. Candidate and final capacity flags describe the batch, so unfound targets are qualified as “incomplete batch” rather than assigned an individual failure. The explorer and showcase distinguish walk-budget loss (4096 nodes per explorer path, 2048 per showcase path) from final output capacity loss; geometry statistics require complete output. The showcase clears its turn-comparison chart whenever either route lacks a usable edge sequence. Only a completed search without batch loss reports “no route found” for pathFound=0. The path-extraction lens retains the candidate flag and refuses captures whose walk budget was exhausted.

  • GPUNetworkServiceAreas assigns every node to its nearest per-frame facility. Ties go to the smallest facility row; optional predecessors follow only tight edges between nodes of the same assignment, so a path always ends at the facility that assignments names, also on cost ties. It also reports per-facility node counts and the total cost each facility serves, all in output. It composes GPUNetworkReachability with a frontier-based min-label pass over the tight shortest-path edges. maximumLabelIterations bounds the label rounds (default min(maximumIterations, 32)) and localIterations sets the hops chained per round in both phases (default 16), so large-diameter grids converge at the defaults.

  • GPUNetworkNeighborhood publishes k-hop ego networks around per-frame startNodes (startCount a number or a view), with per-frame k up to a compile-time maximumHops. output holds hop distances, masks, and compact node and induced-edge IDs.

  • GPUNetworkAnalyticsColumns publishes node-aligned degree, inDegree and weak components columns directly on the caller's topology (and optional reverseTopology) with analysis-owned kernels, so a transient CSR built in the same graph by GPUCOOToCSR works as well as imported buffers. A degree counts the live slots of a row (a slot whose neighbor is >= nodeCount is not an edge) and a self-loop slot once, the rule of GPUGraphAlgorithmsDegree; GPUNetworkStatistics counts an undirected self-loop twice. Each column can be normalized to [0, 1] with a GPU extent. PageRank, core number and label propagation are luma.gl GPUGraphAlgorithms* operations that accept only physical topology; run them from @luma.gl/graph/gpu-graph-algorithms.

CPU network execution budgets

computeNetworkFlowOnCPU and CPUNetworkFlowOperation resolve solver and costed mode before selecting an explicit budget. Reference and costed successive-shortest-path use maximumAugmentations; uncosted parallel uses maximumRelabels; costed primal-dual uses maximumCostPhases. The latter two modes ignore maximumAugmentations, including zero. auto selects the same route as the contributor (including topology, mode and size triggers). After selection, reference mode refuses maximumRelaxationRounds, maximumRelabels, mode and maximumCostPhases in both backends. In particular, maximumRelabels alone does not opt auto into parallel mode; select solver: 'parallel' to supply that budget. Both operation forms reject incompatible reference settings at construction, before lowering or execution. CPU parallel phases serially exhaust shortest residual paths of equal cost and hop count; GPU phases use parallel preflow discharges, so allocation and progress can differ. An explicit maximumRelaxationRounds binds each synchronous CPU search, including its final unchanged sweep. A budget exit retains feasible flow, reports the remaining finite demand in unserved, clears summary complete and status converged, and sets iterationLimitReached. A finite request already served or an exhausted residual network is complete even at the budget boundary. Omitted CPU budgets run to completion.

GPUNetworkPathExtraction

Convert reachability predecessors and target intersections into ordered start-to-target node paths with offsets, costs and found flags.

For CPU reachability, explicit maximumIterations and per-frame activeIterations bind the search to at most localIterations hops per round (default 32); the active count is clamped to the compiled maximum (default 64). Explicit maximumTieIterations similarly bounds zero-cost predecessor tie levels. Budget exits retain current labels, clear converged, and set iterationLimitReached; path extraction suppresses paths when that certificate is clear. CPU frontier scheduling is synchronous and can advance further than GPU workgroups within a round. With no explicit CPU budgets, searches run to completion. Zero active rounds never certify a search, including an empty start set.

output.ids contains caller node identities (nodeIds[row], or the identity mapping when no map is supplied); optional output.nodeRows separately contains raw node rows for positional gathers. With edge extraction, edges.output.ids contains caller edge identities and optional edges.output.edgeRows contains CSR edge slots. Each row output must match its identity output's capacity and use a separate buffer. The CPU twin always returns nodeRows and, with edges, edges.edgeRows; graph operations declare those ports when requested. Use rows to gather positions or attributes, including when caller IDs happen to equal row indices. Operation props use NetworkPathExtractionNodeOperationOutput for the node bag and NetworkPathExtractionEdgeOperationOutput for the edge bag. Swapped row fields are rejected by TypeScript and at runtime before lowering. Both operation forms and the contributor capture their declared scalar fields, output/status maps and topology maps at construction; later caller mutation cannot change validated graph declarations. Input view contents remain per-frame.

GPUNetworkStatistics

Summarize road connectivity into component counts, degree histograms and maxima in one GPU-written table of words.

::lens{scenario=gpu-network.network-statistics rung=result caption="Read the GPU summary: 1,199 intersections, 2,810 directed edges, and one connected component."}

Statistics for a graph panel over the same CSR as GPUNetworkAnalyticsColumns, reduced on the GPU into one caller-owned uint32 summary. It reports live node, edge and slot counts, weak component count and largest component size, isolated nodes, maximum degrees, out-, in- and total-degree histograms ('linear' or 'log2' bins), and the modularity of a caller-supplied community labeling. Optional nodeMask and edgeMask restrict every statistic to live rows. Components run GPUGraphAlgorithmsConnectedComponents on a masked copy of the adjacency, so masking a bridge node splits its component. Modularity is accumulated with exact integer atomics and a fixed-order f32 finish, so it is deterministic. On undirected graphs a self-loop adds 2 to the degree, the histograms, the maxima and the modularity volumes, as in networkx and GPUGraphAlgorithmsModularity; slot and edge counts count the stored slot once. (The degree column of GPUNetworkAnalyticsColumns counts a self-loop slot once, as GPUGraphAlgorithmsDegree does, so the two differ on nodes with self-loops.) GPUNetworkSnapping, GPUNetworkCostMatrix, and GPUNetworkAccessibility

For GPUNetworkSnapping.maximumSnapDistance, no warning is possible because the distance is a GPU view; see Precision of longitude/latitude positions.

Accessibility over the same directed CSR road network as GPUNetworkReachability, in three steps.

  • GPUNetworkSnapping snaps planar points (origins, facilities, opportunities) to the nearest network edge of a topology with nodePositions (edge costs are topology.weights, or the edge length when the topology has no weights). For each point it outputs the edge row (ties go to the smallest row, so a point on a node takes the smallest incident edge), the fraction along the edge, the snap distance, the snapped position, and the two start costs: fraction * edgeCost to the edge source and (1 - fraction) * edgeCost to the target, all in output. output.startNodes / output.startCosts (two rows per point) feed a search directly. startDirection picks which endpoints count: 'both' for undirected networks, 'forward' for a point that leaves along a one-way edge, 'reverse' for a point that a one-way edge arrives at. Without candidateCapacity, every point scans every edge, which is exact. With it, candidates come from GPUNearestFeatureJoin over the edge segments within a per-frame maximumSnapDistance, and the required output.status.overflow reports when capacity runs out. With candidateCapacity the network has at most getGPUNetworkSnappingMaximumCandidateEdgeCount(device) (8388608 on a default device) edges. With spatialContext: {coordinateSpace: 'longitude-latitude', metric: 'great-circle'} points and nodes are degrees: the closest point of an edge is found in the point's local equirectangular frame (longitudes wrapped at +-180), and snap distances, maximumSnapDistance and default edge costs are in the context's length unit (meters or kilometers). Edges should be road-length. With candidateCapacity the context is passed to GPUNearestFeatureJoin, whose great-circle search ignores the capacity. Edge rows past offsets[nodeCount] (a CSR shorter than neighbors) are not part of the network: every edge-source row is cleared before the expansion, so no stale row becomes a phantom edge.
  • GPUNetworkCostMatrix computes a bounded many-to-all cost matrix: one shortest-path search per row, from that row's starts (startRows, or startsPerRow: 2 for snapped points) to every node. It batches laneCount rows (default recommendLaneCount(): about 1M expanded nodes per batch, at least 32 lanes, within 128 MB of scratch, at most rowCount, rounded down to make laneCount * nodeCount a multiple of 64 when there are several batches) into one GPUNetworkReachability over a lane-expanded copy of the CSR. Lane l, node u becomes node l * nodeCount + u, so the frontier rounds, hop chaining, per-frame costLimit, and convergence flag serve all lanes at once. The matrix is bit-identical for every laneCount. Every batch runs at the full lane count (a short last batch masks its lanes) on 64-element-aligned sub-views, so all batches share one set of pipelines. A batch whose block of costs is not 256-byte aligned searches into a scratch block and is copied. targetNodes (a compile-time length targetCount, per-frame node IDs) makes output.costs the compact [rowCount x targetCount] matrix: column t is the cost to targetNodes[t], +Infinity when unreached or out of range, bit-identical to that column of the dense matrix. Each batch searches into one laneCount * nodeCount scratch block and a gather kernel writes its rows, so memory is that block plus rowCount * targetCount instead of rowCount * nodeCount; lower laneCount to shrink the scratch block. columnCount reports the column count. Compile cost: every round of every batch is an unrolled command node. The exact count is the read-only property estimatedCommandNodeCount, and the constructor throws above 32,768 (for example 600 one-lane batches at the default 64 rounds); raise laneCount or lower maximumIterations. Rows set the number of searches, so put the smaller side on rows. To score every node, put opportunities or facilities on rows and search the reverse CSR (an undirected network can reuse its CSR).
  • GPUNetworkAccessibility scores a retained matrix with per-frame parameters (getGPUNetworkAccessibilityParameterValues: threshold, decay 'none' | 'exponential' | 'power', beta, minimum cost for power decay). It outputs cumulative opportunities within the threshold, gravity accessibility, and the two- or three-step floating catchment area (catchment: method '2sfca' (default) or '3sfca', supply on rows, demand per node, per-facility ratios, and per-node accessibility, with the decay applied inside each catchment). The catchment composes GPUNetworkCostWeights (the matrix as facility weights and their transpose, rowCount x nodeCount transient slots each) with GPUCatchmentAccessibility, the one floating catchment kernel; for a large matrix build sparser weights and run the two directly. orientation: 'origin-rows' scores a forward matrix whose rows are origins. Per-node sums gather rows in ascending order. Per-row sums use one workgroup and a fixed tree. Neither uses float atomics, so results are bitwise reproducible. Non-finite opportunity, supply or demand weights are missing values and are skipped; the encoder rejects a negative or non-finite beta and a minimumCost that is not positive and finite.

Encode the matrix graph when the network or the opportunity set changes. Encode the scoring graph every frame: threshold, decay, and beta changes never re-run a search. The threshold must not exceed the costLimit the matrix was built with.

GPUNetworkIsochrones

Turn road-network travel times into cost-band triangles or cell outlines around the reachable streets.

::lens{scenario=gpu-network.network-isochrones rung=result caption="Read the travel-time bands across 4,622 output triangles radiating from the start."}

Isochrone polygons from a network topology with nodePositions (pgRouting pgr_drivingDistance with a buffer, QGIS service area polygons). Costs come from the caller (costs, for example GPUNetworkServiceAreas output.costs) or from startNodes, which runs GPUNetworkReachability and writes costs; costs and assignments therefore stay top-level props, inputs or outputs depending on startNodes. With startNodes, output.status.converged (one row) reports whether that search reached a fixpoint within maximumIterations, and localIterations sets its hops per round. A 0 means the costs, and so every polygon, are truncated too small. As on GPUNetworkReachability and GPUNetworkServiceAreas the flag is optional, and omitting it accepts that truncation unchecked. The optional one-row uint32 output.status.iterationLimitReached is the complement of converged and can be requested alone. Both the plain reachability search and the facility-label search forward it; with assignments, label-round exhaustion also sets it. Both ports require startNodes and separate buffers from inputs, geometry outputs and each other. Budget exits still publish incumbent costs and geometry.

Every published output must occupy a distinct logical byte range, including costs and assignments when startNodes is supplied. Construction rejects aliases and names the two output ports. Outputs written in separate passes may use disjoint ranges of one allocation; bindings used together must also satisfy their alignment and read/write separation requirements. The contributor snapshots declared option and port fields at construction, including inherited and non-enumerable getters on class-backed output maps; later caller mutations do not change validated bindings. GPU view identities are retained, so their contents remain per-frame inputs. The labelled decode, triangle-label and cell-label passes validate their co-bound ports at construction as well.

  • Raster path. Every edge is sampled at up to raster.maximumSamplesPerEdge points. The cost is interpolated linearly from the source node along the edge weight, and the minimum (default) or maximum cost is written to the pixels within the walking buffer (bufferRadius, with cost cost + walkCostPerUnit * distance) using integer atomics on order-preserving float bits, so the result is independent of thread order. In 'max' mode the cost of a sample is first reduced to the cheaper of the two directions of its road (min(cost[u] + t w, cost[v] + (1 - t) wReverse) when a slot v -> u exists), so the maximum runs over the samples and roads within the buffer of a pixel and never over a road and its own reverse direction. The raster feeds GPUIsobands: band k is cost in (costBreaks[k - 1], costBreaks[k]] (a cost exactly on a break is within it, as in GPUNetworkReachability bands), and the last band is beyond the last break, which includes unreached space. The default lastBand is breakCount - 1, so unreached space gets no triangles.
  • Cell path. Nodes with cost at most cellCostLimit are keyed to H3 or Quadbin cells (GPUCellAggregation, or GPUPointToCell then GPUCellAggregation) and outlined with GPUCellSetOutline. Positions must be longitude and latitude. cellOutline.rings (same options as GPUCellSetOutline rings: vertexTolerance, normalizeWinding, output) chains the outline into closed isochrone rings with shells, holes, shell assignment and an optional polygon layout (GPUSegmentRingAssembly). One run is one cost limit, so bands need one run each. The polygons output plugs into GPUPointInPolygonJoin for "is this demand point inside the isochrone", which addDriveTimeCatchmentRecipe wires as isochrones.joinDemand. The recipe is exported from this entry (@luma-contributors/analysis/gpu-network) and documented with the other recipes in spatial analysis. For the recipe's maximumSnapDistance, no warning is possible because the distance is a GPU view; see Precision of longitude/latitude positions.
  • Parameters. Per-frame values are packed with getGPUNetworkIsochronesParameterValues({breakCount, extent, bufferRadius, walkCostPerUnit, firstBand, lastBand, cellCostLimit}) into a 12-element float32 view. costBreaks is a float32 view whose length is the maximum break count. The raster size, maximumBufferPixels (default 6, at most 16), maximumSamplesPerEdge (default 64, at most 1024), unreachedCost (default 1e30) and the mode are compile-time.
  • Accuracy. Pixel accurate. Edges are straight node-to-node segments, the outer contour is inset by up to one pixel (interpolation toward unreachedCost), and the effective buffer is at least half a pixel diagonal, truncated at maximumBufferPixels. The raster is planar in the units of topology.nodePositions, so use projected meters for an isotropic buffer. An edge longer than maximumSamplesPerEdge * bufferRadius / 2 leaves gaps.
  • Facilities. assignments (a uint32 view of the facility per node) is an input, or, when startNodes is given, an output: the nearest-facility allocation of GPUNetworkServiceAreas (ties to the lowest row; maximumLabelIterations bounds its rounds). Raster and outline capacity status is in raster.output.status and cellOutline.output.status. raster.output.pixelFacilities (minimum mode, at most 255 sources; the pixel word keeps the top 24 cost bits, relative precision 2^-15) and raster.output.triangleFacilities label the raster path, and raster.rings writes band rings (GPUIsobandRings). On the cell path cellOutline.byFacility with cellFacilities gives each cell the facility of its cheapest node and outlines with groups, so rings never mix facilities (Quadbin is keyed through GPUPointToCell). A supplied cellOutline.table determines the row capacity from table.cells.length; tableCapacity applies only when the table is omitted (default: node count). Caller-owned cellFacilities must have exactly that many rows; omitted facility and minimum-cost buffers use the same capacity. With a supplied table, tableCapacity is ignored, including zero. Without a supplied table, tableCapacity must be at least the node count: the internal cell-loss flag is not published, so potentially lossy transient tables are refused. With a smaller caller-owned table, check table.status.overflow before treating any derived outline or rings as complete; cellOutline.output.status.overflow reports segment-capacity loss only. The drive-time catchment recipe exposes the supplied table's status as the isochrone-cells stage and enforces the same transient-capacity rule through this contributor.
  • Coordinates. The public spatialContext always holds a resolved context. Omitted means native planar for raster, or {coordinateSpace: 'longitude-latitude', metric: 'none'} for cellOutline alone. With both outputs and no context, the raster's planar default applies and cell-outline positions remain unchecked for compatibility. An explicit context checks both paths: longitude/latitude with raster throws (project into an AEQD frame first), and planar with cellOutline throws. Lambert equal-area frames are rejected because buffers measure distance.
  • Limits. The cell path samples reached nodes only, so long edges on sparse networks drop cells. The rings follow the cell outline, so they have cell resolution. Three mid-latitude H3 pentagons (resolutions 2, 3 and 5; alone, in disks, as holes and open rings) match h3-js cellsToMultiPolygon; the two polar pentagons enclose a pole and have no planar lng/lat orientation. Before declaring search nodes or allocating scratch, the contributor checks caller STORAGE bindings, its direct raster/cell scratch bindings, and raster-ring edge/ring capacity limits. Child contributors also validate their own intermediate allocations. In particular, a raster needs 4 * width * height bytes for its encoded pixels, and the same amount for values when no values output is supplied. An 8,192 by 8,192 raster needs 256 MiB per such binding and is rejected on a device with a 128 MiB storage binding limit. A transient cell table needs 8 * tableCapacity bytes for its cell keys; facility scratch uses four bytes per table row. Raster rings use getGPUIsobandRingsMaximumEdgeCapacity and getGPUIsobandRingsMaximumRingCapacity for the outer preflight, so on a 128 MiB binding device raster.rings.edgeCapacity is at most 8,388,608.

addDriveTimeCatchmentRecipe

Snap facilities and demand points to roads, assign drive-time catchments and count demand per cost band.

Coincident facility and demand endpoints remain accessible at zero cost even when a road is one-way. Interior movement still obeys its permitted directions. The recipe's min-mode raster includes the direct paths from each snapped facility to its road endpoints, so early bands can appear around facilities inside streets even when neither endpoint lies in that band. The recipe requires min raster mode; the standalone isochrone contributor still supports max mode. GPUNetworkIsochronesRaster.sourcePaths supplies these additional directed paths through the same splatter, with optional assignments in the main network's start-row identity space.

::lens{scenario=gpu-network.drive-time-catchment-recipe rung=result caption="Compare drive times from 100 demand points to their nearest of 4 facilities."}

A snapped point lies at fraction f of the straight road between the two end nodes of its edge. The road is driven in a direction only when the topology has a passable edge that way, at the weight of the cheapest one, so a one-way edge is driven one way. An interior facility gets one start row (the other row of startNodes is 0xffffffff); a facility coincident with an endpoint also seeds that node at zero cost. The demand time is the smallest of cost[source] + f * w(source -> target), cost[target] + (1 - f) * w(target -> source) and, for each facility snapped to the same road, the way straight along it (abs(f - f_facility) * w on a two-way road of one cost). Demand beside its facility therefore gets the short way along the road, not the way out to an end node and back. The facilities are sorted by road and each demand point binary-searches its own, so it is compared only with the facilities snapped to that road. Band k holds the times in (costBreaks[k - 1], costBreaks[k]]: a time exactly on a break is within it, as in the bands of GPUNetworkReachability and GPUNetworkIsochrones. An unsnapped or unreached demand point has the time +Infinity and no band.

GPUNetworkNoding

Split raw centrelines at their intersections, merge end points within a tolerance, and return nodes, edge pieces and a network.

::lens{scenario=gpu-network.network-noding rung=result caption="Compare 16 raw centrelines with 134 noded pieces and 87 nodes; bridges are not distinguished."}

Maximum: intersectionCapacity is at most getGPUNetworkNodingMaximumIntersectionCapacity(device) (1048576 on a default device), a quarter of getGPULineSplitMaximumPieceBound(device).

Builds a routable network from raw linestrings. GPULineSplit pieces (see GPU Spatial Analysis) are the edges. Their end points are snapped by a per-frame tolerance (a one-row float32 view; integer grid cells floor((x - origin) / tolerance) counted from the minimum corner of the live end points, so UTM northings keep exact cells; 0 means exact), deduplicated by a stable two-pass GPUSort, and the node ID is the group rank. Cells are exact up to 2^24 per axis; a wider extent sets output.status.overflow. Props: lines, intersectionCapacity, tolerance, and output with pieces, nodes (positions and status.count, optional status.requiredCount), edges (fromNodes, toNodes, lengths) and topology (offsets, neighbors, weights, optional edgeIds), with optional output.status.overflow and output.status.uncertainCount. The topology is undirected and feeds GPUNetworkReachability, GPUNetworkServiceAreas and the other contributors directly. Every edge has two entries, one in the row of each end node; a loop (a closed ring, or a piece whose two ends merge within the tolerance) has one entry in the row of its node, the rule of GPUNetworkCoarsening, GPUNetworkSubgraphFilter, GPUNetworkStatistics and luma.gl's GPUGraphAlgorithmsTopology.

Turn-restricted routing as a line graph in CSR form: one node per directed edge of the road network and one arc per allowed turn. GPUNetworkCostTable

Search every node within a cost limit and store each reachable target and its cost in one sparse CSR table.

::lens{scenario=gpu-network.network-cost-table rung=result caption="Follow the start intersection's row of the 30-second table, which stores 23,449 entries network-wide."}

Precomputes a bounded all-pairs cost table of a static directed network, in the spirit of the UBODT of fast map matching (Yang and Gidofalvi 2018). Row u lists every node v whose shortest-path cost from u is finite and at most costLimit, u itself included at cost 0, as a CSR (offsets, targets, costs) with ascending targets, so a consumer finds a cost by binary search of the row. When status.complete is nonzero, the table is exact up to its limit: a target missing from a row is farther than costLimit or unreachable. GPUMapMatching.routeTable is the first consumer.

The contributor and both operation forms capture named budgets and port fields at construction. Later changes to the caller's props do not change the validated command graph; buffer contents remain per-frame inputs. Status words must occupy distinct storage even on class-instance bags.

  • Props: topology (with weights as the travel cost), costLimit (one row, per frame), laneCount, maximumIterations, localIterations (default 16) and output: offsets (nodeCount + 1 rows), targets (its length is the entry capacity), costs (same length) and optional status.overflow, status.requiredCount, status.converged and status.complete. The one-word status.complete is 1 only when every batch converged without capacity overflow; it can be requested alone and is the word to forward to map matching. Optional status.iterationLimitReached is 1 - converged and can be requested alone. It reports round-budget exhaustion independently of capacity overflow. On a budget exit, retained CSR rows remain consistent, and requiredCount counts entries found so far; it is not a certificate of the full table size. The CPU twin searches to completion when maximumIterations is omitted; an explicit round budget binds the CPU search too. Local hops default to 16. On a budget exit it publishes its incumbents and sets iterationLimitReached when its frontier remains nonempty. CPU scheduling is deterministic per source; GPU lane packing and scheduling can change partial incumbents near the budget boundary. Both forms report convergence independently of capacity. Completeness also requires no capacity overflow: on the nine-node unit chain, capacity 3 after convergence gives converged=1, overflow=1, complete=0, while capacity 81 gives converged=1, overflow=0, complete=1. All scalar ports reset on each encoding and need separate physical buffers from inputs and other outputs.

  • Method: source nodes are searched laneCount at a time with one lane-expanded GPUNetworkReachability per batch into one scratch block, then a per-lane count, a single-workgroup scan of the batch's lane counts on top of a GPU running entry cursor (which writes the batch's offsets rows), and a per-lane ordered fill. The batch index never reaches the shader, so every batch shares pipelines. Converged costs are the f32 fixpoint of reachability and are identical for every laneCount. Partial incumbents can vary before convergence. The CPU table rounds every path addition to float32 before the inclusive cutoff test, preserving membership when a CPU table feeds GPU matching; for example, float32 0.1 + 0.4 is admitted at cutoff 0.5.

  • Capacity: entries past output.targets.length are dropped and offsets are clamped, so a reader always sees a consistent, possibly truncated CSR. status.overflow is 1 and status.requiredCount is the exact entry count (saturating at 0xffffffff) for the grow loop. Do not use a table that overflowed or did not converge. Forward status.complete as routeTable.status.complete: GPUMapMatching falls back to A* whenever this word is zero or omitted. It does not turn missing entries from unfinished rows into track breaks; the fallback reports its own route-budget limits.

  • Scaling: each batch sweeps its laneCount x nodeCount scratch block, so work and memory traffic are O(laneCount * nodeCount) words per batch and O(ceil(nodeCount / laneCount) * laneCount * nodeCount) words per build including padding, plus the searches (quadratic overall because laneCount <= nodeCount). Build once and reuse while weights are static; the table holds only entries within costLimit. The largest scratch binding is the two frontier queues: 8 * laneCount * nodeCount bytes. Every topology and output view must also fit its storage binding.

  • Compile cost: every round of every batch is an unrolled command node, 2 + batchCount * (6 + maximumIterations) nodes, plus one per batch when status.converged, status.iterationLimitReached or status.complete is requested. The exact count is the read-only property estimatedCommandNodeCount; construction rejects more than 32,768 commands. For example, 50,000 nodes with 128 lanes and 64 rounds use 27,763 commands with completeness tracking and 51,200,000 frontier bytes, below a 128 MiB binding. Lane count must be supplied explicitly for this example. At 100,000 nodes and 64 rounds, no lane count fits both limits: at most 167 lanes fit the frontier, but at least 217 are needed for commands with completeness tracking. Lowering the rounds may produce an incomplete table; check status.complete.

// Build once for a static network. The weights must equal the edge lengths GPUMapMatching measures
// from the node positions (here 100 m blocks, so a 700 m limit covers 7 blocks).
const table = new GPUNetworkCostTable({
  id: 'street-table',
  topology: {offsets, neighbors, weights: edgeLengths},
  costLimit: tableLimit,
  output: {
    offsets: tableOffsets, targets: tableTargets, costs: tableCosts,
    status: {complete: tableComplete, overflow: tableOverflow, requiredCount: tableRequired, converged: tableConverged}
  }
});
graph.add(table);
graph.add(new GPUMapMatching({
  positions, trackOffsets, topology: {offsets, neighbors, nodePositions}, parameters,
  cellSize: 60, bounds, output: {matchedEdges},
  routeTable: {
    offsets: tableOffsets, targets: tableTargets, costs: tableCosts,
    costLimit: tableLimit, status: {complete: tableComplete}
  }
}));

GPUMapMatching

Rows are bounded by min(floor(bindingBytes / 12), 16,777,215). Optional output.status.candidateOverflow mirrors intermediate-table overflow; routeOverflow counts dropped route nodes. Fixed matched-row output overflow is always zero. Check intermediate loss before treating a route as complete.

Match noisy GPS tracks to directed road edges with candidate edges, bounded route searches and a Viterbi decode.

In a great-circle context, both CPU and GPU matching project onto the same wrapped start-to-end longitude arc and compare the projected candidate with both endpoints. A rounded distance tie preserves an interior projection; ties between endpoint candidates select the start. The selected fraction and snap distance therefore describe the same point, including for remote antimeridian queries. Long edges still use the documented local projection approximation.

::lens{scenario=gpu-network.map-matching rung=result caption="Compare 3 simulated GPS tracks with their road-snapped runs; 137 of 139 fixes matched."}

Pass optional spatialContext in the settings of getGPUMapMatchingParameterValues to warn when finite positive sigma or searchRadius is below 10·Q (16.97 m with the default sphere); see Precision of longitude/latitude positions.

Maximums: topology has at most getGPUMapMatchingMaximumEdgeCount(device) (11184810 on a default device) edges and entryCapacity is at most getGPUMapMatchingMaximumEntryCapacity(device) (33554432); the default entryCapacity is capped there and status.candidateOverflow reports lost entries. The per-point scratch (candidates 12 bytes per candidate, the route table candidateCount * (candidateCount + 1) * 4 bytes) must fit one storage binding: positions has at most getGPUMapMatchingMaximumPointCount(device, candidateCount, hasTraversedEdges) rows (466033 at 8 candidates on a default device, with output.traversedEdges the 20-byte hop table per point binds only at one candidate), and getCommandNodes throws a positions rows must be at most ... error past it. Lower candidateCount or split the tracks into several GPUMapMatching instances.

Hidden Markov model map matching of GPS tracks to a directed network (Newson and Krumm 2009). Per point, up to candidateCount (at most 8, default 8: a directed edge row is one candidate, so the default keeps the 4 nearest two-way roads) distinct directed edges within searchRadius come from an edge grid rebuilt every encoding (cellSize and bounds are compile-time). The emission is Gaussian on the perpendicular distance (sigma) and the transition exponential on |straight - route| (beta). The route is the rest of the current edge, a bounded A* search (it stops at routeFactor * straight + routeSlack, exits early once every target is settled, and uses a routeNodeBudget node table) and the start of the next edge; a route longer than routeFactor * straight + routeSlack, partial end edges included, is infeasible. Viterbi runs one thread per track.

  • Props: positions, trackOffsets, the network topology (offsets, neighbors, nodePositions; weights unused), parameters (getGPUMapMatchingParameterValues: sigma, beta, searchRadius, routeFactor, routeSlack, per frame), candidateCount, cellSize, bounds, entryCapacity, routeNodeBudget, minimumFixSpacingSigmas, traversedEdgeCapacity and spatialContext. The contributor, both operation forms and the track-quality recipe capture named model fields, bounds and port/status maps once, including inherited getters. Later props mutation does not alter compiled budgets; input buffer contents remain per-frame values.
  • Local geographic snaps retain an interior projection when its haversine term ties the endpoint terms in float32. Local candidates are compared before converting those terms to distances, so inverse trigonometric rounding does not move a midpoint snap onto an endpoint. Distant queries retain central-angle comparisons to preserve resolution near antipodes.
  • Fix spacing (minimumFixSpacingSigmas, compile-time, off by default): Newson and Krumm drop a fix within 2 sigma of the previous retained fix, so stationary or backward jitter does not look like a move. Pass 2 to do the same, measured with the frame's sigma and the context's distance. Without it a fix that jitters backward along a one-way edge has no feasible transition (the route would have to leave the edge and return within routeFactor * straight + routeSlack) and breaks the track. The first fix of a track is always kept and each later fix is measured from the last retained one. A dropped fix is never a candidate source or target and is unmatched in every output (matchedEdges is GPU_MAP_MATCHING_NONE, breaks is 0, it is not in matchedCount). Dropped fixes are not matched to the edge of their neighbors, so resample or interpolate them yourself if you need a value per fix.
  • Score renormalization: the forward pass subtracts the best score of each step from every score of that step. This moves all candidates of a step equally, so the chosen path is unchanged, and it keeps the float32 scores small over a track of any length (unnormalized, a 100000-fix track reaches 1e5 to 1e6, where one float32 step is 0.008 to 0.06 and close candidates tie). trackLogLikelihoods adds the subtracted amounts back, as a whole part and a fraction, so it stays accurate to one float32 rounding of its own magnitude; there is no option to set.
  • Geodesic: with spatialContext: {coordinateSpace: 'longitude-latitude', metric: 'great-circle'} positions and nodes are degrees and every distance (emission, straight line, edge and route lengths, and the distance parameters) is in the context's length unit (meters or kilometers); the A* heuristic stays consistent. cellSize and bounds stay in degrees, the candidate window widens in longitude by 1 / cos of its highest latitude, and longitudes are unwrapped around the grid center, so give bounds across the antimeridian (for example 179.9 to 180.1) for a network that crosses it.
  • Outputs (output): matchedEdges (a CSR row per point; GPU_MAP_MATCHING_NONE when unmatched), matchedFractions, matchedOffsets, snapDistances, snappedPositions, breaks, trackLogLikelihoods, matchedCount, breakCount, traversedEdges, status.candidateOverflow, status.overflow and status.routeOverflow. A break restarts the model where no transition is feasible or a point has no candidate (breaks value 1). A break where a route search into the point dropped nodes is a budget break (value 2): the route may exist but did not fit the table. status.candidateOverflow is 1 when the edge grid, route search or traversal recovery lost candidates; fixed matched rows fit, so status.overflow is zero, and status.routeOverflow counts the dropped route nodes (saturating at 0xffffffff).
  • Traversed route (output.traversedEdges, needs traversedEdgeCapacity): matchedEdges is the edge each fix snaps to; the route is the edges passed between fixes, including edges that no fix lands on. The caller owns {edges, counts, status?: {overflow?, candidateOverflow?}}: edges has trackCount * traversedEdgeCapacity rows and track t writes its list, in travel order, from row t * traversedEdgeCapacity; counts[t] is the number of entries the track needs, so a value above traversedEdgeCapacity tells how much capacity to allocate and rows past the capacity are not stored; traversal status.overflow is 1 only when a track's list exceeds capacity. Traversal status.candidateOverflow inherits grid/scoring loss and is also 1 when recovery drops nodes or cannot reconstruct a hop; an unrecovered hop writes a GPU_MAP_MATCHING_NONE separator before its end edge. The list holds the first matched edge, then for each recovered hop the shortest-route edges followed by the next fix's edge, and nothing for a fix that stays on its edge ahead of the previous fix. One GPU_MAP_MATCHING_NONE entry separates sub-tracks after a break or an unmatched fix, so counting traversals skips it and invents no adjacency across the break. Each hop repeats the bounded search of the route kernel for the chosen candidates only, one thread per track in sequence, so it costs about one more route pass over the matched hops; it needs 20 bytes per point of scratch. GPUMapMatchedEdgeVolumes counts edge volumes over these lists. Forward both traversal status words; its required output.status.candidateOverflow marks retained volumes/movements as incomplete, and a requested nested transition candidate flag includes that loss. Missing matching completeness is refused; only fixed external sequences may assert completeness: 'known-complete'. With grid/scoring loss the counts are conditional on the retained match, not lower bounds on an exact match's per-edge counts. Without traversedEdges nothing changes.
  • routeTable (optional): a GPUNetworkCostTable of the same network, built with weights equal to the edge lengths this contributor measures from the node positions (in the context's length unit), passed as {offsets, targets, costs, costLimit, status?: {complete}}. A route search whose allowance (routeFactor * straight + routeSlack minus the tail of the source edge) is within the table's costLimit reads its network costs by binary search of the source node's row, with no search and no node budget, so it is exact and never counted in status.routeOverflow. Searches above the limit, or all of them while the table's complete flag is zero or omitted, run the bounded A* search as before, so there is no cliff and no extra flag. Matched edges equal the A*-only results where A* is exact; route lengths differ only by f32 rounding of the summed costs (about 2^-24 relative per hop). The table is built once and reused, which pays off for large track batches. Without routeTable nothing changes.
  • Route budget: a full node table keeps the open nodes with the best A* keys and drops the rest. A search needs about as many nodes as the street blocks between two samples. On a 100 m street grid the default 64 covers samples up to about 800 m apart and 128 up to about 1.1 km. At 1 km and 64 it still misses routes (80 of 227 in a mimic, 171 under the old drop-in-discovery-order policy, which reported nothing). Each miss is reported, so sample more densely or raise routeNodeBudget when status.candidateOverflow is set. CSR rows past offsets[nodeCount] are not part of the network.
  • CPU twin: an explicitly supplied routeNodeBudget binds fallback and traversal-recovery searches, including dropped-node counts, budget breaks and traversal separators. Certified-table lookups binary-search only the source CSR row, independent of spare capacity. Without a budget CPU searches remain uncapped. A complete cost table within the hop allowance bypasses fallback search in both backends; traversal reconstruction still needs its own bounded search. CPU arithmetic is float64 outside the precomputed table, so boundary and tie differences remain documented.
  • The route passes run per (point, previous candidate) work item, so Viterbi is a cheap recursion: on a New York scene the matching graph went from 923 to 30 ms at a budget of 64 (20 ms at 40), with identical results.
  • Limits: distances are planar unless a great-circle spatialContext is given, and edges are straight segments in the coordinates, so on longitude/latitude they should be road-length. The bounded search is an approximation that can overestimate or miss routes when samples are far apart for the budget (always reported, see above), and the route table is pointCount * k * (k + 1) floats (checked against the storage binding limit, see Maximums). A two-way road needs both directions, and each takes a candidate slot. Exact routes and time-aware transitions are not provided.

GPUNetworkKFunction

Optional output.status.converged is one only when every shortest-path batch reaches a fixpoint; iterationLimitReached is one if any batch exhausts its round budget. Snapping overflow remains a separate status.

Count crash pairs by network distance band and return the network K value at each distance threshold.

::lens{scenario=gpu-network.network-k-function rung=result caption="Compare K for 58 snapped crashes against the seeded simulation minimum, mean and maximum."}

For maximumSnapDistance and maximumDistance, no warning is possible because the distance is a GPU view; see Precision of longitude/latitude positions.

Maximum: rowsPerBlock * events is at most 4294967295 (one 1-D dispatch), checked under the contributor's own ID. Each row block unrolls maximumIterations + 6 command nodes; the read-only estimatedCommandNodeCount (an upper bound within 192 of the true count, which covers the snapping, reduction and scan primitives) must be at most 32,768, so raise rowsPerBlock or lower simulationCount or maximumIterations for large pattern counts.

Network-constrained Ripley K function (Okabe and Yamada; spaghetti GlobalAutoK). Events are snapped with GPUNetworkSnapping, then multi-source reachability searches limited to maximumDistance run in blocks of rowsPerBlock rows (which bounds scratch memory). The lane-expanded CSR is built once for all rows and shared by every block, so rowsPerBlock trades only the node count of the relax and initialize passes against scratch memory. Unordered pairs below each of bandCount thresholds are counted with integer atomics and K = 2 * pairs * L / n^2 (spaghetti's normalization; multiply by n / (n - 1) for the Okabe-Yamada ratio form), with L the per-frame networkLength. Optional envelope: simulationCount random patterns (Philox, an edge drawn proportional to its length in two integer levels: edge lengths are quantized to 2^24 units of the longest live edge, a GPU maximum, and summed inside chunks of 128 slots; the chunk totals, scaled against the largest chunk total, get a second prefix sum; a draw picks a chunk and then an edge of it. Short edges keep their share on large networks, and a wrong networkLength changes K but never the draw). Only the live CSR rows 0..offsets[nodeCount] are snapped to or drawn; networkLength is half the sum of their weights. Blocks and batches run at a fixed shape on 64-element-aligned sub-views and read their first row from a per-block info word, so every block shares one set of pipelines.

  • Props: positions, the network topology (with nodePositions), maximumDistance, networkLength, maximumSnapDistance, parameters (getGPUNetworkKFunctionParameterValues: seed and active simulations), bandCount (at most GPU_NETWORK_K_FUNCTION_MAXIMUM_BAND_COUNT), simulationCount, rowsPerBlock, candidateCapacity. For many events pass candidateCapacity (with maximumSnapDistance) so snapping uses the BVH join instead of scanning every edge per event; output.status.overflow is then required and is set when the snap candidates overflow (K is then inexact). spatialContext is passed to GPUNetworkSnapping: a great-circle context snaps longitude/latitude events in the context's length unit (give weights, maximumDistance, maximumSnapDistance and networkLength in that unit too). kValues and envelope are also in the context's length unit.
  • Outputs (output): kValues, optional pairCounts, envelope (min, mean and max per band), snappedEventCount, status.overflow and status.converged.
  • Counts and K are pinned to spaghetti 1.7.6. Parallel edges between the same two nodes count as one road, and the envelope is the plain min, mean and max (spaghetti scales the extremes by the threshold). 192 events with 20 patterns on 97,000 edges took about 61 ms (181 ms before the shared CSR expansion and BVH snapping), of which about 41 ms is relaxation. Cross-K between two patterns is not provided. Open: a block of 192 rows produced no result in one explorer capture (not investigated, so keep rowsPerBlock near the 128 MB lane budget of recommendLaneCount), and snap-candidate overflow is reported only through status.overflow.

GPUEdgeBundling

Bend origin-destination lines toward shared corridors by iterating a density field, keeping both endpoints fixed.

::lens{scenario=gpu-network.edge-bundling rung=result caption="Compare 150 straight taxi flows with their bundled paths after 8 density iterations; endpoints stay fixed."}

Kernel-density edge bundling (KDEEB) as WebGPU compute, producing renderable polylines. Each edge starts as a straight subdivision. Every iteration does four things:

  1. Splats Epanechnikov weights of all control points into a fixed-point atomic<u32> density buffer.
  2. Advects interior points one kernel radius along the bilinearly sampled normalized gradient.
  3. Resamples each edge to uniform arc length and applies one Laplacian smoothing pass.
  4. Anneals the radius by lambda.

Endpoints are pinned. Density is a storage buffer, so there is no float-renderable texture requirement and no texture size cap.

Lengths are relative to a square work box computed on the GPU every encoding from live-edge endpoints, so results are scale invariant. Dead edges (masked, out-of-range or non-finite) do not bundle, and their path collapses onto the source position. Outputs (output):

  • paths: edgeCount * pointsPerEdge float32x2 rows, edge-major, in caller coordinates.
  • lineOffsets (optional): for PathLayer binary attributes.
  • drawRecord (optional): a four-word drawIndirect record [pointsPerEdge, edgeCount, 0, 0] for instanced line strips.

pointsPerEdge (2 to 64), maximumIterations (1 to 64) and densityResolution are compile-time. When parameters is given, one gate node writes the indirect dispatches of every iteration, so iterations beyond activeIterations dispatch nothing (the graph has 5 + 3 * maximumIterations nodes, plus one gate with parameters and one for indices). Each iteration reads its index from a 256-byte aligned iteration-info slot, so all iterations share one splat and one update pipeline. With a longitude/latitude spatialContext nodePositions are longitude and latitude in degrees and longitude is scaled by the cosine of the mid-latitude of the live endpoints (computed on the GPU, clamped at 0.01); the output stays in degrees and endpoints are exact. Bundling measures nothing in physical units, so the context's metric is not used, and data spanning the antimeridian is not supported. The per-frame parameters view holds [activeIterations, kernelRadius, lambda, smoothing, stepScale]; pack it with getGPUEdgeBundlingParameterValues. The edge list is sourceNodes and targetNodes into nodePositions.

const parameters = new GPUParameterBuffer(device, {id: 'bundling', format: 'uint32', length: 5,
  values: getGPUEdgeBundlingParameterValues({kernelRadius: 0.03}, 'uint32')});
graph.add(new GPUEdgeBundling({nodePositions, sourceNodes, targetNodes, edgeMask,
  output: {paths, lineOffsets, drawRecord}, pointsPerEdge: 16, maximumIterations: 15,
  densityResolution: 256, parameters: parameters.importToGraph(graph)}));
parameters.write(getGPUEdgeBundlingParameterValues({activeIterations: 6, kernelRadius: 0.05}, 'uint32'));

The normalized-gradient schedule is chaotic in f32. The f32 CPU oracle matches below 1e-5 of the box after one iteration, and only statistically after that. Gradients below four fixed-point quanta are treated as zero so a lone edge does not drift.

GPUFlowAggregation

Group origin-destination records by zone pair and rank the pairs by summed trips, with record counts per pair.

Use getCommandNodes(graph) to build the contributor. Binding and scratch preflight runs before it declares resources. The former internal validateBindings class method is no longer exposed; map-matched transition composition uses a private module helper with the same allocation-free checks. Output layouts and command nodes are unchanged.

::lens{scenario=gpu-network.flow-aggregation rung=result caption="Compare 450 taxi records with the top 32 of 150 zone pairs; the highlight is the busiest pair."}

Maximum: rows * maximumProbeCount is at most 4294967295, so inputs above 2^24 rows need a maximumProbeCount below the default.

Origin–destination aggregation for flow maps. Each row's origin and destination are assigned to square-grid cells, hexagons, or caller zone IDs. Rows are then grouped by zone pair through a compile-time-capacity GPUHashIndex, counted and weighted with GPUGroupAggregation, and ranked by two stable GPUSort passes. The result is a deterministic top-K list (weight descending, ties by origin then destination zone) with zone columns, counts, and weights for an ArcLayer, plus per-zone outgoing and incoming totals. An optional caller mask and per-frame time window (getGPUTimeWindowFilterParameterValues) gate rows without recompiling. All results are in output (a GPUCompactOutput plus the flow and zone columns). output.status.pairOverflow reports a full pair table, also published as optional status.candidateOverflow. status.overflow reports only top-K truncation (requiredCount > ids.length). requiredCount counts pairs retained in the table, so it is a lower bound on the full requirement after pair-table loss.

Filter source rows with mask; a zero weight still contributes an accepted row and can create a zero-weight pair. The commute-flow website applies its minimum-workers threshold through this mask. Its hover count describes retained pairs as “displayed flows” when the 160-pair display capacity truncates the top list; the outgoing jobs total still covers all accepted rows. Pair-table loss is reported separately as incomplete aggregation, and no rejected input creates a displayed arrow. The hover shows “pending aggregation” until its count, both loss flags and displayed columns have arrived; an unread status is never interpreted as loss or a zero flow count.

For grid and hexagon zones, zones.activeGridSize is a per-frame packed uint32 [columns, rows] clamped to 1..gridSize, so gridSize becomes the compile-time capacity: zone IDs are row-major in the active size, zone outputs keep capacity length with zeros past columns * rows, and pair keys use the capacity zone count (GPUFlowAggregationActiveGridSize). Pair it with the per-frame hexagon radius. zoneOutCountExtent and zoneInCountExtent (two float32 rows [min, max]) hold the extent of the nonzero per-zone counts (both 0 when none), usable directly as a layer extent buffer.

The time gate accepts the same three timestamp forms as GPUTimeWindowFilter, including exact Int64 words with a uint32 word window. sumOrder defaults to 'sorted': rows are sorted by pair and by zone and each group is summed in a fixed tree, so output.flowWeights, output.zoneOutWeights and output.zoneInWeights are bitwise reproducible, at the cost of three sorts and scans per encoding (38 instead of 22 nodes). 'atomic' uses float compare-exchange addition and serializes when rows share a pair (1M rows on one pair: 12-17 s against 22 ms sorted); it is faster only when nearly every row has its own pair. The sorted pair sum runs one 256-lane workgroup per stored pair, dispatched indirectly from the stored-pair count, so with weights and 'sorted' pairCapacity is at most 2^23.

graph.add(new GPUFlowAggregation({
  zones: {kind: 'hexagon', bounds: viewport.importToGraph(graph), gridSize: [64, 48], radius: 250},
  origins, destinations, weights: tripCounts,
  timeWindow: {timestamps: departures, window: window.importToGraph(graph)},
  pairCapacity: 8192, excludeSelfFlows: true,
  output: {
    ids: flowKeys, status: {count, overflow, requiredCount},
    flowOriginZoneIds, flowDestinationZoneIds, flowWeights, zoneOutCounts, zoneInCounts,
    drawInstanceCount: graph.importGPUData('arcs', arcDraws.getInstanceCountData(0))
  }
}));
