GPURaster analysis contributors

Overview

The @luma-contributors/analysis/raster-analysis entry point exports analysis contributors that build on the operations in the other families: zonal statistics, contrast stretch, isolines and isobands, Euclidean distance fields, cost distance, polygon rasterization, raster joins, reclassification, sampling and profiles, change detection, particle advection, streamlines, and line integral convolution, and exact min/max pyramids. Each is an algorithm or workflow that declares resources and command nodes into a caller-owned GPUCommandGraph through getCommandNodes(graph) (GPUCommandNodeProducer). It never compiles, submits, encodes, or reads back.

When to use it

Use these contributors when a map analysis needs a finished, bounded result rather than a building block, and when its per-frame inputs (levels, seeds, windows, thresholds) change without recompiling.

  • GPUIsolines and GPUIsobands extract several levels at once, order segments deterministically, and can stitch polylines or filled bands. Use GPURasterContours for a single level of raw marching-squares segments, and GPUTerrainContours (see GPU Terrain) for elevation levels with one overflow flag.
  • GPURasterStretch computes linear, percentile, and equalization stretches together with a colormap lookup and statistics row, using integer atomics only. Use GPURasterContrast for a calibrated, nodata-aware contrast or gamma that keeps the scalar domain, and GPURasterHistogram when you only need the histogram.
  • GPURasterZonalStatistics reduces a raster band over a pre-rasterized grid of zone IDs. Use GPUZonalStatistics from GPU Spatial Analysis when the input is points and polygon features instead of a raster.
  • GPUDistanceField and GPUCostDistance are the Euclidean and friction-weighted surfaces. Use GPU Network reachability when travel follows a road network rather than a grid.

Quick start

import {GPUCommandGraph} from '@luma.gl/graph/gpu-core';
import {GPUParameterBuffer} from '@luma-contributors/analysis/analysis-core';
import {
  GPUDistanceField,
  getGPUDistanceFieldParameterValues
} from '@luma-contributors/analysis/raster-analysis';

const graph = new GPUCommandGraph(device, {id: 'raster-analysis'});
const parameters = new GPUParameterBuffer(device, {id: 'df-parameters', format: 'float32', length: 8});

// `grid` is a `GPURasterMetadata` (see `makeGPURasterMetadata`). `seedPositions`, `seedCount`,
// `seedMask`, and the output views are graph views created on `graph`.
graph.add(new GPUDistanceField({
  grid, parameters: parameters.importToGraph(graph),
  seedPositions, seedCount, seedMask,
  output: {distances, allocation, withinDistance}
}));
const compiled = await graph.compileAsync(); // once

parameters.write(getGPUDistanceFieldParameterValues({maximumDistance: 500}, grid));
compiled.encode(device.commandEncoder, {parameters: undefined});

encode() only records; submit with device.submit(). Running contributors covers compileAsync(), rebuilding without a stall, submission and why parameters is undefined.

Conventions

  • One grid. Grid contributors take grid: GPURasterMetadata; makeGPURasterMetadata({width, height, cellSize, origin, rowDirection}) builds an axis-aligned area grid. Packers whose layout holds a cell size, extent or latitude band take the frame's grid as their second argument and read it from grid.affine, so it is never typed twice. makeGPURasterBand(view, grid) wraps an output view as the input band of the next contributor. Values and optional validity may have spare capacity: the helper borrows exactly grid.width * grid.height entries at each view's existing byte offset, without copying. Both views must be packed, cover the grid and belong to the same graph.
  • parameters in, output out. The packed per-frame view is parameters (a second view of another format is uint32Parameters); outputs live in one output bag, the validity output is validity (an input row filter is mask), and one-row status words are in output.status.
  • Graph views in, graph views out. Inputs and outputs are GraphDataView, GraphVectorView, or GraphTextureView objects created on the target graph. Outputs are always caller-owned; scratch storage is graph transients that die with compiled.destroy(). Contributors never compile, encode, submit, or read back.
  • Per-frame values never recompile. Viewports, thresholds, radii, observer positions, budgets, and region shapes are read from storage views, usually a GPUParameterBuffer that the application rewrites with write(). Lengths, capacities, grid sizes, and which optional views exist are compile-time topology; each prop's TSDoc says which category it belongs to.
  • Bounded results report overflow on the GPU. Compact ID lists use GPUCompactOutput (ids and a status with count, overflow and optional requiredCount). status.count is clamped to ids.length and can be an indirect draw instance count; status.overflow is rewritten every encoding.
  • Stable IDs. Result IDs are the caller's sourceIds[row] (or tile IDs) when given and zero-based rows otherwise. Node and transient IDs are ${id}-<step>, so two instances in one graph need different id props.
  • Shared contracts. Four shapes mean the same on every analysis page:
    • Status. Every GPU-written status word sits in the status member of the bag that owns it: output.status.overflow, output.status.converged, and output.status.code for model fits.
    • Grid. Raster and terrain contributors take grid: GPURasterMetadata, and their packers read the cell size from it (see GPU Terrain conventions).
    • Network. Network contributors take topology: GPUNetworkTopology (offsets, neighbors, weights, optional nodePositions). Its CSR part can be passed as GPUSpatialWeights (see GPU Network conventions).
    • Polygons. Polygons use the four-level GPUPolygonGeometryPort: kind: 'polygons', positions, featureOffsets, polygonOffsets and ringOffsets. Contributors with a single geometry take the same fields flat, without kind (GPUPolygonGeometryFields). See Shared ports.
  • Extent-local coordinates. Positions, extents, seeds, sample points, and output vertices are float32, whose ulp is 0.5 m at a UTM northing of 4.6e6 m and 2 m at 2e7 m in EPSG:3857. The parameter packers of GPUDistanceField, GPUIsolines, GPUIsobands (and GPUIsobandRings), GPURasterSampling, and GPURasterProfile take an optional float64 localOrigin: they subtract it from the extent or grid origin in float64, seeds, points, and line vertices are uploaded relative to it, and contour, band, and sample-position outputs come back relative to it. Add it back on the CPU or as the layer's coordinate origin. With the raster or tile corner as origin, positions keep about 1.2e-7 of their distance from it (a 2.5 m UTM raster places contour vertices within 0.02 mm of a float64 reference, against 0.34 m with absolute coordinates). The default [0, 0] keeps absolute coordinates. GPUPolygonRasterization follows the same rule with caller-subtracted coordinates.
  • Row direction. GPURasterSampling, GPURasterProfile, GPUDistanceField, GPUCostDistance, GPUPolygonRasterization, GPURasterReprojection and the fractional coverage classes take the row direction from grid.affine. GPUIsolines, GPUIsobands, GPUIsobandRings and the flow family (GPULineIntegralConvolution, GPUStreamlines, GPUParticleAdvection, GPULagrangianFlowMap, GPUFiniteTimeLyapunovExponent) do not: they place row 0 at the smallest y of their extent and ignore the affine, with no check at construction. Give them a raster whose rows run from south to north (reverse the row order of a north-up raster before upload). In the flow family v is the velocity toward larger y. Making them follow the affine is deferred (roadmap 12.4).
  • Non-finite samples are nodata. NaN and both infinities are nodata in every raster contributor on this page, GPURasterSampling, GPURasterProfile and GPUFocalStatistics included (before 2026-11-10 those three kept an infinity as a value).
  • One import per buffer. Import a buffer once (for example with graph.importGPUData() or GPUParameterBuffer.importToGraph()) and pass the returned view to every contributor that reads it, so the graph tracks hazards on one logical handle.

GPUCostDistance and GPUCostDistancePath

GPUCostDistance: With continuation, settledAt stores cumulative last-decrease rounds across resumed submissions. Explicit or automatic restart clears it together with costs/state; removing all sources restarts the result.

Accumulated cost surface over a friction raster from per-frame source cells, a source mask, or both: 8-connected moves cost ground distance times mean friction, invalid or negative friction is a barrier, and a per-frame cost limit, isoline-ready bands with counts, and D8 back-links are optional. Relaxation runs in 16x16 workgroup tiles with workgroup-memory repeats and per-tile activity, gated on the GPU like GPUNetworkReachability. GPUCostDistancePath walks the back-links from a per-frame target into a compact cell list. The cost surface feeds GPUTerrainContours directly for isolines. Both take a grid and write into an output bag (costs, backLinks, bands, bandCounts and status for GPUCostDistance; path and status for GPUCostDistancePath). The grid supplies the width, height, cell size and latitude band, and the packer takes it as its second argument. The move lengths are hypot(a, d) along a row, hypot(b, e) along a column and the root of the sum of their squares on a diagonal, which needs perpendicular pixel axes: axis-aligned and rotated grids are accepted, and a sheared affine (a * b + d * e not zero) throws at construction and in the packer, because its two diagonals have different lengths.

When maximumIterations stops the relaxation before a fixpoint, passable costs are NaN and bands and band counts are GPU_COST_DISTANCE_UNRESOLVED, so a truncated surface never reads as a converged one. Every relaxation round shares one pipeline per pass variant: its gate-group position is a GPU word, not WGSL text.

const grid = makeGPURasterMetadata({width, height, cellSize: 10});
graph.add(new GPUCostDistance({
  grid, friction, parameters: parameters.importToGraph(graph),
  sources: sources.importToGraph(graph), maximumIterations: 512,
  output: {costs, backLinks, status: {converged}}
}));
graph.add(new GPUCostDistancePath({
  grid, backLinks, target: target.importToGraph(graph), output: {path: output}
}));
parameters.write(getGPUCostDistanceParameterValues({costLimit: 5000}, grid));

frictionParameters (a GraphDataView of [scale, offset], per frame; its presence is compile-time) applies friction = value * scale + offset on top of the band's own calibration, so a friction slider is a buffer write. Results that are negative or non-finite are impassable. Relaxation uses one gate node per four rounds, so the unrolled loop has about a third fewer nodes (271 to 189 in the explorer, converging after 43 of 128 iterations).

Back-links across zero-friction plateaus come from a second, tie-level relaxation. It now defaults to maximumTieIterations = maximumIterations (it was 8) and uses the cost phase's schedule, with directional tile sweeps after sweepAfterIteration, so long or winding plateaus resolve. A link that a budget cut short is GPU_COST_DISTANCE_UNRESOLVED (0xfffffffe), never 0, because 0 would claim a source. That covers every passable cell when the cost relaxation stops at maximumIterations, and plateau cells whose tie level did not converge. GPUCostDistancePath returns an empty path when the walk meets an unresolved link, and sets its optional one-row output.status.iterationLimitReached. It also returns an empty path for links that do not form a valid forest (an invalid code, a link off the grid or into an unreached cell, a cycle), so it only ever reports a complete path from the target to a source.

maximumIterations defaults to 512. After sweepAfterIteration iterations (default 96) relaxation adds directional tile sweeps that carry a front along a whole row or column of tiles, so long corridors and spirals converge in far fewer iterations; open terrain converges before the switch. Pass sweepAfterIteration >= maximumIterations for plain tiled passes only.

continuation: {state, values} (opt-in) spreads one relaxation over several submissions instead of unrolling every round: maximumIterations then defaults to 64 and is the budget of one execution. state is a zero-filled imported uint32 buffer of getGPURasterRelaxationContinuationStateLength(grid) words and values an imported float32 per-cell buffer (neither can be a graph transient, which the planner may alias). An execution resumes the previous one when that stopped unconverged, skipping initialization and seeding; after a converged run, or after the caller writes a nonzero value at element GPU_RASTER_RELAXATION_RESTART_WORD of state (the GPU clears it), it starts from scratch. Set the restart word whenever an input changes. output.status is cumulative, the sweep schedule follows the cumulative count, and output.costs stays NaN for passable cells until the converging execution. Poll converged and submit again until it is 1. Not supported with output.backLinks.

Back-links are cycle-safe across zero-cost plateaus: a cell links to its strictly cheaper tight neighbor or, when it was reached only across zero-cost moves, to the equal-cost neighbor one tie level closer to a strict entry or a source. The tie phase runs only when output.backLinks is requested and takes up to maximumTieIterations (default maximumIterations) extra gated iterations; output.status.converged is 0 if either phase was truncated. The isochrone breaks are the per-frame costBreaks input, required exactly when output.bands or output.bandCounts is given.

Generated transient IDs are prefixed with the contributor id, for example <id>-total. If one collides with a caller resource, the error names the contributor and the generated ID.

Output Type Description
output.settledAt (optional) GraphDataView<'uint32'> Packed, one value per cell: the 1-based gated relaxation round in which its cost last decreased; 0 for sources and cells whose cost never decreased. For a converged run, visualizes the propagation wavefront. Adds one store per improved cell; omit in production. Must be distinct from inputs and other outputs. Not supported with continuation.

GPURasterZonalStatistics

Optional zoneDictionary maps sorted native uint32 IDs to dense rows. sourceZoneIds and denseZoneRows make row association explicit; invalidCount reports IDs missing from the dictionary. Omitting the dictionary retains dense IDs. Strings and automatic dictionary construction are not supported. For example, sourceZoneIds [100, 900] corresponds to denseZoneRows [0, 1]: the former preserves caller identities and the latter publishes physical output rows (or 0xffffffff for an invalid dictionary).

Counts cells and computes the mean, lowest and highest elevation of each land-cover zone from a zone raster.

::lens{scenario=gpu-raster.raster-zonal-statistics rung=result caption="Elevation statistics per land-cover zone; tree cover spans the widest range."}

Per-zone cell count, valid-value count, sum, mean, minimum, and maximum of a value band over a dense uint32 zone raster (for example rasterized administrative areas). Calibration, nodata, validity, and non-finite samples are honored; one ignored zone ID is skipped silently, and zone IDs at or above the compile-time capacity raise a GPU overflow flag. Composes GPUGroupAggregation.

graph.add(new GPURasterZonalStatistics({
  grid, zones, values: {id: 'ndvi', format: 'float32', storage: {kind: 'buffer', values}},
  zoneCapacity: 256, ignoredZone: 0,
  output: {valueCounts, means, minimums, maximums, status: {overflow}}
}));

sumOrder defaults to 'sorted': cells are stably sorted by zone ID and each zone is reduced in a fixed tree (the same sorted segmented sum as GPUZonalStatistics), so sums and means are bitwise reproducible on one device, at about 6-25 ms at 2048x2048 for any zone layout. 'atomic' skips the sort and is at most about 1.5x faster, only with 1000 or more spatially scattered zones; it can be 10-60x slower when neighboring cells share a zone, because float compare-exchange atomics contend on one address, and its last bits can vary between runs. Counts, minimums, and maximums are exact either way.

Longitude/latitude rasters set cellSizeMode: 'geographic', parameterLayoutVersion: 2, and a per-frame parameters view [cellSizeX, cellSizeY, northEdge, southEdge, signedRowStep, originPoleDistance, poleSign] (version 2), packed from the grid with getGPURasterZonalStatisticsParameterValues(grid). The signed row step preserves thin-cell area when the float32 latitude edges round equal. originPoleDistance = 90 - abs(firstRowEdgeLatitude) is packed before float32 rounding; poleSign is -1 south of the equator and +1 otherwise. Evaluating the midpoint relative to that pole preserves shifted thin polar windows. Geographic weighting requires an axis-aligned grid. The default parameterLayoutVersion: 1 always decodes the legacy four-word prefix and ignores all padding, including nonzero padding. It derives the row step from the edge difference and can lose thin-cell area. Version 2 is explicitly selected and requires at least seven words; view length never selects a layout. A packer target shorter than seven words requests the legacy prefix. Each cell is then weighted by its area on the WGS84 authalic sphere: sums are sum(a * v) in value times square meters, means are sum(a * v) / sum(a), and the optional weightSums column is the valid area of each zone. Counts, minimums, and maximums are never weighted, and the default 'uniform' mode is unchanged. Optional variances and standardDeviations are unbiased two-pass estimates with the GPUZonalStatistics convention: sum (v - mean)^2 / (n - 1), or with cell areas as reliability weights sum a (v - m)^2 / (V1 - V2 / V1) (numpy.cov(v, aweights=a, ddof=1)). They add a second pass over the cells, so request them only when needed. The divisor is n - 1 (sample form): two cells with values 1 and 3 give a standard deviation of 1.414. ArcGIS Zonal Statistics, rasterstats and GPURasterCellStatistics divide by n (1 for the same cells); multiply a variance by (n - 1) / n to convert.

GPUDistanceField

Turns a seed mask into the exact Euclidean distance in metres from every cell to its nearest seed.

::lens{scenario=gpu-raster.distance-field rung=result caption="Distance to the nearest water body, from the WorldCover water cells of the Dixie window."}

Euclidean distance transform and nearest-seed allocation (Voronoi zones) on a raster grid, from seed points snapped to cells, a labeled seed raster, or both. distances holds the grid distance from each cell center to the nearest seed cell center (+Infinity when unreached), allocation the nearest seed's ID, and nearestCells its cell; ties break on the smallest seed ID. A per-frame maximumDistance clears cells beyond it and fills an optional withinDistance mask, and an optional r32float texture receives a copy of distances. Cell sizes may differ in x and y.

Distances use grid units (world units of the affine), so degree grids yield degree distances, not meters; ground-meter conversion is a non-goal of GPUDistanceField—use GPUCostDistance with cellSizeMode: 'geographic' | 'web-mercator' and unit friction for ground-meter distances.

const parameters = new GPUParameterBuffer(device, {id: 'df-parameters', format: 'float32', length: 8});
graph.add(new GPUDistanceField({
  grid, parameters: parameters.importToGraph(graph),
  seedPositions, seedCount, seedMask,  // capacity is seedPositions.length
  output: {distances, allocation, withinDistance}
}));
parameters.write(getGPUDistanceFieldParameterValues({maximumDistance: 500}, grid));

mode: 'exact' (default) is the separable Felzenszwalb-Huttenlocher transform, banded as in the Parallel Banding Algorithm (Cao et al. 2010): banded column scans find the nearest seed row, then 32-column band envelopes of those candidates merge pairwise in ceil(log2(width / 32)) rounds and a banded running maximum colors each row. Every pass runs about width * height / 32 invocations instead of one per row or column, and the result is bit-identical to the sequential envelope. Candidates compare by exact integer squared offsets when the cell is square and by f32 squared ground distance otherwise, so allocation matches a brute-force oracle exactly on square cells. 'exact' is exact on isotropic grids only: with unequal cell width and height the f32 keys can misorder near-ties, and envelope crossings can be off by a cell. A correctly rounded square root keeps distances within 1 ULP of an f64 reference (0 ULP when the cell size is a power of two). mode: 'jump-flood' is a cheaper preview for dragging seeds: ceil(log2(max(width, height))) full-grid passes plus jumpFloodRefinementIterationCount extra passes (exactly 0, 1, or 2; default 1). It always reports the distance to a real seed, so it can only overestimate; on random 256x256 scenes JFA+1 misallocated at most 0.009% of cells with errors up to 1.24 cells, and JFA+2 was exact in the measured scenes (not guaranteed).

A seed mask value v is the seed ID v - 1: write 1 for a plain mask or label + 1 for per-zone allocation. Seed point IDs default to the row index or come from seedIds. Rewriting seeds, the count, the mask, or parameters never recompiles the graph. The grid origin and cell size come from grid (axis-aligned, north-up or north-down), not from the settings.

For projected grids pass localOrigin (for example the raster corner) to getGPUDistanceFieldParameterValues and upload seedPositions relative to it, so seeds near a cell edge snap to the same cell as in float64. The grid origin stays absolute.

GPURasterReclassify, GPUWeightedOverlay, and local raster operations

Per-cell map algebra over float32 rasters or plain columns, with every table, weight, threshold, and operation code in a per-frame parameter view, so sliders never recompile. Rasters are packed row-major float32; NaN is always nodata, and an optional finite noDataValue sentinel is compared exactly. The sentinel marks raster cells only: a per-frame constant operand that equals it is a value, so GPURasterConditional with noDataValue: 0 and constantB: 0 writes 0 where the condition fails, and GPURasterArithmetic maximum(a, 0) with noDataValue: 0 is defined wherever a is. Stacks are band-sequential: layer i occupies rows [i * cellCount, (i + 1) * cellCount).

GPURasterReclassify.values and GPURasterConditional.conditionValues, a, and b also accept published GPURasterBand inputs. Supply grid when any input is a band. Buffer bands may be float32, uint32 or sint32; texture bands use the published scalar/channel storage contract. The published raster conversion resolves native no-data and band validity before applying scale and offset. Non-finite band samples are missing. Legacy float views keep the NaN/sentinel rules above, including infinity handling. The contributor-level noDataValue applies only to legacy views; each band owns its native sentinel. In a conditional, only the chosen operand must be valid, and an invalid condition always produces NaN. An additional reclassify mask still filters cells. Band storage and validity may have padding after the grid; only the grid prefix is read. Reclassify uses the grid cell count by default for a band and can classify a smaller rowCount prefix. Band metadata and grid dimensions are compile-time; input contents and masks can change each frame.

GPURasterCellStatistics.stack and GPUWeightedOverlay.stack also accept an ordered array of published bands: stack: [elevationBand, moistureBand, ...]. Supply exactly layerCount bands and grid with exactly cellCount cells; every band must already occupy that complete grid. Buffer and texture storage and native scalar formats can be mixed. Each band's validity, native nodata, scale and offset are resolved independently. The top-level noDataValue applies only to the legacy packed stack, so a calibrated band value equal to it stays valid. The existing mask, nodata policy, minimum valid count, frequency tie rules and remapping operate on calibrated observations.

Band arrays are converted and packed on the GPU into one float32 stack, so the analytical kernels keep one input binding even at 64 statistics layers or 16 overlay layers. The extra stack occupies 4 * cellCount * layerCount bytes, plus published band-conversion scratch. Its binding must fit the device's storage limit; reduce the grid or layer count if construction of the command nodes rejects it. estimatedCommandNodeCount bounds conversion, packing and analysis nodes and is checked at construction. Compiled graphs own the scratch; these contributors need no destroy(). Legacy packed stacks retain their existing path and results.

Band metadata is validated at construction. Calibration and non-NaN float sentinels must round to finite float32; integer sentinels must be integers within the native uint32 or sint32 range. Textures must select one 2D mip, one array layer and one sample, preserve the declared band scalar format, and select an existing channel. Validity must belong to the same graph as the band storage.

Contrast stretches and colormap lookups for a float32 raster, computed on the GPU every frame with no readback: a linear min/max stretch, a percentile stretch (for example 2%/98%), and histogram equalization, with optional display gamma (t^(1/gamma), so gamma > 1 brightens, as in rio-color and GIMP levels) and sigmoidal contrast (normalized so 0 and 1 are fixed). NaN, the applicable no-data sentinel, and cells rejected by band validity or mask are nodata (stretched NaN, colors 0). A constant raster (lo == hi) maps values below to 0, equal to 0.5, above to 1; with an automatic domain and no included cell, statistics is NaN and validCount 0.

A cell with a nodata corner (NaN or an infinity, optional noDataValue, optional validity) emits nothing; infinities are nodata because a crossing cannot interpolate them. The extent must be finite with max > min on both axes (a y-down or zero-size extent throws). Corners with value >= level are high; saddles are resolved by the bilinear (asymptotic) decider of the published GPURasterContours: the two high corners are joined when the saddle value of the bilinear surface through the four corners, (v0 * v2 - v1 * v3) / (v0 + v2 - v1 - v3), is at or above the level (a tie joins). Before 2026-11-10 the rule was the corner mean ((v0 + v1) + (v2 + v3)) / 4; the two differ only on saddles whose corners are far from symmetric, such as 10, 0, 1.1, 0 at level 1 (mean 2.775 joined them, saddle value 0.991 separates them). Crossings are computed once per canonical edge (left to right, bottom to top), so neighbouring cells produce identical vertices.

GPUIsolines.values and GPUIsobands.values also accept a published GPURasterBand on grid. Buffer bands support float32, uint32 and sint32; texture bands use the published scalar/channel storage contract. Conversion honors native nodata and nonzero band validity before applying scale and offset. Non-finite samples become missing. The contributor-level noDataValue applies only to legacy float views, so a calibrated band value equal to that sentinel remains valid. An additional mask still filters samples, and any missing corner excludes its marching cell from all geometry. Classes, segments, stitched polylines, triangles and boundary edges use the same calibrated values.

Band metadata and grid dimensions are compile-time; sample values, band validity and masks can change between encodings. Buffer storage and validity may have byte offsets and padding after the grid; only the grid prefix is converted. Canonicalization allocates graph-owned float32 values and uint32 validity, each 4 * grid.width * grid.height bytes, and checks the device binding limit before allocation. For tiled isolines the band covers the local grid including its halo, while parameters still describe the shared domain. Contour coordinates continue to use the explicit parameter extent and the row direction documented below.

Isoline tiles. Optional compile-time GPUIsolines.tile partitions the domain into owned marching cells with halo samples. The tiling guide is the canonical contract for ownership, shared placement parameters, per-tile status, fragment joining and composition with external vector boundaries. The existing Dixie Fire lens uses one resident grid without tile.

Row direction. GPUIsolines, GPUIsobands and GPUIsobandRings place row 0 of the raster at minY of the extent and read sample dimensions (grid, or the domain for tiled isolines), not grid.affine. Construction validates tile bounds but does not infer row direction. A north-up grid (row 0 at the top, the default of makeGPURasterMetadata) therefore comes out mirrored north to south unless you reverse the row order of the raster before upload. Mirroring the output instead (y' = minY + maxY - y) also swaps the documented side: high values are then on the right of a segment and ring windings are reversed. Making these classes follow the grid affine is deferred (roadmap 12.4).

A corner exactly on a level gives a zero-length GPUIsolines segment. The raw segment output keeps it, because the edge-based stitching needs it as the bridge between the neighbouring cells' chains; a contour through a sample stays one polyline. Stitched polyline vertex lists collapse bit-identical consecutive vertices (a polyline made only of such segments keeps one vertex), and the vertex capacity is checked before that collapse.

GPUIsolines writes proper two-endpoint segments [x0, y0, x1, y1] (high side on the left), their level index, and optionally the global edge ids [startEdge, endEdge], ordered by (cell, level, slot). Unlike GPUTerrainContours, a record is one segment, not a vertex pair to reassemble. Passing output.polylines stitches segments of the same level into deterministic polylines by pointer jumping in a fixed ceil(log2(capacity)) + 1 rounds: open chains start at the segment with no predecessor, closed rings at their smallest segment index and repeat the first vertex; polylines are ordered by head segment. Publishing the longest prefix that fits the vertex capacity uses binary search over at most segmentCapacity offsets, taking at most ceil(log2(segmentCapacity + 1)) steps in one invocation.

GPUIsobands writes bandClasses (number of breaks <= each sample, 0xffffffff for nodata) for fragment-side shading, and band geometry as counter-clockwise triangles with a band index: each cell's fragment of band [b[k - 1], b[k]) is Above(b[k - 1]) ∩ Below(b[k]), built combinatorially from the cell boundary walk (no float clipping), at most two convex pieces per band and cell. An optional status.vertexCount (3 * status.count) feeds a non-indexed indirect draw, and firstBand/lastBand limit the emitted bands per frame.

The packers take the frame's grid (its width and height give the cell sizes and must match the contributor's). On projected rasters add localOrigin: [extent[0], extent[1]] to both packers' settings. Segments, polyline vertices, triangles and ring vertices are then relative to it, so draw them with it as the layer's coordinate origin. It also keeps GPUIsobandRings vertex hashes within their i32 range, which saturates beyond 2^31 * vertexTolerance (214,748 units at the default tolerance).

GPUIsobands can also write the band boundary as edges: output.edges (float32x4), edgeBands, status.edgeCount, status.edgeOverflow and an optional status.edgeRequiredCount. Edges are counter-clockwise with the band on the left; an edge shared by two cells cancels, and a zero-area cell (one or two samples exactly on the lower break) writes none, so edges lying on a break leave no slits.

GPUIsobandRings chains those edges into closed rings with GPUSegmentRingAssembly, grouped by band, so every band comes as shells and holes (holes attach within a band) and, optionally, GeoArrow polygons with sourceIds. Props: grid, values, breaks, parameters (same packing as GPUIsobands), a compile-time edgeCapacity, vertexTolerance, splitTouchingRings and output (the GPUSegmentRingAssembly outputs plus optional status.edgeCount and required status.edgeOverflow). Check both status.edgeOverflow (intermediate boundary-edge truncation) and status.overflow (final ring/vertex capacity) before using geometry. Each edge status view is packed uint32 with at least one word; the edge publisher writes only its first logical word and leaves padding untouched, including at nonzero byte offsets. Intermediate edge status ranges must not overlap final ring output ranges; construction rejects these aliases before allocating scratch. Props and output/status bindings are captured once. A zero final overflow word alone does not establish complete rings. Construction refuses an omitted edge-loss word; both flags are overwritten each encoding. Maximum: edgeCapacity and the ring capacity (output.ringOffsets.length - 1) are each at most getGPUIsobandRingsMaximumEdgeCapacity(device) and getGPUIsobandRingsMaximumRingCapacity(device) (8388608 on a default device). Unlike the triangle fill it gives true boundary geometry, but filling it for display needs polygon triangulation or rasterization (GPUPolygonRasterization gives an exact even-odd fill at raster resolution).

Outputs are ordered by count, GPUScan, and scatter, so they are deterministic; capacities are segments.length and triangleBands.length, with clamped status.count, status.overflow, and status.requiredCount rewritten every encoding. If segments overflow, stitching produces no polylines and sets its own status.polylineOverflow; a short vertices buffer keeps only the complete polylines that fit (the worst case is 2 * segmentCapacity vertices). Coordinates match an f32 CPU oracle within a few ULP (GPU division and FMA contraction); topology, ordering, and band indices match exactly.

GPURasterSampling and GPURasterProfile

Both contributors accept a published GPURasterBand in values, including buffer and texture storage. Band validity, native nodata and calibration are resolved by published raster primitives before interpolation. mask filters additional cells; the legacy noDataValue applies only to a bare value view, so a calibrated band value equal to that sentinel remains valid. Padded buffer views are bounded to the grid, and borrowed validity is reread on every encoding.

Writable sampling and profile outputs must use buffers separate from inputs, including separate imports of the same physical buffer. Construction errors name both conflicting ports: for example, output.values conflicts with values.storage.values, or output.status.count conflicts with values.validity. Bare raster views are named values; a band's buffer and validity are named values.storage.values and values.validity. Optional masks, point counts, polyline offsets, positions and parameters retain their own prop names in errors. The same physical-buffer rules apply to raster algebra, isolines and isobands: separate graph imports do not make a shared allocation independent. Writable outputs also require distinct physical allocations. Algebra diagnostics preserve operand names (for example output.values conflicts with a), band validity (a.validity), and stack indices (stack[1].validity) instead of private binding indices.

GPURasterSampling samples a float32 raster at points ("extract raster values to points", draping, tooltips). The pixel coordinate is u = (x - minX) * (1 / cellWidth) - 0.5, so integer u is a cell centre; the extent, cell size, and row direction (row 0 at maxY for a north-up grid) come from the grid. Points outside the closed extent (or with NaN coordinates) give NaN; inside it, indices beyond the outermost centres clamp to the edge cell. nearest is the cell containing the point (the maxX/maxY edge belongs to the last cell), bilinear uses the four surrounding centres, bicubic is Catmull-Rom (a = -0.5) over the 4x4 support. A neighbour participates only when both axis weights are nonzero, so a point on a cell centre returns that cell. noDataPolicy: 'strict' gives NaN when a participating neighbour is nodata; 'renormalize' divides the valid bilinear weights by their sum; bicubic with nodata in its support falls back to the bilinear rule of the same policy. Nodata is NaN or an infinity, an optional finite noDataValue, or a zero validity flag. method, noDataPolicy, and the packed grid placement are per-frame; pointCount is an optional per-frame active count (rows beyond it are NaN and 0).

GPURasterProfile builds elevation profiles along polylines (positions plus CSR lineOffsets) at a per-frame spacing (planar distances in grid world units). Each line emits samples at 0, s, 2s, ... below its length plus the final vertex at exactly the length; a zero-length line emits one sample, an empty line none. Outputs (any subset): sample positions, distances, values, line IDs, cumulative gain and loss; per line: sample offsets (clamped to capacity), length, gain, loss, minimum, and maximum over finite samples (gain and loss sum positive and negative differences between consecutive finite samples); plus status.count, status.overflow, and status.requiredCount.

The profile pipeline is a serial per-line walk, GPUScan, a per-sample binary search and sample, then a serial per-line cumulative pass, all in fixed order, so results are deterministic.     stepLength: 0.5, // output pixels
    period: 8, // animated ripple, in steps; 0 = static LIC
    phase: frame / 30 // advance every frame to make the texture flow
  })
);
  • Noise is Philox white noise per output pixel keyed by (seed, column, row); the kernel is a Hann window, optionally times an animated ripple 0.5 * (1 + cos(2 * pi * (s / period - phase))).
  • Streamlines step along the normalised field (RK2) and stop at the field or output edge, NaN data, or speeds at or below minimumSpeed. Pixels whose centre has no data are NaN. A step is tangent to the field in world space and stepLength output pixels long, also on non-square output cells (before 2026-11-10 the step was scaled per axis, which bent the trace on non-square cells).
  • The output extent is independent of the field, so a viewport renders at screen resolution from a coarse field.

GPUStreamlines

Traces evenly spaced streamlines from jittered seeds of a vector field and prunes them to a separation distance.

::lens{scenario=gpu-raster.streamlines rung=result caption="Seeded lines pruned to 0.5 degree separation, coloured by seed index."}

Evenly spaced streamlines (after Jobard and Lefer) whose pruning is resolved by a random priority per seed instead of processing order, so the result is deterministic. Output is CSR polylines for a PathLayer.

graph.add(
  new GPUStreamlines({
    velocities, fieldWidth: 360, fieldHeight: 180,
    gridWidth: 180, gridHeight: 90, // occupancy grid; its cell is the separation distance
    seedColumns: 90, seedRows: 45, stepsPerDirection: 60, maximumIterations: 16,
    parameters: parameters.importToGraph(graph), // float32, 12
    uint32Parameters: words.importToGraph(graph), // uint32, 4
    output: {
      lines: {ids, status: {count, overflow, requiredCount}}, lineOffsets, positions, positionCount,
      status: {iterationLimitReached}
    }
  })
);
parameters.write(
  getGPUStreamlinesParameterValues({
    fieldExtent: [-180, -90, 1, 1],
    gridExtent: [-180, -90, 2, 2],
    stepLength: 0.5
  })
);
words.write(getGPUStreamlinesUint32ParameterValues({seed: 1, minimumPoints: 8}));
  • Seeds form a Philox-jittered lattice over the grid extent; each is traced L RK2 steps backward and forward. Priorities are Philox keys with ties toward the lower seed index.
  • The result equals a greedy pass in descending priority: reject a line whose seed cell is occupied, cut each direction before its first occupied cell, accept it if it keeps minimumPoints points, and occupy its cells. The GPU reaches it in at most maximumIterations GPU-gated rounds of claim (atomicMax of keys over the cells a line can still keep) and decide (accept lines that win all their cells); status.iterationLimitReached is 1 if rounds ran out (undecided lines are dropped).
  • Published lines are in ascending seed order: line i is positions[lineOffsets[i] .. lineOffsets[i + 1]). lines.status.overflow is 1 when lines were dropped because the line or point capacity was full.
  • Optional lines.status.candidateOverflow is 1 when the pruning budget leaves undecided seeds; it is independent of final capacity. requiredCount counts decided accepted lines and is then a lower bound. The CPU twin and both operation forms honor maximumIterations (default 32) and expose the same flags. GPU_STREAMLINES_CANDIDATE_UNCONVERGED (1) replaces the old overflow bit-2 constant; a zero final-capacity flag alone does not establish completeness.
  • Optional candidates outputs expose the traced lines before pruning, for diagnostics.

Both operation forms capture iteration budgets and nested output bindings once at construction, including inherited getters. Mutating the original JavaScript maps later does not change the operation; changes to bound buffer contents still apply on each execution.

GPUChangeDetection

Subtracts the before slice from the after slice for each band; here near-infrared and shortwave-infrared reflectance around the fire.

::lens{scenario=gpu-raster.change-detection rung=result caption="After minus before for near-infrared; strong decreases mark the fire scar."}

GPUChangeDetection computes per-cell change statistics over a dense float32 stack of time slices indexed (cell * sliceCount + slice) * bandCount + band (cell-major, like GPUTemporalReduction). A sample is missing when it is not finite (NaN or an infinity) or when the optional per-observation observationMask view (cell * sliceCount + slice, for example a per-date cloud mask) is zero for it, the rule of the raster time-series contributors. The modes are selected at compile time by which outputs are present; each present output group adds one compute node (two-slice, multiband, t-test, sen-slope, mann-kendall), and one thread handles one cell with fixed-order loops, so results are deterministic and no atomics are used.

const parameters = new GPUParameterBuffer(device, {
  id: 'change-parameters',
  format: 'float32',
  length: GPU_CHANGE_DETECTION_PARAMETER_LENGTH
});
graph.add(
  new GPUChangeDetection({
    slices: stack, // cellCount * sliceCount float32 rows
    parameters: parameters.importToGraph(graph),
    cellCount,
    sliceCount,
    output: {difference, logRatio, tStatistic, tPValue, senSlope, mannKendallS, significance}
  })
);
parameters.write(
  getGPUChangeDetectionParameterValues({beforeSlice: 0, afterSlice: 11, splitSlice: 6, alpha: 0.05})
);
  • compile-time: cellCount, sliceCount (2 to 256, at most 64 with senSlope), bandCount (default 1), the optional cell mask, significanceSource, and which outputs exist.
  • per frame (parameter buffer, no rebuild): beforeSlice, afterSlice, epsilon, alpha, splitSlice.
  • Two-slice outputs (any bandCount, cellCount * bandCount rows): difference (after minus before), logRatio (ln((after + epsilon) / (before + epsilon)), NaN when either side is <= -epsilon) and percentChange (100 * (after - before) / |before|, NaN when before is 0).
  • Welch t-test between slices [0, splitSlice) and [splitSlice, sliceCount): tStatistic, tDegreesOfFreedom (Welch-Satterthwaite) and two-sided tPValue. Missing slices are dropped; each group needs 2 valid slices and a positive standard error. Variance is two-pass. The p-value is the regularized incomplete beta I_x(df / 2, 1 / 2), x = df / (df + t^2), by continued fraction (at most 64 iterations) with a Stirling log-gamma, in float32 (about 1e-4 absolute for df up to 254).
  • senSlope: exact Theil-Sen median of the pairwise slopes over valid slices, by in-thread bounded max-heap selection. O(T^2 log T) per cell, so sliceCount <= 64.
  • mannKendallS (sint32, integer exact), mannKendallZ and mannKendallP: tie-corrected variance, Z = (S - sign(S)) / sqrt(var), p = erfc(|Z| / sqrt(2)) (Numerical Recipes erfcc, relative error below 1.2e-7). Fewer than 2 valid slices give NaN; all values tied give Z 0, p 1.
  • Multiband (bandCount >= 2, at most 16): changeMagnitude (Euclidean norm of the band difference vector) and changeDirection (float32 atan2(d1, d0) for 2 bands; uint32 sign code for 3 to 16 bands with bit b set for an increase and bit 16 + b for a decrease; NaN or 0xffffffff when any band is missing).
  • significance (uint32): 1 significant increase, 2 significant decrease, 0 otherwise, from the t-test p-value (default) or Mann-Kendall p-value (significanceSource: 'mann-kendall') below alpha; the sign follows the t statistic or S.
  • Masked cells write NaN (float), 0 (mannKendallS, significance) or 0xffffffff (multiband direction code).

GPURasterExtremaPyramid

Builds a min and max mip chain of a raster band, each cell holding the extremes of its pixel block.

::lens{scenario=gpu-raster.raster-extrema-pyramid rung=result caption="Highest elevation of each 960 m block, level 1 of the pyramid."}

An exact min/max mip chain (Tevs et al. 2008 maximum mipmaps) for conservative ray skipping. The GPU Terrain sight-line and point-horizon contributors use it for traversal: 'pyramid'.

  • Grid and outputs. The raster is grid (a GPURasterMetadata; its width and height size the pyramid, cells live in pixel index space so no cell size applies). The caller-owned views go in output (GPURasterExtremaPyramidViews): maximum, minimum, or one combined view of 2 * layout.length floats. With combined, pyramid.output (a GPURasterExtremaPyramidOutput, {layout, combined}) is what the consumers take as their pyramid prop.
  • Levels. Level L has blocks of firstBlockSize·2^L pixels (default 4), down to 1×1 or levelCount. Levels are packed into one float32 view per extremum, with offsets from getGPURasterExtremaPyramidLayout(grid, options).
  • Footprint. With footprint: 'bilinear' (the default), each cell also covers one extra pixel column and row. Every bilinear sample whose base pixel lies in the block is then bounded by that one cell. 'cell' gives the plain block extrema.
  • Validity. Invalid pixels are excluded. Cells with no valid pixel hold ∓FLT_MAX (GPU_RASTER_EXTREMA_PYRAMID_EMPTY_*).
  • Exactness. The GPU output is bit-identical to a CPU build. Level 0 reduces from pixels and each higher level reduces the 2×2 cells below in a fixed order.
