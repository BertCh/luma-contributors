# Raster EOF analysis and lagged correlation

Empirical orthogonal functions of a raster time series by the method of snapshots, and lagged correlation maps
against an index. Import from `@luma-contributors/analysis/raster-analysis`. Slices are regular slots: the lag and
the snapshot matrix count slices, with no date axis.

## Method of snapshots: the readback is explicit

A contributor never reads the GPU back, and the eigenproblem is small enough (`T x T`, `T` at most 256) to do on the CPU
in binary64. The flow is three steps, and the middle one needs your readback:

1. `GPURasterSnapshotCovariance` writes the Gram matrix `X_w' X_w` as fixed-point words.
2. Read `output.covarianceWords` back, then call `getGPURasterSnapshotCovarianceMatrix` and
   `getGPURasterSnapshotEOFDecomposition` on the CPU. The decomposition is a cyclic Jacobi eigendecomposition.
3. Upload `temporalModes` and `singularValues`, and run `GPURasterEOFProjection` for the spatial EOF maps.

```ts
const parameterValues = getGPURasterSnapshotCovarianceParameterValues({maximumValueMagnitude: 40}, cellCount);
// Step 1 on the GPU, with parameterValues uploaded as `parameters`.
// Step 2 after readback:
const matrix = getGPURasterSnapshotCovarianceMatrix(words, sliceCount, parameterValues[0]);
const decomposition = getGPURasterSnapshotEOFDecomposition(matrix, sliceCount, modeCount);
// Step 3: upload decomposition.temporalModes and decomposition.singularValues.
```

## `GPURasterSnapshotCovariance`

Removes each cell's temporal mean, then accumulates `weight * anomaly[s] * anomaly[t]` over cells for every pair of
slices. A cell with any missing sample, a sample above `maximumValueMagnitude`, or a weight outside `(0, 1]` is excluded
entirely, so results reflect complete cases; `keptCellCount` reports how many contributed. The sum uses the shared 96-bit
fixed-point accumulator, per block of 256 cells and matrix entry, so it is independent of thread order and reaches CPU
decoding at full precision. Accumulation invocations (`ceil(cells / 256) * T * (T + 1) / 2`) are limited to 65,535 workgroups of 256 in one dispatch, about
`1.7e7`, and a larger raster is refused at construction.

**Area weighting.** A weight `w` is applied as `sqrt(w)` on the data matrix, so pass `cos(latitude)` on a regular
latitude-longitude grid. Weights scale the anomaly products, not the temporal mean.

## `getGPURasterSnapshotEOFDecomposition`

Eigendecomposes the Gram matrix. `singularValues` are `sqrt(eigenvalue)`; `explainedVariance` is `s^2 / (T - 1)`;
`explainedVarianceRatio` is over the trace. `temporalModes` are mode-major and orthonormal.

**Sign convention.** Singular vectors have no intrinsic sign. Each temporal mode is flipped so that its largest-magnitude
entry (the first on a tie) is positive, and a spatial EOF takes its sign from its temporal mode. This is the convention
tested here against a NumPy SVD with the same rule; it is not claimed to equal xeofs' rule. Negating the data leaves
a temporal mode unchanged and negates the corresponding EOF.

## `GPURasterEOFProjection`

`u[cell, mode] = sqrt(weight) * sum_t((x[cell, t] - mean[cell]) * v[t, mode]) / s[mode]`. `componentSpace: 'weighted'`
(the default) publishes the left singular vectors of the weighted matrix, orthonormal under the plain dot product.
`'value'` divides by `sqrt(weight)`, giving a pattern in the field's own units, orthonormal under the area-weighted dot
product. Excluded cells are NaN with status 1; a mode with a zero singular value is NaN.

Reference: a binary64 NumPy SVD of the weighted anomaly matrix (`test/oracles/rts07-snapshot-eof-numpy.py`). **xeofs (MIT)
was not run** (it was not installed, to stay within the disk available when the fixture was generated), so the EOF definition is verified but the package itself is a pending oracle.

## `GPURasterLaggedCorrelation`

Pearson correlation of each cell against `referenceIndex` at fixed slice `lags`. At lag `L` the pairs are
`index[t]` and `cell[t + L]`, so a **positive lag means the index leads the cell**. Pairs are pairwise-complete and
means and variances are taken over those pairs. Below `minimumPairCount` the status is 1 and the value NaN;
zero variance (within float32 rounding of the mean) is status 2. Reference: NumPy, the same fixture.
