Change points and the expectation-based scan

STX-06 and STX-07. Import from @luma-contributors/analysis/gpu-spatial-analysis. Cubes use the layouts of GPUCubeLayoutTranspose: 'cell-major' (cell * sliceCount + slice) or 'period-major'.

Per-location change points: GPULocationChangePoints

GPULocationChangePoints runs unpruned optimal partitioning per cell: F(t) = min_s F(s) + C(s + 1..t) + beta, the same optimum PELT finds, with sliceCount^2 / 2 bounded segment costs and no pruning. Missing (NaN) slices are skipped; minimumSegmentLength counts finite slices. Values are standardized per location by the series' own mean and standard deviation (the Poisson cost uses a deviance form), so the partition does not depend on the unit of values. The moments of each segment are running sums that begin at the segment's own start, about its first value; no difference of two long prefix sums is formed, so a quiet segment after a loud one keeps f32 relative accuracy at sliceCount = 512.

Variance floor ('variance' and 'mean-variance'): a segment variance below 1e-11 times the variance of the whole series is raised to that value, so a constant segment has a finite cost whatever the unit. (Until 2026-11-10 the floor was 1e-11 in data units, which clamped every segment of a series in small units, for example values near 1e-6, and returned no change point.) The R changepoint package substitutes 1e-11 in data units only when a segment variance is not positive; the two rules pick the same segments, and differ in the value given to an exactly constant segment unless the series variance is 1. A constant series has no change point, and its optimalCost uses 1e-11 in data units.

cost Segment cost Smallest segment
'mean' sum (y - mean)^2, a unit-variance Normal cost: standardize values or scale penalty 1
'variance' n (ln(2 pi) + ln(s^2) + 1), s^2 = sum (y - m)^2 / n, m the mean of the whole series (the changepoint package's cpt.var) 2
'mean-variance' As 'variance' with each segment's own mean 2
'poisson' 2 x (ln n - ln x), x the segment total 1
'slope' Residual sum of squares of a line per segment, true slice positions 3

penalty and minimumSegmentLength are per-frame; pack them with getParameterValues. The R changepoint package uses the penalty SIC (p + 1) ln n, with p the parameters added per segment. With the unit-variance 'mean' and 'slope' costs, scale the penalty by the variance.

Outputs per cell: changePointCount (clamped to maximumChangePoints, the earliest kept), changePoints at cell * maximumChangePoints + index, the first slice of each later segment, unused rows GPU_LOCATION_CHANGE_POINTS_NONE. Optional: requiredChangePointCounts (unclamped), optimalCost (the sum of the segment costs plus penalty per change point), and status.overflow (1 when any cell needed more than the capacity).

Limits: sliceCount <= 512 (<= 256 for 'slope', whose time sums are exact unsigned integers up to that length), maximumChangePoints <= 128. In the slope cost, when one line explains almost all the variance the cancellation of standardized moments limits the absolute residual to about 2e-6 * sliceCount * variance.

Validated against ruptures 1.1.10 Pelt for 'mean', 'slope' and 'mean-variance'. The variance and Poisson costs are checked only against a binary64 reference of the published changepoint definitions in the spec; the R package is GPL and R-only and was not run, so the external R fixture is pending.

  • Packer: instance.getParameterValues(settings), writes the float32 parameter view.

Settings of instance.getParameterValues:

Field Type Description
penalty number Penalty beta per added change point, finite and non-negative, on the scale of the cost: see GPULocationChangePoints. For the changepoint package's SIC: (p + 1) ln n with p the parameters added per segment (1 for mean, variance and Poisson, 2 for mean-variance and slope, the Poisson and Normal likelihoods assume unit-variance scaling for mean and slope).
minimumSegmentLength (optional) number Smallest number of finite slices per segment. Defaults to the smallest length the cost is defined on: 1 for mean and Poisson, 2 for variance and mean-variance, 3 for slope.

Pettitt test: GPUPettittTest

K = max_t |U_t|, U_t = sum_{i<=t} sum_{j>t} sign(x_i - x_j), over the finite series in exact integers. Outputs one row per cell: statistic (uint32), changeSlice (the first slice after the change, GPU_PETTITT_TEST_NO_CHANGE_SLICE under 2 finite slices) and pValues (min(1, 2 exp(-6 K^2 / (n^3 + n^2)))). sliceCount <= 512. Checked against pyhomogeneity 1.1.

Corrected emerging hot spot trend

GPUEmergingHotSpots and addSpaceTimeHotSpotsRecipe take trendAutocorrelationCorrection:

  • 'none' (default): the unmodified Mann-Kendall test, as before.
  • 'hamed-rao' (Hamed and Rao 1998): ranks of the Sen-detrended series, lags whose autocorrelation exceeds trendCorrectionCriticalZ / sqrt(n) (default 1.96).
  • 'yue-wang' (Yue and Wang 2004): autocorrelation of the Sen-detrended values over all lags.

trendCorrectionMaximumLag limits the lags (default every lag). The correction is compile-time and needs sliceCount <= GPU_EMERGING_HOT_SPOTS_MAXIMUM_CORRECTED_TREND_SLICE_COUNT (63), where each cell can select the Sen slope in one invocation. trendS and the category codes keep their meaning. Checked against pymannkendall 1.4.3.

Expectation-based scan: GPUExpectationBasedSpaceTimeScan

The space-time permutation model of GPUSpatialScanStatistic conditions on the zone and bucket margins, so a rise shared by every zone is explained by the bucket margin and is not a cluster (Tango et al. 2011). This scan compares the counts with a supplied baseline instead: F = C ln(C / B) + B - C for C > B, Neill et al. (2005). It scans windows ending at the last bucket.

For each center and window length, the neighborhood is its nearest zones (the kNN table the scan builds, maximumNeighbors <= 64). Fast Subset Scan (Neill 2012): the best subset is a prefix of the zones sorted by C_i / B_i, so an exact search over the subsets of the neighborhood is a fixed sort and one prefix scan. A zone whose baseline is not positive is excluded. The most likely cluster is reported with its member zones.

Neighbor discovery defaults to nearestZoneSearch: 'auto', which uses the same exact coordinate indexes as the spatial scan for truncated lists (at most 64 rows). A whole-domain list uses full-scan. Neighbors are ordered by (separation key, zone row); a zero-distance tie with lower rows can displace the center itself. For three coincident zones and maximumNeighbors: 1, every neighborhood contains only row 0, so cases on rows 1 and 2 are outside those neighborhoods. 'indexed' selects it explicitly; 'full-scan' selects the exhaustive route for comparison. contributor.nearestZoneSearch reports the resolved route, and contributor.estimatedFullScanSeparationCount bounds exhaustive separation evaluations per submission by 5 * zones^2 for a shorter-than-domain list, or zones^2 for a whole-domain list, excluding sorting. Both routes order by (separation key, zone row) in planar and great-circle contexts. The index is rebuilt each submission; axis-degenerate data can still require quadratic search work. See the spatial scan neighbor discovery details.

Inference: maximumReplicates Monte Carlo replicates of independent Poisson counts from the baseline, each searched like the data. The p-value is (1 + #{replicate maxima >= observed}) / (P + 1). Secondary clusters and repeated-analysis adjustment are not implemented; convert with getGPUScanRecurrenceInterval(pValue, analysisInterval). Checked against an exhaustive binary64 subset enumeration and the same Philox streams; the scanstatistics R package (GPL, R-only) was not run, so its fixture is pending.

Inputs: cases and baseline, zones * timeBuckets rows (zone * timeBuckets + bucket). The baseline is the caller's: for example a moving average of earlier buckets. Parameters (seed, replicate count, per-frame window limit) are packed by getGPUExpectationBasedScanParameterValues. Limits: maximumWindowLength <= 32, maximumReplicates <= 99999. Outputs: clusterZones, clusterStatistics (GPU_EXPECTATION_BASED_SCAN_CLUSTER), statistics (maxima per replicate, observed first), summary (GPU_EXPECTATION_BASED_SCAN_SUMMARY) and optional zoneStatistics.

{/* lens:GPUExpectationBasedSpaceTimeScan */}

Prospective mode of GPUSpatialScanStatistic

temporalMode: 'prospective' keeps only windows that end at the last bucket, in the observed data and in every replicate. The default 'retrospective' is unchanged. No adjustment for earlier analyses is applied: report recurrence intervals with getGPUScanRecurrenceInterval(pValue, analysisInterval), in the unit of analysisInterval, and treat alarms from repeated analyses accordingly (Correa et al. 2015; Kulldorff and Kleinman 2015).
