Geometry refinement computation lenses

These executable examples use small, explicitly synthetic coordinates in arbitrary planar units. Each lens captures the actual GPU command graph, input buffers and bounded outputs. Read active counts, validity masks and status before interpreting unused capacity. See Geometry refinement for supported domains and limitations; these examples are not independent numerical validation or performance benchmarks.

GPUNormalizePolygons

A rotated, counterclockwise rectangle becomes a clockwise ring starting at its smallest coordinate. Offset captures retain the polygon hierarchy.

GPUSegmentSnap

Default searchStructure: 'grid' reuses candidate scratch in batches of at most 256 lines. candidateCapacity defaults to 1,024 and is at most 4,294,967,290. Overflow uses bounded exhaustive fallback or reports incomplete geometry; candidateOverflowPolicy: 'incomplete' disables fallback. If this can suppress a line, supply issueCode, validity or status.candidateOverflow; required geometry/count outputs alone are rejected because suppressed and genuinely empty lines have the same zero counts. This check applies to GPU and CPU operation forms too. Explicit brute force and fallback bound (positions + lines) * (references + 1)^3 by 16,777,216.

Two reference points are inserted along a six-unit segment in projection order. Counts delimit the fixed output slots; issue codes and source edges are captured. Optional validity is nonzero for usable lines.
