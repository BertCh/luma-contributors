GPU Spatial Analysis

:::caution Experimental @luma-contributors/analysis/gpu-spatial-analysis is an experimental entry point. APIs may change between releases without a deprecation period. :::

The @luma-contributors/analysis/gpu-spatial-analysis entry point is the analysis layer above luma.gl's GPU spatial primitives. It does not reimplement them. It composes the geospatial kernels (projection, distances, point-in-polygon, GPUGridIndex, GPUPointSpatialQuery) and the GPU Core primitives (sort, scan, compaction, hash and grid indexes, GPUBVH, segmented reductions) into higher-level workflows: spatial weights and their algebra, statistics computed on those weights, predicate and nearest joins, geometry validity, density, discrete global grid cells, line and trajectory geometry, regression, change of support, distribution dynamics, accessibility, and prebuilt recipes. New WGSL is written only where no primitive fits.

Reach for the geospatial kernels when you need one primitive (a distance, a containment test, one indexed query per frame). Reach for this entry point when the question is about every row at once, or about statistics over the neighborhood structure.

For global Moran, local Moran and hot-spot analysis, pass a neighbor search's outputWeights directly to the statistic. It carries completeness status with the CSR buffers. Final-capacity or candidate-capacity loss suppresses inference; the statistic's optional output.status.overflow and candidateOverflow forward the producer's flags separately. Overflow is final-slot loss; candidateOverflow is intermediate loss, including contiguity pair scratch. Chunk-local loss flags are rejected by these statistics; use aggregate status on the outer port.

See expansion computation lenses for executable examples of the new contributors and recipes. These cards expose actual command graphs and status outputs on explicit illustrative inputs.

Overview

Each contributor is an algorithm or workflow that declares resources and command nodes into a caller-owned GPUCommandGraph through getCommandNodes(graph) (GPUCommandNodeProducer), and is added with graph.add(contributor). They are composed from GPU Core primitives (GPUVisibilityWorkflow, GPUBVH, GPUGridBinning, GPUHistogram, GPUReduction, GPUAncestorProjection, and others) and the raster operators; new WGSL is written only where no primitive fits.

Quick start

Run the complete point-density walkthrough. It creates its own device and five positions, then reads [2, 0, 1, 1] from a 2 × 2 grid and releases every resource. Use that program as the shared execution scaffold for the other families.

Point density's domain-specific ports are:

Port Format and rows Meaning
positions float32x2, one row per point Planar XY positions; nonfinite and out-of-bounds points are excluded.
bounds float32, 4 rows [minimumX, minimumY, maximumX, maximumY]; buffer contents can change each submission.
output.values float32, columns × rows Per-cell statistic, X varying fastest; 'count' is the default.
output.status.overflow optional uint32, 1 row Grid mode writes 0; hexagon mode writes 1 if an in-bounds point missed the lattice.

The walkthrough requests count values only. Other statistics, weights, smoothing, extent, histogram and texture outputs are described in the density reference.

Read GPU Spatial Analysis concepts for the ontology, shared ports, conventions, coordinate precision and the compile, encode and submit pattern. The operator pages group the contributors by task; the operators index lists them all.
