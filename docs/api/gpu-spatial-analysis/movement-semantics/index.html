Movement semantics

Staypoints, locations, triplegs and trips, mobility indicators on staypoints, and trajectory cleaning. Everything here reads the shared GPUTrajectoryGeometryPort layout: positions (float32x2), trackOffsets and timestamps (float32 relative or uint32x2 Int64 words, with an optional temporalContext). Durations and the shared gap rule, maximumGap, are in the timestamps' unit: a step is a gap only if it is strictly longer than the limit, and 0 or absent means no limit.

The families follow, in order, trackintel (MIT), scikit-mobility 1.3.1 (BSD) and MovingPandas 0.23 (BSD-3); fixtures from those packages check them. Parameters are per-frame packed float32 buffers unless a section says otherwise.

Out of scope (as the 2026-11 spatiotemporal review concluded): exact flocks and convoys, TRACLUS, T-LoCoH, and continuous-time movement model fitting (CTMM, OU/OUF).

Staypoints, locations and triplegs

The contributors compose, each reading the columns the previous one writes:

parameterBuffer.write(
  getGPUTrajectoryStaypointsParameterValues({
    distanceThreshold: 100,
    timeThreshold: 300_000,
    maximumGap: 900_000
  })
);
graph.add(
  new GPUTrajectoryStaypoints({
    spatialContext: {coordinateSpace: 'longitude-latitude', metric: 'great-circle'},
    positions,
    timestamps,
    trackOffsets,
    parameters: parameterBuffer.importToGraph(graph),
    output: {ids, status: {count, overflow}, startRows, finishRows, centroids, durations, staypointIds}
  })
);

GPUTrajectoryStaypoints

Detects staypoints with trackintel's sliding rule (Li et al. 2008) in a bounded number of passes: every row searches forward independently for its first break (a gap, or a fix at or beyond distanceThreshold), at most maximumSearchRows rows ahead; pointer doubling in ceil(log2(rowCount)) fixed passes then keeps the rows reachable from each track's first row. That reproduces the sequential chain exactly as long as no search hits the cap; status.candidateOverflow reports when one did.

output.status.overflow reports final staypoint-table capacity only. A capped search can set candidateOverflow while all retained staypoints fit and final overflow stays zero. Both words are rewritten each submission, so a frame whose searches fit the bound clears candidate loss.

Compact candidate-status words on trajectory metrics stops and trajectory segments are outputs, too. They must be separate from input trackOffsets and the other output words; publication must never alter the trajectory used by the next submission.

Unlike a per-step speed test, one parked stop stays one stop under GPS jitter: the window restarts only when a fix leaves distanceThreshold of its anchor. The cost is N * min(maximumSearchRows, L) distance tests for stays of L rows, so 1 Hz data parked for a long time needs a cap of at least that many rows, or thinning first.

Prop Meaning
parameters Packed getGPUTrajectoryStaypointsParameterValues: distance, time, gap, include-last
maximumSearchRows Forward search cap per row, compile-time, default 4096
output.ids Track of each staypoint, ordered by track then time
output.startRows, output.endRows, output.finishRows First row, exclusive end row and the row whose time is finished_at
output.centroids Mean of the staypoint's distinct coordinates (trackintel union_all)
output.durations finished_at - started_at
output.staypointIds Per-row staypoint_id, 0xffffffff outside staypoints

GPUTrajectoryLocations

Staypoint locations per track with trackintel's generate_locations (dbscan, num_samples=1, agg_level='user'): the connected components of staypoints of one track within epsilon (inclusive), labelled by bounded min-label hooking with path compression (maximumIterations rounds, status.converged). Locations are numbered by first visit within a track, tracks in order. Dataset-level locations and num_samples > 1 are GPUSpatialClustering jobs; the convex-hull extent is not produced.

GPUTrajectorySegments

Triplegs (between_staypoints) and trips (generate_trips) from the per-row staypoint IDs and the staypoint table. A tripleg is a maximal run of rows outside every staypoint, broken at a gap, with at least two rows that are not all the same coordinate. A trip aggregates triplegs and non-activity staypoints between activities (staypoints strictly longer than activityMinimumDuration), breaks at a gap between events, and starts at the last activity of an activity run. Origin and destination staypoints are the activities directly around a trip, unknown across a gap or at a track end, as origin_staypoint_id and destination_staypoint_id are in trackintel. triplegTripIds is the trip_id of each tripleg. The overlap_staypoints method is not implemented.

Supply available staypoint status.overflow and status.candidateOverflow beside status.count. Their loss is propagated into triplegs.status.candidateOverflow and trips.status.candidateOverflow. Trips consume only the stored tripleg prefix, so tripleg capacity loss also sets trip candidate overflow. Each table's status.overflow still means only that table's final output capacity was exceeded. A trip count/required count derived from an incomplete input describes the partial result; the candidate flag must be checked before treating it as a complete trip table. Trip construction requires a caller-visible trips.status.candidateOverflow destination. Supplying either staypoint loss input also requires triplegs.status.candidateOverflow. Both operation forms and the direct contributor reject omitted destinations at construction; private scratch never substitutes for a public loss diagnostic.

Pass both tripleg overflow and candidateOverflow to modal split and tracking quality. If either supplied flag is nonzero, modal split suppresses every aggregate to NaN and every predicted mode to 0xffffffff; tracking quality suppresses every track's value to NaN. The flags describe whole-table loss, so these consumers cannot identify unaffected tracks. Omitting both flags asserts that the input table is complete. Complete empty tracks still produce zero. Website views hide incomplete modal bars/classes and label tracking quality unavailable; Kepler exports unavailable numeric values as null. Never interpret NaN or the missing-mode sentinel as a count or a speed class.

The thinning and staypoint CPU twins honor an explicit maximumSearchRows, including the GPU's anchor jumps/window splits and candidate-overflow flag. Omitted CPU search budgets remain uncapped. Thinning count and candidate-overflow words have separate writers, so adjacent non-overlapping scalar subviews of one status allocation are supported.

Mobility indicators

GPUMobilityIndicators

Per-track indicators on the staypoint table (and, for tracking quality, the tripleg table), following scikit-mobility 1.3.1 individual measures and trackintel:

Output Definition
radiusOfGyration RMS haversine distance of the staypoints from their arithmetic mean position
jumpLengths Distance between consecutive staypoints (0 for a track's first)
waitingTimes Difference between consecutive staypoint start times
randomEntropy log2(distinct locations)
uncorrelatedEntropy Shannon entropy in bits of location shares
realEntropy Lempel-Ziv estimator of the location sequence, n * log2(n) / sum(lambda) as in scikit-mobility
homeLocations, workLocations Locations with the longest and second longest summed duration (trackintel FREQ, no pre-filter)
trackingQuality Sum of positive durations over staypoints and triplegs, divided by the extent from first start to last finish (trackintel temporal_tracking_quality, granularity all)

Location statistics are O(m^2) per track and real entropy O(m^3) in the worst case for m staypoints; maximumEntropySequenceRows bounds the last and reports status.candidateOverflow. Pass available staypoint status.overflow and status.candidateOverflow alongside status.count, including when the table comes directly from GPUTrajectoryStaypoints. Either nonzero input suppresses every numeric indicator to NaN and both location outputs to 0xffffffff, across all tracks and all capacity rows. The optional output status.candidateOverflow is the OR of supplied staypoint loss and entropy sequence loss; it resets on each frame, including when real entropy is not requested. Suppression remains observable when that optional status destination is omitted. The CPU function takes the same loss arrays beside staypoints.count. Omitting both loss inputs asserts completeness. Website views hide these indicators and label them unavailable for incomplete staypoints; Kepler exports missing numeric and location values as null.

{/* lens:GPUMobilityIndicators */}

GPUModalSplit

Per-(track, mode) accumulation of tripleg count, distance or duration (trackintel calculate_modal_split). Modes come from modes, or are predicted from average tripleg speed when modeSpeedBreaks is given (trackintel simple-coarse, left-closed classes, for example [15 / 3.6, 100 / 3.6, Infinity] in metres per second). The last class has no upper bound, so a speed at or above a finite last break stays in the last class. A tripleg with no speed (no time between its first and last row, or a non-finite length) gets the missing key 0xffffffff in output.predictedModes and is left out of the split; the same key in a caller's modes is left out too.

{/* lens:GPUModalSplit */}

Cleaning

GPUTrajectoryOutlierFlags

Point-centred speed and acceleration flags. The speed bit flags a fix when both adjacent steps fail, so the valid fix after a spike is not. The acceleration bit flags a fix when the step speed rises by more than the limit into it and falls by more than the limit after the step out of it (the two accelerations on either side of the two fast steps; the one between them is near zero), so a sustained jump flags no row. At a track end the missing side is waived. A single pass; two consecutive displaced fixes are not caught (the step between them is slow), unlike movingpandas.OutlierCleaner, which compares each fix to the last kept one. addTrackQualityRecipe applies the same rule with speedOutlierMode: 'point-centred'; its default remains 'step'.

GPUTrajectoryHampel

Hampel filter per track (the hampel package used by PTRAIL): a value is an outlier when |value - median| > numberOfSigmas * 1.4826 * MAD over a window centred on it; outliers become the window median, and rows within half a window of a track end pass through unchanged. Compile-time windowSize, at most 129.

GPUTrajectorySplit

Splits tracks and rewrites offsets: 'gap' (MovingPandas ObservationGapSplitter), 'stop' (maximal runs of rows outside every staypoint, the trackintel tripleg rule: the rows of a staypoint are in no segment, unlike the MovingPandas StopSplitter, which keeps the boundary fixes of each stop), and 'value-change' (MovingPandas ValueChangeSplitter, where each segment but the last repeats the first row of the next segment, so rowIds can reference a row twice). Segments need at least two rows. The output is segmentOffsets, segmentTracks and rowIds with optional copied positions and timestamps, so a split feeds the next contributor without readback.

GPUTrajectoryThinning

Minimum-distance and minimum-time generalization (MinDistanceGeneralizer, MinTimeDeltaGeneralizer): the first and last row of a track are kept, and each kept row is followed by the first later row at or beyond the tolerance. As with staypoints, the sequential rule is a bounded forward search (maximumSearchRows, status.candidateOverflow) plus pointer doubling.

GPUTrajectoryTrackRelativeTimes

Int64 word timestamps to float32 ticks after each track's first row, exact while the track spans fewer than 2^24 ticks. Use its output as the float32 time column of the time-aware simplification (GPULineSimplification, metric: 'time-ratio') to run TD-TR on word timestamps, and of any other float32 trajectory path.
