Density & interpolation

GPUPointDensity

Chunked positions and weights use fixed tile scratch for packed hexagon/masked routes, controlled by scratchTileSize. Shared grid outputs remain packed; fixed-point scale and counts span all chunks.

Bins points into grid or hexagon cells and writes a per-cell count, sum or mean raster.

::lens{scenario=gpu-spatial-analysis.point-density rung=result caption="2,344 observations (grey) binned into 125 m cells (blue); counts per cell, not per km²."}

Bins points into a square grid (GPUGridBinning, GPUGridAggregation) or pointy-top hexagons (keys kernel plus GPUGroupAggregation) and writes per-cell counts, sums, means, a heatmap field, its [min, max] extent, a histogram, and an optional r32float texture. Bounds and hexagon radius may be GPU views; the field can be smoothed with a per-frame GPUConvolution kernel. Instead of a full kernel, pass a separable separableKernel: {horizontal, vertical} (one of the two is required), which smooths in two 1D passes.

This is binned counting, not a kernel density estimate. output.values is the count (or weight sum or mean) per cell, so it changes with gridSize and is not an intensity per unit area or a probability density. Optional smoothing convolves that field with a kernel whose radius and sigma are in cells, not ground units, using a zero boundary: kernel mass leaks out of the domain, so the field is underestimated within about two sigma of the border, and a grid whose cells are not square on the ground smooths anisotropically. For intensity per unit area, a bandwidth in ground units, a choice of kernels, and edge correction use GPUKernelDensity. spatialContext is planar/native only (omitted means planar/native); longitude/latitude throws, so project first. It measures area, so local-azimuthal-equidistant frames throw.

Weighted sums default to sumAccumulation: 'auto', which always selects the deterministic 'workgroup' path, because reproducible sums are the contract. 'atomic' (direct float compare-exchange atomics, no key pass) is an explicit opt-in for known diffuse input and is not deterministic: its last float bits depend on the atomic interleaving. Each 256-row workgroup pre-aggregates in shared memory before writing to the grid, so a hotspot no longer serializes on one cell (90% of 1M points in one cell drops from seconds to about 4 ms, at about 2 ms extra on uniform data). 'workgroup' sums are fixed point: each weight is quantized to one power-of-two unit derived from the largest weight and the row count, then added as an exact 96-bit integer, so the sums are bitwise identical across runs, row orders and chunkings and are the f32 nearest to the exact sum of the quantized weights. Weights smaller than about 2^(h - 71) times the largest (h is the bit length of the row count, so about 1e-15 at a million rows) round to the unit. 'atomic' sums can differ from a CPU sum, and between runs, in the last bits.

graph.add(new GPUPointDensity({
  positions, weights, bounds: viewport.importToGraph(graph), gridSize: [256, 256],
  statistic: 'mean',
  smoothing: {kernel: kernel.importToGraph(graph), kernelWidth: 5, kernelHeight: 5},
  output: {values, extent, histogram, texture}
}));

mask is an optional per-row uint32 view with the same length as positions. Rows whose mask is 0 are excluded from count, sum, mean, smoothing input, extent and histogram; any nonzero value includes the row, like the mask inputs of GPURegionStatistics and GPUFlowAggregation. Contents are per-frame and rewriting them never recompiles. Hexagon binning reads the mask in its keys kernel; grid binning adds one pass that writes masked positions as NaN into a transient copy. Without mask the graph is unchanged. Pass a residency arena liveMask, or GPUTimeWindowFilter.outputMask, to get time- or tile-gated density without poisoning position columns.

getGPUPointDensityHexagonGridSize sizes a hexagon lattice that covers given bounds, and GPU_POINT_DENSITY_HEXAGON_WGSL lets render shaders place hexagon bins.

GPUStudyWindowPreparation

Prepares a polygon study window once: oriented edges, bounds, area, perimeter and sampling cells for window-aware statistics.

::lens{scenario=gpu-spatial-analysis.study-window-preparation rung=result caption="13 community areas prepared as one study window (blue outline) in an equal-area frame."}

Prepares one valid polygon or multipolygon, including holes and disconnected islands, as a reusable studyWindow handle for point-pattern statistics and kernel-density edge correction. Add the preparation to the graph before adding its consumers. One handle belongs to one graph; declaring it a second time throws, including in the same graph. isDeclaredIn(graph) reports its declaration.

The first submitted encoding captures a persistent geometry snapshot. invalidate() or a true CPU rebuildWhen(parameters) requests a new generation. Its applied generation is committed only after the complete preparation executes, so discarded encodings and abandoned prefixes retry automatically. Published preparation stages replay against that snapshot every encoding; geometry refresh alone is GPU-gated. This repeats preparation work and adds one copy of each geometry view plus 24 generation-control bytes, with the same view lengths and storage binding limits. Changed geometry needs invalidation, otherwise consumers deliberately reuse the previous geometry. Consumers evaluate their current inputs on every encoding. Changing view lengths requires a new handle and graph. destroy() frees the handle's buffers and allows re-adding it; destroy compiled graphs using it first. getViews(graph) throws until this handle has been declared in that graph.

The first encoding and first encoding after explicit invalidation bypass rebuildWhen; other encodings call it once. encodedBuildCount counts CPU refresh-request encodings, including discarded requests; automatic GPU retries and replayed builds do not increment it.

The props and handle accept a frame type parameter, for example GPUStudyWindowPreparation<{geometryChanged: boolean}>; use that type on GPUCommandGraph too. The default is unknown; invalidate() alone also works with a void graph. See the execution guide for a typed rebuildWhen example. No additional invalidation is needed after discarding an encoding. Use one active resumable execution per handle/graph.

const studyWindow = new GPUStudyWindowPreparation({
  positions: windowPositions,
  featureOffsets: windowFeatureOffsets, // exactly two entries: one feature
  polygonOffsets: windowPolygonOffsets,
  ringOffsets: windowRingOffsets,
  spatialContext,
  samplingGrid: [256, 256],
  output: {summary: windowSummary} // optional caller-owned float32[8] readback copy
});
graph.add(studyWindow);
// Pass studyWindow to consumers added after this preparation.

The geometry uses the GeoArrow polygon layout: the first ring of each polygon is its shell, regardless of winding. Only planar frames are supported. Project longitude/latitude positions first with GPULocalFrame.projectArray, using the same frame as the observations. The polygon must be valid; consider GPUGeometryValidity. Self-intersections or overlapping polygons invalidate the fan identity used by consumers.

GPURectangleClip polygon output can feed the preparation directly, including empty polygon and ring slots. A ring with fewer than three vertices, or exactly zero orientation for every triangle (first, vertex, next) in its fan, is degenerate. Such rings contribute no area, perimeter, edge count, bounding box or uncertainty flag; their oriented edges are NaN. The constructor still needs at least three vertex rows and one ring slot. An all-degenerate window is legal and produces EMPTY at encode time. The raster sampler reads raw positions, so degenerate rings can only add boundary flags (extra exact inclusion tests), never change coverage.

The GPU copies oriented edges with the interior on their left and computes the eight-float GPU_STUDY_WINDOW_SUMMARY row: [minX, minY, maxX, maxY, area, perimeter, edgeCount, flags]. Area subtracts holes; perimeter includes them. Flag 1 (GPU_STUDY_WINDOW_FLAG_ORIENTATION_UNCERTAIN) indicates a ring area within a conservative f32 rounding bound of zero, or non-finite orientation; flag 2 (GPU_STUDY_WINDOW_FLAG_EMPTY) indicates non-finite or non-positive total area. Ring areas use a fixed pairwise reduction of determinants relative to the first vertex. The orientation bound is 8 * epsilon_f32 * (1 + ceil(log2(vertexCount))) * sum(abs(products)) on doubled area.

samplingGrid is compile-time, defaults to [256, 256], and must contain positive integers with a product no larger than 1048576. The sampler compacts inside or boundary cells in row-major order; bit 31 marks a boundary cell that needs an inclusion test. crossingCapacity is forwarded to GPUPolygonRasterization and defaults to 4 * samplingGrid[1] * ringCount; size it for polygons with many crossings per row. On crossing overflow, a slower exact GPU center test preserves sampler coverage. slabEntryCapacity controls the optional edge index, whose overflow falls back to walking edges. getViews(graph) exposes the edge, summary, slab and sampler views; its packed view is internal to consumers.

All preparation runs on the GPU. Each rebuild's fixed ring tree costs O(V log V); sampler cost also depends on the grid and crossing capacity.

GPUKernelDensity

Explicit method binned accepts aligned chunked positions and weights. Corrected-weight scalar scratch splits when a global binding cannot fit; split totals use fixed-point accumulation. Exact and auto retain packed indexed inputs, and shared grid outputs must fit.

Estimates event intensity on a raster from points with a planar kernel, a ground-unit bandwidth and edge correction.

::lens{scenario=gpu-spatial-analysis.kernel-density rung=result caption="2,344 iNaturalist observations (grey) and their 400 m gaussian density on 125 m cells."}

Maximum: indexGridSize has at most getGPUGridIndexMaximumCellCount(device) (2^25 - 1 on a default device: cells + 1 uint32 cell offsets in one 128 MiB binding) cells.

A true planar kernel density estimate on a raster, with the bandwidth in ground units. For each output cell center u it evaluates lambda(u) = sum_i w_i K_h(|u - x_i|) over the points inside the kernel support, where K_h(d) = K(d / h) / h^2 is radially symmetric and integrates to one over the plane (Silverman 1986, Density Estimation, Table 3.1):

kernel K_h(d) for t = d^2 / h^2 Support
'gaussian' (default) exp(-t / 2) / (2 pi h^2) truncated at 5h; lost mass exp(-12.5), 3.7e-6
'quartic' (biweight), alias 'bisquare' 3 / pi (1 - t)^2 / h^2 t < 1
'epanechnikov' 2 / pi (1 - t) / h^2 t < 1

'bisquare' is the name GPUNeighborSearch and GPUSpatialWeightsTransform use for the same shape (their weights are normalised in one dimension, 15/16 (1 - z^2)^2, where the density kernel is normalised over the plane). KDE accepts either name for kernel; both run the same kernel and kernel reads back as 'quartic'.

const kdeParameters = new GPUParameterBuffer(device, {id: 'kde', format: 'float32', length: 9});
graph.add(
  new GPUKernelDensity({
    positions, // float32x2, planar frame with equal units on both axes
    weights, // optional float32 (populations, counts); NaN or negative excludes the point
    parameters: kdeParameters.importToGraph(graph),
    grid, // axis-aligned GPURasterMetadata; its width and height size the raster
    indexGridSize: [64, 64], // internal GPUGridIndex over the points
    indexBounds: [minX, minY, maxX, maxY], // must cover the points that should count
    kernel: 'quartic',
    edgeCorrection: 'uniform', // default
    normalization: 'intensity', // default
    // bandwidthRule: 'scott', // optional: bandwidth computed on the GPU, output.bandwidth reads it
    output: {values, weightSum, status: {invalidCount}} // weightSum and status are optional
  })
);
kdeParameters.write(
  getGPUKernelDensityParameterValues({bandwidth: 250 /* meters */}, grid) // no recompile
);
  • Grid. grid is a GPURasterMetadata: its width and height size the kernels (compile-time) and the packer reads the placement from the same object, so pass the frame's grid to getGPUKernelDensityParameterValues(settings, grid). It must be axis-aligned (a rotated or sheared grid throws). Output rows follow the grid's row order: row 0 is the grid's first row, the top row of a north-up grid (makeGPURasterMetadata default, affine[4] < 0) and minY when rows advance north (rowDirection: 'north'). Cell (x, y) is evaluated at its center, from the outer corner of cell (0, 0), half a cell in with pixelInterpretation: 'point'.
  • Units. normalization: 'intensity' (default) is the sum of weights per unit area, position units to the power -2: points per square meter in a meter frame, so the value does not change with the raster resolution. Multiply by a cell area to get expected weight per cell. 'probability' divides by the sum of included weights (output.weightSum), giving a probability density that integrates to about one over the window (exactly one only without edge correction and with the whole kernel inside the window). Cells are evaluated at their centers, not averaged over the cell.
  • Edge correction repairs the downward bias within one bandwidth of the study window, where kernel mass falls outside the data region. 'uniform' (default) divides each cell by e(u), the kernel mass inside the window (Diggle 1985; spatstat density.ppp(edge = TRUE)). 'diggle' instead weights each point by 1 / e(x_i) (Jones 1993; spatstat diggle = TRUE), which keeps the total closer to the point count but is noisier at the edge. 'none' is the plain sum. The window is window in getGPUKernelDensityParameterValues and defaults to the rectangle of the grid; with correction, points outside the window are excluded and cells whose centers are outside are NaN. e(u) is closed form, with no quadrature: normal-CDF differences for the gaussian, and an exact inclusion-exclusion of four disk-clipped quadrant integrals for quartic and epanechnikov. getGPUKernelDensityWindowMass is the float64 rectangle reference. For a polygon, pass a GPUStudyWindowPreparation as the compile-time studyWindow prop (default 'rectangle') and add it to the graph before the KDE. Set window: 'study-window' in the parameter packer; slots 5–8 become NaN and polygon kernels read the prepared window instead. A rectangle-mode operator given this sentinel with edge correction produces NaN cells. Polygon windows work with 'exact', 'binned' and 'auto'. Outside points are excluded and cells with centers outside W are NaN. Polygon e(u) uses oriented fan decomposition, with analytic compact-kernel integrals and Gaussian quadrature (2e-5 relative accuracy); only edges within the kernel support contribute corrections. Uniform correction divides by e(u); Diggle correction uses w_i / e(x_i). Both retain the rectangle small-mass guard (mass > 1e-6). The window must be valid (consider GPUGeometryValidity) and in the same planar frame as the KDE. Window queries use absolute frame coordinates, without subtracting gridStart. Polygon plus edgeCorrection: 'none' throws ${id} studyWindow is ignored without edge correction; set edgeCorrection to 'uniform' or 'diggle'.
  • Bandwidth. It is per-frame, in position units, and should reflect the question (a service distance, a neighborhood). Pass bandwidthRule: 'scott' or 'silverman' to have the GPU compute a normal-reference bandwidth from the points every encoding, with no read-back: h = n_eff^(-1/6) sqrt((variance x + variance y) / 2), the pooled isotropic bandwidth of scipy.stats.gaussian_kde with the unbiased weighted covariance (numpy.cov(aweights = w)) and n_eff = (sum w)^2 / sum w^2. In two dimensions the two rules coincide (the IQR-based 1D Silverman rule is not used). Rows with a non-finite position or a non-finite or negative weight are skipped; indexBounds and the window are not applied. The moments are a two-stage hierarchical reduction (workgroup partials, then further levels) in two passes (mean, then centered sums) relative to the grid's start corner, so large projected coordinates do not cancel. parameters slot 4 is then ignored, and output.bandwidth (optional, one float32 row) receives the value the kernels use (NaN, and an all-NaN raster, when undefined: fewer than two rows, n_eff <= 1, or zero spread). A normal-reference rule oversmooths clustered data; likelihood cross-validation and Diggle's selector are not provided.
  • Exclusions. A non-finite position or weight, a negative weight, and a position outside indexBounds exclude the row; output.status.invalidCount is their number. Zero-weight rows are included.
  • Determinism and precision. The index is rebuilt every encoding, IDs are put back in ascending row order inside each index cell by a stable sort of the rows by cell (linear in the row count, however many rows share a cell), and each cell sums in a fixed order (index row, column, ascending row), with no float atomics. Distances use offsets from the grid's start corner to limit f32 cancellation; the f32 inputs themselves are not recentered, so use local coordinates for fine resolution far from the origin.
  • Large bandwidths (method). The default 'exact' gather costs (5h / cell)^2 cells per point and explodes when the bandwidth spans many cells. method: 'binned' (gaussian only; other kernels throw) splits each included weight over the four nearest cell centers (linear, cloud-in-cell binning, Wand 1994) with the shared deterministic fixed-point accumulator, then blurs the bins along x and y with three running-sum box blurs and one two-sided exponential pass per axis, variance-matched to (h / cell)^2 (Wells 1986; Kovesi 2010; the exponential cancels the boxes' fourth cumulant). The cost is a few passes over the grid whatever the bandwidth; every bandwidth-dependent filter parameter is computed on the GPU, so changing h never recompiles. Edge correction, normalization and NaN rules are the same as 'exact'. method: 'auto' builds both and the GPU picks one every encoding: exact while 5h is at most 32 cells, binned above. Error versus 'exact', for h >= 3 cells, in units of W / (2 pi h^2) (W the included weight, the height of one point's kernel): at most r^2 / 4 + 0.016 + 1.4e-5 + 6e-8 (13 / r + 210) with r = cell / h (getGPUKernelDensityBinnedErrorBound): r^2 / 4 from the linear binning, 0.016 from the filter shape, the rest from truncation and float32. For example 1.9% at h = 10 cells and 1.6% at h = 64; smooth fields err far less than one point. The blur drops the mass that leaves its array, so it needs a margin of 2.5h around the cells you read: binnedPadding (default: the larger grid side, so h up to 40% of it) adds that margin and also extends the region whose points are counted. output.status.insufficientPadding flags a 'binned' run that lacked it; 'auto' falls back to the exact gather instead. The array costs (width + 2 binnedPadding + 2) * (height + 2 binnedPadding + 2) cells of 20 bytes.
  • Pinned to sklearn.neighbors.KernelDensity (gaussian, epanechnikov), numpy (quartic), and scipy.integrate.dblquad (window mass, edge-corrected fields); bandwidth rules to scipy.stats.gaussian_kde.
  • spatialContext is planar/native only (omitted means planar/native). It measures area, so local-azimuthal-equidistant frames throw.

Not provided: adaptive or space-time bandwidths, network KDE (see the network contributors), reflection boundaries.

GPUInverseDistanceWeighting

Interpolates sample values onto a raster as inverse-distance-weighted means of the nearest samples.

::lens{scenario=gpu-spatial-analysis.inverse-distance-weighting rung=result caption="Helene rain gauges (grey) to a rainfall surface: power 2, up to eight gauges within 150 km."}

Maximum: indexGridSize has at most getGPUGridIndexMaximumCellCount(device) (2^25 - 1 on a default device: cells + 1 uint32 cell offsets in one 128 MiB binding) cells.

Interpolates scattered samples onto a raster with inverse distance weighting (w = 1 / d^p), the GPU counterpart of turf interpolate, GDAL invdist, and GRASS v.surf.idw. The output placement (the grid passed to the packer), search radius, power, nearest-neighbor limit, and minimum neighbor count are per-frame; the grid's size is compile-time.

graph.add(
  new GPUInverseDistanceWeighting({
    positions, // float32x2 per sample
    values, // float32 per sample, NaN skips
    mask, // optional uint32, 0 skips
    parameters: idwParameters.importToGraph(graph), // 9 float32
    grid, // axis-aligned GPURasterMetadata; its width and height size the raster
    indexGridSize: [128, 128], // internal GPUGridIndex over the samples
    indexBounds: [minX, minY, maxX, maxY], // samples outside are ignored
    maximumNeighborCount: 16, // compile-time capacity for k; 0 compiles radius-only
    output: {values: surface, counts} // float32 (NaN = nodata), optional uint32
  })
);
idwParameters.write(
  getGPUInverseDistanceWeightingParameterValues(
    {
      searchRadius: 250,
      power: 2,
      taper: 'none', // or 'modified-shepard' (Franke-Nielson, needs a finite radius)
      neighborCount: 8, // 0 = every sample within the radius
      minimumNeighborCount: 3
    },
    grid // the frame's placement: pan or zoom by passing a different grid of the same size
  )
); // no recompile
  • Gather form: one invocation per output cell samples the cell center gridStart + (x + 0.5, y + 0.5) * cellSize and visits the grid-index rows that overlap the search square. No atomics touch values. grid must be axis-aligned (the packer and constructor throw otherwise); gridStart is the outer corner of cell (0, 0) and cellSize is signed, so output rows follow the grid's row order: row 0 is the top row of a north-up grid (affine[4] < 0) and minY when rows advance north.
  • Samples with d^2 <= radius^2 contribute. With neighborCount = k > 0 the k nearest are kept by (d^2, row), so equal distances keep the smallest row. k is clamped to maximumNeighborCount (at most 64).
  • An exact hit (d == 0) returns that sample's value, the smallest row among several, regardless of minimumNeighborCount. Otherwise a cell with fewer than max(minimumNeighborCount, 1) contributors is nodata (NaN). counts holds the contributors after the k limit.
  • Negative or NaN radius, or a negative or non-finite power, produces an all-NaN raster. searchRadius: Infinity searches the whole index domain.
  • Units and coordinates: by default positions, grid and radius share one planar unit and distances are differences of offsets from the grid's start corner, so large absolute coordinates (UTM northings) do not quantize them. With spatialContext: {coordinateSpace: 'longitude-latitude', metric: 'great-circle'} positions are absolute lon/lat degrees, the index and output grid stay in degrees, and distances and searchRadius use the context's length unit (meters by default; kilometers with units: 'kilometers'), on a sphere of sphereRadius or the mean Earth radius in that unit. Neighbors and radius tests order by the haversine term. The query box is conservative (longitude span widened by the cosine of the highest latitude reached, full span near the poles) but does not wrap the antimeridian, and the nearest-k limit scans the whole box instead of early-stopping. Pass optional spatialContext to getGPUInverseDistanceWeightingParameterValues(settings, grid) to warn on short searchRadius values; see Precision of longitude/latitude positions. Other longitude/latitude metrics (rhumb, ellipsoidal, none) throw; project to a planar frame (for example createGPULocalFrame) for them. It measures distance, so local-lambert-equal-area frames throw.
  • taper: 'none' (default) is w = 1 / d^p inside the radius, a hard cutoff: a sample entering or leaving the radius changes the surface discontinuously. taper: 'modified-shepard' is the Franke and Nielson (1980) weight w = ((R - d)+ / (R d))^p with R = searchRadius, which falls to zero at the radius (a sample exactly at R has weight zero). It needs a finite radius (getGPUInverseDistanceWeightingParameterValues throws otherwise). counts still counts every sample inside the radius. Default stays 'none' for backward compatibility; prefer the taper when a finite radius is a modelling choice rather than just a speed limit.
  • Parameter guidance: power 2 is conventional, not optimal; higher powers flatten the surface around samples. minimumNeighborCount defaults to 1, so a lone distant sample inside the radius paints a constant plateau of its value; use 3 or more to leave sparse cells as nodata. IDW has no direction or sector search and no leave-one-out output; use GPUKriging's cross-validation to compare models on the same samples.
  • Determinism: the grid index's in-cell order depends on atomics, so the contributor re-sorts IDs inside each index cell every encoding; sums then run in a fixed order (index row, column, ascending row; or (d^2, row) with k). Weights are accumulated in log space against a running maximum, so tiny distances with large powers do not overflow f32.
  • The index is rebuilt every encoding, so positions and values may change per frame. Keep a few samples per index cell: the in-cell sort is quadratic in cell population.
  • output.values is a row-major float32 raster that GPUTerrainContours accepts directly as elevation: {id, format: 'float32', storage: {kind: 'buffer', values: surface}}; NaN cells clear their marching-squares cells.

GPUKriging

Predicts values and kriging variance on a raster by solving an ordinary kriging system per cell from nearby samples.

::lens{scenario=gpu-spatial-analysis.kriging rung=result caption="Helene rain gauges to rainfall: spherical variogram, 150 km range; nearer gauges get larger weights."}

Maximum: indexGridSize has at most getGPUGridIndexMaximumCellCount(device) (2^25 - 1 on a default device: cells + 1 uint32 cell offsets in one 128 MiB binding) cells.

Local ordinary kriging on a raster (PyKrige OrdinaryKriging with n_closest_points, GSTAT, ArcGIS Kriging). For every output cell the k <= 16 nearest samples within the radius form a (k + 1) x (k + 1) system under a fitted variogram, solved per invocation by pivoted Gaussian elimination in f32 (the variogram is normalized by its total sill and the prediction is relative to the nearest value). The samples come from the same internal GPUGridIndex as GPUInverseDistanceWeighting.

graph.add(
  new GPUKriging({
    positions, values, parameters: krigingParameters.importToGraph(graph),
    grid, // axis-aligned GPURasterMetadata; its width and height size the raster
    indexGridSize, indexBounds, maximumNeighborCount: 16,
    output: {
      values: surface, variance, // float32 rasters
      crossValidationPrediction, crossValidationVariance, // optional float32 per SAMPLE row
      status: {invalidCount, uncertainCount} // optional uint32 scalars
    }
  })
);
  • Props: positions, values (NaN skips), optional mask, parameters (getGPUKrigingParameterValues, at least 12 float32), grid, indexGridSize, indexBounds, maximumNeighborCount (1 to 16, compile-time) and output: {values, variance?}.
  • Per frame: radius, k, minimum neighbors, the placement (the grid passed to getGPUKrigingParameterValues(settings, grid), axis-aligned, same width and height as the props; output rows follow its row order, row 0 at the top of a north-up grid and at minY when rows advance north), model ('spherical', 'exponential' or 'gaussian', the fitVariogramModel convention) and nugget, sill and range. range is the effective range: the exponential model is 1 - exp(-3 h / range) and the Gaussian model 1 - exp(-3 (h / range)^2), both at 95 percent of the sill at range. Converting to another library:
    • PyKrige: pass sill + nugget as its "sill" (PyKrige's value is the total sill). Its exponential and spherical models take the same range. Its built-in Gaussian model is 1 - exp(-(h / (range * 4 / 7))^2), exponent 3.0625 instead of 3, so pass range * 7 / (4 * sqrt(3)) (about 1.0104 * range) to get the same surface.
    • gstat vgm: the range parameter is range / 3 for "Exp", range / sqrt(3) for "Gau" and range for "Sph".
  • values is a row-major raster and nodata is NaN: too few distinct neighbors, an ill-conditioned system, or an unreliable variance. variance is the kriging variance in squared value units, 0 at exact hits, NaN at nodata.
  • Units and coordinates: by default positions, grid, radius and variogram range share one planar unit; distances are differences of offsets from the grid's start corner (cross-validation: from the index domain minimum), so UTM-sized coordinates keep full f32 precision relative to the neighborhood. With spatialContext: {coordinateSpace: 'longitude-latitude', metric: 'great-circle'} positions are absolute lon/lat degrees, the index and grid stay in degrees, and the search radius, variogram range and all sample-sample and sample-cell distances are haversine meters (sphereRadius, else 6371008.8 m; kilometers with units: 'kilometers'). Neighbors are ordered by (haversine term, row); exact hits and duplicate coalescing compare degree positions exactly; leave-one-out uses the same metric. The query box is conservative and does not wrap the antimeridian, and the ring scan's early stop is disabled (the whole box is scanned, so an unbounded radius is O(samples) per cell). Pass optional spatialContext to getGPUKrigingParameterValues(settings, grid) to warn on short searchRadius and range values; see Precision of longitude/latitude positions. Other longitude/latitude metrics throw. It measures distance, so local-lambert-equal-area frames throw.
  • Status: invalidCount counts cells that are NaN for lack of data or invalid settings (fewer than minimumNeighborCount distinct positions, no sample in the radius, outside the index domain). uncertainCount counts cells rejected by the numerical checks below. Both are computed over the raster of the last encoding, so a nonzero uncertainCount means the surface has holes that are not "no data" but "do not trust the solve here".
  • Singularity is a relative test, not an absolute one: a pivot at or below KRIGING_RELATIVE_PIVOT_TOLERANCE (1e-6) of the system scale is zero, and a system whose smallest pivot is below KRIGING_PIVOT_RATIO_TOLERANCE (1e-4) of its largest is rejected as ill conditioned (the same limit GPULocalKriging and GPULocalRBF apply), since an f32 solve loses about cond * 6e-8 of the weights' accuracy and the ratio tracks 1 / cond. The usual cause is a Gaussian model with a near-zero nugget and closely spaced samples: add a nugget (0.001 of the sill moves the ratio from 1e-6 to 5e-5 for 12 clustered samples) or thin the samples. The constants were calibrated against emulated f32 solves compared with float64.
  • Variance is mu + sum(w * gamma) in units of the total sill and is never negative for a valid model. A negative value above -KRIGING_NEGATIVE_VARIANCE_TOLERANCE (1e-4) is f32 rounding and is clamped to zero; a larger negative variance makes the cell NaN (value and variance) and counts it in uncertainCount. It is never silently clamped.
  • Duplicate sample positions inside a neighborhood are coalesced into one kriging point whose value is the mean of their values (summed in (d^2, row) order, so the result is deterministic), instead of making the system singular. Duplicates still occupy neighbor slots, so a neighborhood of k rows can hold fewer than k points, and minimumNeighborCount counts distinct positions. An exact hit returns the mean of the samples at that position with variance 0.
  • The nugget is treated as micro-scale variation: the predictor is exact at the data even with a positive nugget (zero variance at exact hits). Filtered kriging with a measurement-error nugget is not provided.
  • Leave-one-out cross-validation (crossValidationPrediction, optional crossValidationVariance, one float32 row per sample) krigs each sample from its k nearest OTHER samples with the same variogram, radius, k and minimum-neighbor settings and the same solver code. Rows that are NaN, masked or unestimable are NaN. Another sample at exactly the same position is an exact hit (its mean, variance 0). Compare models with the standardized error (value - prediction) / sqrt(variance), which should have mean near 0 and variance near 1, and the root mean squared error of value - prediction.
  • A sample mask is folded into a transient value copy first (a one-pass kernel), and the per-cell status goes to a transient before the counters are accumulated, so every kernel stays within 8 storage buffers.
  • Pinned to PyKrige 1.7.3 with 8 closest points: exponential, spherical and Gaussian within 2e-5 of the data scale on values (about 1.4e-3 on values near 70) and 1e-4 on variance relative to max(1, variance). The Gaussian fixture uses a custom PyKrige variogram with exponent 3, because PyKrige's built-in Gaussian has the other range convention (see above); the pivot-ratio, duplicate-coalescing, mask, leave-one-out and translation fixtures are float64 numpy ordinary kriging (Cressie 1993, eq. 3.2.12 to 3.2.16) that reproduces the PyKrige numbers to 5e-7. Global and universal kriging, anisotropy, octant search and filtered (measurement-error) kriging are not provided.

GPULocalKriging

Predicts values and latent variance at query points or quadrature supports by solving a local covariance system per query.

Local kriging in simple, ordinary, universal, external-drift, block and co-kriging forms, with spherical, exponential, Gaussian or Matérn (smoothness 1/2, 3/2, 5/2) covariances. Unlike GPUKriging, which fills a raster from an indexed grid, it takes explicit query rows and scans the samples or a supplied neighborhood. Full reference: Bounded GPU interpolation and simulation.

  • Covariance parameters are either compile-time (covariance, coregionalization, coregionalizationModels) or per-frame: supply parameters from getGPULocalKrigingParameterValues to change nugget, sill, range and model between frames without a recompile. Set covarianceStructureCount for per-frame co-kriging. The parameter view counts one more storage binding.
  • Matérn range is the effective range (correlation exp(-3) at range, like the exponential and Gaussian models); a Matérn 1/2 model equals the exponential model. Pinned to GSTools 1.7.0 correlation values and simple and ordinary kriging, predictions and variances, with len_scale = sqrt(nu) * range / factor.
  • A system whose pivot ratio is below KRIGING_PIVOT_RATIO_TOLERANCE (1e-4) reports status 2 and writes its pivot ratio to values.z. No nugget floor is applied; see Conditioning of smooth covariances.

::lens{scenario=gpu-spatial-analysis.dot-density rung=result caption="199 tracts (grey) to one dot per 500 residents (blue); dots are not where people live."}

GPURandomPointsInPolygon: Samples a requested number of seeded, uniformly distributed points inside each polygon.

::lens{scenario=gpu-spatial-analysis.random-points-in-polygon rung=result caption="13 community areas (grey) with 20 seeded uniform points each (blue)."}

GPURandomPointsOnLine: Samples seeded points along lines, uniformly per unit of arc length.

::lens{scenario=gpu-spatial-analysis.random-points-on-line rung=result caption="721 street edges (grey) with two seeded points each (blue), uniform along length."}

Maximum: GPUDotDensity holds at most getGPUDotDensityMaximumCapacity(device) (8388608 on a default device) dots.

Dasymetric dot-density maps: value * dotsPerUnit random dots inside each polygon, per category, optionally concentrated by a weight raster such as built-up area. Changing the dot value with zoom only adds or removes dots; existing dots never move, so there is no flicker. GPURandomPointsInPolygon places an integer count of uniform random points per feature. Its internal triangulation limits the polygon layout to getGPUPolygonTriangulationMaximumNodeCount(device) scratch nodes (see GPUPolygonTriangulation).

const parameters = new GPUParameterBuffer(device, {id: 'dots', format: 'uint32', length: 8});
graph.add(
  new GPUDotDensity({
    positions, featureOffsets, polygonOffsets, ringOffsets, // four-level polygon layout
    values, // float32, featureCount * categoryCount rows, feature-major
    categoryCount: 3,
    parameters: parameters.importToGraph(graph),
    mask: {weights, width: 512, height: 512}, // optional, weights in [0, 1]
    output: {positions, dots: {ids, status: {count, overflow, requiredCount}}, categories, status: {failedCount}}
  })
);
parameters.write(
  getGPUDotDensityParameterValues({seed: 1, dotsPerUnit: 1 / peoplePerDot, maskExtent: [x0, y0, cw, ch]})
);
  • A slot (feature, category) draws ceil(value * dotsPerUnit - u) dots with a per-slot Philox uniform u: floor(x) dots plus one more with probability frac(x), monotone in dotsPerUnit.
  • Dot j of a slot is placed exactly, keyed by Philox (seed, slot, j, attempt) and independent of the dot value and of other slots, so coarser dot values give a stable prefix of the finer dots. Every polygon is triangulated on the GPU (GPUPolygonTriangulation; the first ring of a polygon is the shell, later rings are holes), a triangle is picked in proportion to its area (binary search of the feature's cumulative areas, 32-bit fixed point) and the point is uniform in it. Thin or concave polygons in a large bounding box lose no dots. With a mask a candidate is also kept with probability equal to its cell weight, and a masked dot is retried up to maximumAttempts times (default 32; ignored without a mask).
  • Dots are ordered by feature, category and rank (offsets from a prefix scan). dots.ids holds the feature row of each dot and dots.status.count is safe as an instance count; rows past it are NaN / 0xffffffff.
  • Compact status.overflow reports final output capacity only. Optional candidateOverflow reports a per-slot/per-line count clamped before sampling; requiredCount counts retained requests and is then a lower bound. The uint32 prefix bound limits each slot to min(capacity + 1, floor(0xffffffff / slotCount), 2^31) requests. With 65,536 slots and capacity 65,536, a slot requesting 65,536 retains 65,535 and sets candidateOverflow, while final overflow stays zero. Growing the output alone cannot remove the prefix bound. When that per-slot limit is at or below final capacity, construction requires dots.status.candidateOverflow (or points.status.candidateOverflow for line sampling), because clamping could otherwise leave a short result with no visible loss flag.
  • Empty polygons and degenerate rings from clipping are skipped on the GPU. A ring is degenerate when it has fewer than three vertices or every first-vertex fan triangle has exact orientation zero, matching GPUStudyWindowPreparation; an uncertified orientation is retained. A degenerate shell makes its entire polygon empty. Removing these entries while retaining feature rows preserves triangle selection and Philox draws bitwise.
  • Features with zero total area get zero slots, so they consume no capacity and contribute zero to slotCounts, dots.status.count and dots.status.requiredCount. Their clamped requested dot counts are reported in status.failedCount, without an exception.
  • status.failedCount also counts other placement failures, which keep a NaN slot: untriangulable polygons, exceeded triangulation budgets, non-finite areas and masked dots whose attempts all missed (probability (1 - w)^maximumAttempts for mean mask weight w). A feature with no requested dots reports nothing.
  • Coordinates. Dots are uniform in coordinate space, so spatialContext is planar/native only (omitted means planar/native), on GPUDotDensity, GPURandomPointsInPolygon and GPURandomPointsOnLine. Longitude/latitude throws. GPUDotDensity and GPURandomPointsInPolygon declare measure: 'area': an azimuthal-equidistant local frame throws; project into a Lambert equal-area frame. GPURandomPointsOnLine declares measure: 'distance': a Lambert equal-area local frame throws; use an azimuthal-equidistant frame.
  • Ring roles follow GeoArrow position, not an even-odd test: ring 0 of each polygon is the shell and later rings are holes (either winding). The triangulation scratch is about 56 bytes per input vertex.

GPURandomPointsOnLine places counts points per line uniformly in arc length (GeoSeries.sample_points on lines). The Philox key is (line, rank, 0, 0) with key (seed, 3), so the prefix of points is stable as counts grow. Outputs are a bounded positions buffer and a compact points record (ids = line row, status with count, overflow, optional candidateOverflow, requiredCount), plus optional fractions. Parameters reuse getGPUDotDensityParameterValues (seed). Points matched LineString.interpolate at the pinned Philox fractions to 2e-5 relative. Not provided: cluster_poisson sampling.
