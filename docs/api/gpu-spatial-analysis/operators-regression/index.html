Regression

GPUOrdinaryLeastSquares

Fits a linear model of one response on predictor columns by least squares and reports coefficients, standard errors, t statistics and diagnostics.

::lens{scenario=gpu-spatial-analysis.ordinary-least-squares rung=result caption="Diabetes on three predictors across 788 tracts, R squared 0.67; compare each estimate with its standard error."}

Ordinary least squares with an intercept and a full regression report, in one prebuilt graph: coefficients, standard errors, t statistics, R2, adjusted R2, sigma squared, log-likelihood, AIC, BIC, optional per-row residual and fitted columns, the Jarque-Bera normality test, the Koenker-Bassett and Breusch-Pagan heteroskedasticity tests, and collinearity and precision diagnostics (Belsley condition number, correlation condition number, maximum VIF, precision warning). getGPUOrdinaryLeastSquaresModelResult(readback, {predictorNames}) turns the read-back arrays into the shared GPURegressionModelResult (coefficient table with Student t p-values on n - p degrees of freedom, sigmaSquared = RSS / (n - p) and sigmaSquaredMaximumLikelihood = RSS / n, R2, log-likelihood, AIC and BIC equal to spreg, conditioning, and the tests jarqueBera, breuschPagan, koenkerBassett).

const graph = new GPUCommandGraph(device);
graph.add(
  new GPUOrdinaryLeastSquares({
    predictors, // GraphDataView<'float32'>, row-major row * predictorCount + column
    response, // GraphDataView<'float32'>
    mask, // optional GraphDataView<'uint32'>; zero excludes the row
    parameters: ridgeBuffer.importToGraph(graph), // optional: getGPUOrdinaryLeastSquaresParameterValues({ridgeLambda})
    predictorCount: 3, // compile-time, 1 to 15 (16-wide Cholesky); the intercept is added internally
    output: {coefficients, standardErrors, tStatistics, summary, status: {code: status}, residuals, fitted}
  })
);
  • Rows with any non-finite predictor or response value, or a zero mask, are excluded.
  • coefficients, standardErrors, tStatistics: predictorCount + 1 floats, intercept first.
  • summary (22 floats, GPU_ORDINARY_LEAST_SQUARES_SUMMARY_LENGTH), indexed by GPU_ORDINARY_LEAST_SQUARES_SUMMARY_*: row count, R2, adjusted R2, sigma squared, log-likelihood, AIC, BIC, Jarque-Bera, its p-value, Koenker-Bassett, its p-value, RSS, TSS, skewness, kurtosis, ridge lambda, Breusch-Pagan, its p-value, CONDITION_NUMBER, CORRELATION_CONDITION_NUMBER, MAXIMUM_VARIANCE_INFLATION_FACTOR, PRECISION_WARNING. The slots 9 and 10 used to be called BREUSCH_PAGAN; they were always the Koenker-Bassett statistic, and BREUSCH_PAGAN now names the classic test in slots 16 and 17.
  • The predictor count is capped at 15 (16 coefficients with the intercept) by the 16-wide function-local Cholesky factorization of the solve; a larger design needs a tiled solver.
  • status.code (uint32): 0 ok, 1 singular or ill-conditioned (a predictor within 1 - 1e-6 of the span of the others, or constant), 2 too few rows (n <= predictorCount + 1). A failed fit leaves every statistic and per-row column NaN (the row count is still written).
  • residuals and fitted are optional per-row columns (NaN for excluded rows).
  • Optional predictions has one value per input row, including masked rows and rows with a missing response, provided their predictors are finite. It uses the fit's training-only centers, slopes and mean correction; a failed fit or nonfinite predictors produce NaN. The operation form and CPU twin expose the same output. Raw float32 intercepts can lose response-level information at large predictor origins, so use these centered predictions for held-out evaluation. The OLS GPU operation and CPU twin capture all graph names and optional output presence at construction, including the nested status name. Reusing or editing the caller's props/output map cannot rename a declared prediction or disable its writer; construct a new operation to change ports. Input graph values remain per-run data.
  • Conditioning never changes status: a warning is not a failure and the fit is still reported. CONDITION_NUMBER is the Belsley number (spreg OLS.mulColli): sqrt(lambdaMax / lambdaMin) of the raw [1, X] Gram matrix scaled to unit diagonal (rebuilt from the centered moments and means; values above about 30 mean harmful collinearity; ridge is not included). CORRELATION_CONDITION_NUMBER is lambdaMax / lambdaMin of the predictor correlation matrix the float32 Cholesky factors (with the ridge penalty), and MAXIMUM_VARIANCE_INFLATION_FACTOR the largest diagonal of its inverse. Float32 coefficients lose about correlationConditionNumber * 6e-8 relative accuracy, so PRECISION_WARNING is 1 when the correlation condition number exceeds 1e4 (GPU_REGRESSION_PRECISION_CONDITION_LIMIT, about three of seven digits lost). Eigenvalues come from a cyclic Jacobi routine in float32, so the condition numbers are indicative for very ill-conditioned designs (the GPU specs allow 2e-2 to 1e-1 relative against the float64 oracle and spreg). They match spreg mulColli and diagnostics.vif (max over the predictor columns, computed on the centered design) in the float64 oracle.
  • The optional ridge penalty lambda >= 0 is added to the centered normal matrix of the predictors (never the intercept) and changes between frames without rebuilding the graph. Ridge standard errors are sigma2 (X'X + lambda I)^-1 and ignore the shrinkage bias.

Numerics: no float atomics. Per-tile partial sums (one invocation per tile of consecutive rows, in row order) are merged in a fixed pairwise order (a float Kahan compensation is folded to a plain sum by the shader compiler of at least one supported GPU). Each tile first selects a complete training-row origin and sums differences from it. The merge shifts those partials to the first nonempty tile's origin before averaging; empty tiles contribute zero. This preserves small variances when many nearly equal predictors have a large coordinate origin. Means first, then centered cross-products about those means; the solve runs on the correlation-scaled normal matrix with a single-invocation Cholesky. The residual sum of squares comes from the residual pass, not from Syy - b'Sxy, so it stays accurate when R2 is close to 1. A float32 mean misses the true mean of its column by up to a float32 step; the moment pass also sums the deviations of every column from its stored mean, and that remainder is carried through the cross-products, the intercept and the residuals, so the residuals sum to zero and the residual sum of squares matches float64 also when the response mean is thousands of residual deviations (residuals of 0.002 around 10,000: within 1e-4, where a float32 mean alone gave 4% to 20% too much). Results are bitwise reproducible for a given tileRowCount (default max(64, ceil(rows / 4096))). Mean corrections are divided by the row count before multiplication, with the quotient fixed by an integer bit cast, so an overflowing product of deviation sums cannot erase a finite variance. Fitted values and held-out predictions also fix the combined centered contribution and mean correction with an integer bit cast before adding the response mean. This prevents Metal fast math from adding small correction terms to a large mean separately and rounding them away.

AIC and BIC count predictorCount + 1 parameters (GeoDa convention); the log-likelihood is Gaussian with sigma2 = RSS / n. Each estimator on this page counts as its reference library does: OLS the intercept and predictors (p), GPUSpatialLagMaximumLikelihood p + 1 (it adds rho), GPUSpatialErrorMaximumLikelihood p (not lambda), and the GWR family tr(S) + 1 (the error variance). Put the models on one count before comparing criteria: each uncounted parameter adds 2 to AIC and ln(n) to the Schwarz criterion. Jarque-Bera is n/6 (S^2 + (K - 3)^2 / 4) with p-value exp(-JB / 2). Both heteroskedasticity tests use the auxiliary regression of e^2 on [1, X] with R2_aux, and a chi-square p-value on predictorCount degrees of freedom computed by the regularized upper incomplete gamma with a fixed iteration cap. Koenker-Bassett (studentized, valid without normality) is n R2_aux; the classic Breusch-Pagan (assumes normal errors) is 0.5 R2_aux (sum e^4 / s2^2 - n) = 0.5 R2_aux n (kurtosis - 1) with s2 = RSS / n, which is spreg breusch_pagan with z = [1, X]. Both match spreg 1.9.1 (breusch_pagan, koenker_bassett with z = reg.x; spreg's default z is the squared design). With skewed errors they differ several times over, and Jarque-Bera rejecting normality is the cue to read Koenker-Bassett instead. getChiSquareSurvival(value, degreesOfFreedom) is the float64 CPU mirror, and getStudentTTwoSidedPValue / getStudentTSurvival (float64 regularized incomplete beta, pinned to scipy.stats.t.sf) back the model-result p-values.

The shared model result derives global corrected AIC as AIC + 2 k (k + 1) / (n - k - 1), where k is the information-criterion parameter count. It returns null when n <= k + 1 or the model has no likelihood. Estimator-specific corrected-AIC overrides are preserved.

GPUGeographicallyWeightedRegression

Fits a separate weighted regression at every location and writes local coefficients, standard errors, t values and fit statistics, choosing the bandwidth by AICc.

::lens{scenario=gpu-spatial-analysis.geographically-weighted-regression rung=result caption="Diabetes beside the local poverty coefficient, 0.002 to 0.34 across 788 tracts; compare where it is strongest."}

Pass optional spatialContext to getGPUGeographicallyWeightedRegressionParameterValues(settings) to warn on short fixed bandwidths; see Precision of longitude/latitude positions.

Geographically weighted regression with AICc bandwidth selection (Fotheringham, Brunsdon and Charlton 2002; mgwr, ArcGIS GWR). For every included row i it fits a weighted least squares y ~ 1 + x over all included rows j with weights K(d_ij / h) and writes local coefficients, local standard errors, t values and a significance mask, local R-squared, fitted values, residuals and the hat-matrix diagonal.

const parameters = new GPUParameterBuffer(device, {
  id: 'gwr-parameters',
  format: 'float32',
  length: getGPUGeographicallyWeightedRegressionParameterLength(16)
});
graph.add(
  new GPUGeographicallyWeightedRegression({
    positions, // GraphDataView<'float32x2'>, planar (or lon/lat degrees with spatialContext)
    predictors, // row-major row * predictorCount + column
    predictorCount: 2,
    response,
    parameters: parameterBuffer.importToGraph(graph),
    maximumBandwidthCount: 16,
    output: {coefficients, standardErrors, tValues, significant, selectedBandwidth, summary}
  })
);
parameters.write(
  getGPUGeographicallyWeightedRegressionParameterValues(
    {kernel: 'gaussian', bandwidthMode: 'adaptive', bandwidths: [20, 40, 60, 80]},
    16
  )
);

  • Kernels: 'gaussian' exp(-0.5 (d/h)^2) (unbounded unless gaussianCutoff is set) and 'bisquare' (1 - (d/h)^2)^2 for d < h.

  • Bandwidths: 'fixed' (ladder values are distances) or 'adaptive' (ladder values are neighbour counts k, h is 1.00001 times the distance to the k-th nearest included row, the row itself counted as in mgwr; k in [2, maximumNeighborCount], at most 128).

  • Bandwidth ladder: up to maximumBandwidthCount (at most 32) candidates in the parameter buffer. Each candidate's AICc, n ln(RSS/n) + n ln(2 pi) + n (n + tr S) / (n - 2 - tr S), is evaluated on the GPU and the outputs are written at the selected bandwidth. A ladder of one value is a fixed bandwidth. Candidates with a non-positive bandwidth, invalid k or n - 2 - tr S <= 0 score NaN.

  • Singular locations (changed): a location whose local system is singular (for example a rare dummy that is constant in its neighbourhood) makes only that row NaN (coefficients, standard errors, fitted value, residual, hat; localStatus 1). It no longer voids the whole candidate. A candidate's n, RSS, tr S and AICc are taken over its non-singular rows, and bandwidthSingularRowCounts reports the count per candidate. Selection: among the candidates with the fewest singular rows the lowest AICc wins (ties to the lowest index), so a bandwidth with singular rows is chosen only when every valid candidate has some. This is a deliberate deviation from mgwr, which raises on a singular local system.

  • localStatus 1 (SINGULAR) also covers an ill-conditioned local design. The local normal equations are scaled to unit diagonal (a correlation matrix, on the design centred at the focus), and a Cholesky pivot below GPU_ORDINARY_LEAST_SQUARES_PIVOT_TOLERANCE (1e-3, the OLS limit) is singular, so a local predictor within about 1 - 1e-6 of the span of the earlier columns (variance inflation factor above 1e6) is rejected exactly where GPUOrdinaryLeastSquares reports status 1. Before this test only a non-positive pivot failed and a nearly collinear design returned coefficients with status 0. The same test applies to the generalized GWR information matrix and the nonstationarity test refits. Well-conditioned fits are unchanged.

  • Refinement (new, default on; refinement: false keeps the fixed ladder, a number from 1 to 4 sets the pass count, default 2): after the caller ladder, a GPU kernel writes a new ladder that zooms around the best candidate between its nearest evaluated neighbours (it never extrapolates beyond the caller's range), the same kernels evaluate it, and the overall best wins. Adaptive ladders hold integers: when the integers inside the bracket number at most maximumBandwidthCount all of them are tried, so the result is the exact integer optimum of the bracket; a wider bracket is sampled at equal spacing and the next pass narrows it. Fixed ladders are maximumBandwidthCount equally spaced distances per pass. Each pass costs up to one more ladder evaluation, so the default is about three times the work of the bare ladder; shorten the ladder rather than turning refinement off when cost matters. selectedBandwidth is [candidate index, value]; indices from maximumBandwidthCount up are refined candidates, and candidateTable lists every candidate of every pass. Every pass reads its ladder through a GPU pass cursor, so N and N + 1 passes compile the same pipelines. On the 144-row test scene (adaptive bisquare) mgwr's golden section with its default bounds [40 + 2 p, n] stops at k = 47, while its exhaustive integer AICc optimum, which the refinement finds from a five-value ladder, is k = 26 (and mgwr's golden section with bounds widened to 6..144 agrees). The AICc curve in k is not unimodal there (local minimum near 30), which is why a bracket that fits the ladder is enumerated rather than searched.

  • Golden-section search (new, opt-in bandwidthSearch: 'golden-section'; the default 'ladder' is unchanged): mgwr's Sel_BW(...).search('golden_section') as a fixed-depth loop on the GPU, about 12 to 20 candidate evaluations instead of a ladder of up to 32 per pass, no read-back. The first two bandwidths values of the parameters are the bounds [minimum, maximum]; a value of 0 or less takes mgwr's default for that bound, so [0, 0] is mgwr's default search, and a single value is a fixed, unselected bandwidth. Defaults are computed on the GPU from the included rows: adaptive [40 + 2 (predictorCount + 1), n] with n capped at maximumNeighborCount (mgwr's n cannot be evaluated beyond the neighbour list; identical for n <= maximumNeighborCount), fixed [min_dist / 2, 2 max_dist] with min_dist the smallest positive row-to-row distance and max_dist the largest pairwise distance (exact without a grid index; with one, the largest distance from a row to a corner of the grid extent, an upper bound that costs at most an iteration or two). The interior points are mgwr's a + 0.38197 (c - a) and c - 0.38197 (c - a), rounded half to even to integers for adaptive bandwidths. Iteration 1 evaluates both points, every later iteration compares the two scores, shrinks the bracket and evaluates the one new interior point with the same candidate kernels (the other is reused). The search stops when the two interior AICc values differ by at most max(1e-6, 4e-6 |AICc|), mgwr's 1e-6 with a float32 noise floor (the AICc sums n float32 terms; 1e-6 alone never fires at AICc values of hundreds), or after maximumSearchIterations (default 30, at most 64, compile-time). The selected bandwidth is the winner of the last comparison, as mgwr returns it; fewest singular rows first, then the lower AICc, an invalid score loses to a valid one and two invalid scores stop the search. The iteration index is a GPU cursor and the loop is gated by an indirect dispatch that the one-thread iteration kernel zeroes on convergence, so N and N + 1 iterations compile the same pipelines and converged iterations launch nothing. candidateTable then has maximumSearchIterations + 1 rows in evaluation order (rows 0 and 1 are the first interior points, row i + 1 the point of iteration i; unreached rows are NaN), selectedBandwidth[0] is the table row of the selection, bandwidthScores and bandwidthSingularRowCounts hold its first maximumBandwidthCount rows, and the optional searchState output reports the bracket, iteration count and whether the tolerance (not the cap) stopped it (GPU_GEOGRAPHICALLY_WEIGHTED_REGRESSION_SEARCH_STATE). refinement is ignored. Needs maximumBandwidthCount >= 2 and maximumNeighborCount >= 2. Pinned to mgwr 2.2.1 on the 144-row scene (bisquare and Gaussian, adaptive and fixed): the adaptive k is mgwr's exactly, fixed bandwidths agree within the AICc-flatness tolerance of the float32 search, and the float64 CPU mirror of the state machine reproduces mgwr's evaluated bandwidths in order. mgwr rounds its fixed answer to two decimals; this contributor returns the unrounded value.

  • Gaussian cutoff (new, gaussianCutoff in bandwidth multiples, compile-time, default exact unbounded Gaussian): the weight of a row farther than gaussianCutoff * h is exactly 0 (fixed and adaptive), and the Gaussian kernel then uses the grid index like bisquare, O(n * neighbours) instead of O(n^2) (mgwr has no cutoff). The omitted weight of a row is at most exp(-c^2 / 2) of the self weight: 1.1e-2 at c = 3, 3.4e-4 at 4, 3.7e-6 at 5, 1.5e-8 at 6. For a locally uniform density the omitted share of the weight sum is that value and of the weighted second moment (1 + c^2 / 2) exp(-c^2 / 2) (3.0e-3 at 4, 5.0e-5 at 5, 2.8e-7 at 6), which bounds the relative effect on the local sums up to the local conditioning; on the test scene the coefficient error stays below 20 times that share. Recommended: 5 (GPU_GEOGRAPHICALLY_WEIGHTED_REGRESSION_RECOMMENDED_GAUSSIAN_CUTOFF), where the effect is below the float32 accumulation error of the fits; use 4 when 3e-3 is acceptable and 6 only to match the exact Gaussian to float32. The cutoff does not change the bisquare kernel.

  • Local inference (new): standardErrors, tValues and significant (all laid out like coefficients) are mgwr bse, tvalues and filter_tvals != 0. bse = sqrt(diag(C C') sigma2) with C C' = (X'WX)^-1 X'W^2 X (X'WX)^-1 (one more weighted Gram matrix in the same neighbourhood pass) and sigma2 = RSS / (n - tr S) (mgwr sigma2_v1). The summary carries ENP = tr S, SIGMA_SQUARED, LOG_LIKELIHOOD, the Da Silva-Fotheringham adjusted alpha alpha * k / tr S (ADJUSTED_ALPHA, k design columns, alpha 0.05 unless the per-frame significanceLevel says otherwise) and the critical value t.ppf(1 - adjusted / 2, n - 1) (CRITICAL_T). The Student t quantile is inverted on the GPU (continued-fraction incomplete beta with a bisection; the float64 CPU mirror getStudentTCriticalValue is pinned to scipy.stats.t.ppf to 1e-9 and the GPU summary is checked against mgwr), because the mask needs it there. significant is 1 where |t| > CRITICAL_T. The bandwidth is selected on the observed data and the inference is conditional on it, as in mgwr. Pinned to mgwr 2.2.1 (fixed and adaptive, planar and spherical); adaptive fits agree to about 5e-4 because mgwr scales the k-th neighbour distance by 1.0000001 and this contributor by 1.00001.

  • getGPUGeographicallyWeightedRegressionModelResult({summary, selectedBandwidth}) returns the shared GPURegressionModelResult (kind: 'geographically-weighted-regression', empty coefficients, parameterCount = tr S, rowCount = n, sigmaSquared = RSS / (n - tr S), logLikelihood, akaikeInformationCriterion = -2 llf + 2 (tr S + 1) and correctedAkaikeInformationCriterion (mgwr llf, aic, aicc), rSquared) plus effectiveParameterCount, singularRowCount, includedRowCount, adjustedAlpha, criticalT and selectedBandwidth.

  • spatialContext (new): omitted is planar. It measures distance, so local-lambert-equal-area frames throw. {coordinateSpace: 'longitude-latitude', metric: 'great-circle', units: 'meters'} makes positions (longitude, latitude) degrees and every distance (kernels, fixed bandwidths, the adaptive k-th neighbour) a haversine distance on a sphere of sphereRadius (default the mean Earth radius 6,371,008.8 m); bandwidths are then metres. Rows with a latitude outside [-90, 90] are excluded. The grid index is planar-only and is not built for a great-circle context, so every location scans every included row and the 65,536-row scan limit applies; the cell walk is not made exact for longitude wrap-around. mgwr spherical=True uses a 6371.0 km radius and kilometres, so pass sphereRadius: 6371000 and metres to match it.

  • Predictors: 1 to 11 (12 design columns; it was 7). No kernel binds more than eight storage buffers, because the per-row results (including standard errors) share one row-state buffer; the limit is per-thread private memory (2 P^2 + 6 P floats in the fit). The 11-predictor shader has not been run on every adapter: lower GPU_GEOGRAPHICALLY_WEIGHTED_REGRESSION_MAXIMUM_PREDICTOR_COUNT if one rejects it.

  • Outputs: coefficients (row * (predictorCount + 1) + column, column 0 intercept), optional standardErrors, tValues, significant, localR2 (1 - sum_j w_ij (y_j - x_j' beta_i)^2 / sum_j w_ij (y_j - ybar_i)^2: the residuals are those of local model i at its neighbours j, not each neighbour's own GWR residual, so a package that uses the latter gives different values), fitted, residuals, hatDiagonal, localStatus (0 ok, 1 singular, 2 excluded), bandwidthScores (AICc of the caller ladder), bandwidthSingularRowCounts, candidateTable, selectedBandwidth ([index, value]), localConditionNumber and summary (GPU_GEOGRAPHICALLY_WEIGHTED_REGRESSION_SUMMARY: RSS, tr S, AICc, global R-squared, n, has-valid-candidate flag, singular rows, sigma2, adjusted alpha, critical t, log-likelihood, included rows; 12 floats, it was 6).

  • localConditionNumber is the mgwr local_collinearity local condition number: the singular-value ratio of the kernel-weighted, column-normalized design (above 30 flags collinearity). It is pinned to mgwr 2.2.1 (bisquare and gaussian, fixed and adaptive). The weighted design rows are folded into a triangular factor by Givens rotations and its singular values come from one-sided Jacobi (the helpers of GPULocalCollinearity), so the two classes report the same number to about float32 epsilon * condition, also for a predictor with a large mean. The former Gram-matrix route was 17% off for a predictor of 1500 +- 3 and meaningless for a projected northing.

  • Rows with a zero mask or a non-finite position, predictor or response are excluded as calibration locations and as neighbours.

  • Numerics: the design is centred on the focal row and Jacobi-equilibrated before the shared Cholesky solve, so large coordinates or badly scaled predictors stay well conditioned in f32. A predictor that is constant over a neighbourhood makes that location singular.

  • Cost: one thread per location scanning every row per candidate: O(n^2 * ladder * p^2), at most 65536 rows without the grid index (see indexGridSize below) (about 80 ms for 4096 rows and 8 candidates on the test adapter). Reductions use fixed-order 256-row tiles, so results are bitwise reproducible.

  • Grid index: indexGridSize (default: automatic from 1024 rows; false disables) bins rows into a uniform grid so each location scans nearby cells only. The row cap rises from 65,536 to 1,048,576 with the grid, and 'bisquare' fixed-bandwidth fits sum in cell order (about 1e-5 relative to the earlier row-order sums, still deterministic). Gaussian kernels use the grid only with a gaussianCutoff.

Decode localStatus with decodeGPUGeographicallyWeightedRegressionStatus and compare codes with GPU_GEOGRAPHICALLY_WEIGHTED_REGRESSION_STATUS. It reports each local weighted least squares fit. A successful local fit does not establish bandwidth-search convergence: the golden-section searchState reports that separately. MGWR has different row codes and a separate decoder for the coupled backfit outcome; GWR code 1 means singular, while MGWR code 1 means excluded. The parameter packer requires every supplied bandwidth to remain finite in float32 and an explicit significanceLevel to remain strictly between 0 and 1 in float32. ::lens{scenario=gpu-spatial-analysis.spatial-weights-traces rung=result caption="Traces of 12 queen-weight powers fall from 122 at q = 2 to 19; sums stay at 788."}

Powers of a spatial weights matrix: powerTraces[q-1] = tr((W/s)^q) and powerSums[q-1] = 1' (W/s)^q 1 with s = ||W||_inf (largest absolute row sum, written to output.infinityNorm; series then run in rho * s, which keeps the float32 powers bounded for raw weights) for q = 1..Q. Props: weights (any square CSR: asymmetric, not standardized, self-loops allowed), maximumPower (Q, compile-time, 1 to 256), optional mode, probeCount, parameters (per-frame [seed], getGPUSpatialWeightsTracesParameterValues({seed}); omitted means seed 0), includeGramTraces, tileRowCount, probeBatchSize and output: {powerTraces, powerSums, gramTraces?, status?: {approximation?}, infinityNorm?} (float32 views of at least Q, Q, 4 values and a uint32 scalar). Construction requires at most 4096 tiles for the serial norm merge, in both exact and stochastic modes. For whole weights the count is ceil(rows / tileRowCount); for chunked weights it is the sum of ceil(chunk.rowCount / tileRowCount) over chunks. Increase tileRowCount or combine small chunks if the count exceeds 4096. The default whole-CSR layout targets 1024 tiles and still reaches 2^24 rows in stochastic mode. Chunk boundaries can exceed the cap even with the default tile width. GPUSpatialWeightsTracesOperation applies the same check during lowering, including chunked inputs. The contributor captures chunk boundaries and nested weight-view references at construction; later edits to the caller's chunk array or port maps do not change the validated dispatch layout.   • mode: 'exact' runs one unit-vector chain v_q = W v_{q-1} per row and sums the diagonal entries v_q[i]: exact up to float32 rounding. It is the default for at most 4096 rows (GPU_SPATIAL_WEIGHTS_TRACES_MAXIMUM_EXACT_ROW_COUNT): the work is rows * Q * nnz, which at 4096 rows, Q = 256 and 8 neighbors is about 3e10 multiply-adds in about 520 dispatches, while 16384 rows (the limit of an explicit 'exact') already costs 8200 dispatches and 5e11 multiply-adds.
  • mode: 'stochastic' is Hutchinson estimation with probeCount (default 64) Rademacher probes from Philox (counter (probe, row / 4, 0, 'PROB'), key (seed, 'TRAC'), the seed read on the GPU, so changing it never recompiles; a seeded run is reproducible and the test-only CPU reference in modules/analysis/test/reference replays the same probes). The standard error of tr(A) is at most sqrt(2 / probeCount) ||A||_F. output.status.approximation is 1 (it is 0 in exact mode).
  • powerSums is always exact: one chain from the ones vector.
  • gramTraces (when includeGramTraces, 4 values) are [tr(W'W), tr(W'W W), tr((W'W)^2), sum_i c_i^2] with c_i = sum_l w_li^2: the moments of the Kelejian-Prucha and Anselin-Kelejian variance formulas. tr(W'W) and sum c_i^2 are exact sums (the column sums use GPUSpatialWeightsTranspose); the other two are E[(Wz)'(WWz)] and E[||W'(Wz)||^2] over the same probes, exact in exact mode.

Probes run in batches whose two ping-pong vectors stay within 64 MiB. Every dot product is a fixed-order tile sum with a pairwise merge, so there are no float atomics and results are bit-identical across batch sizes and runs. The shaders do not depend on the power, the batch or the probe index: per-power and per-batch tables are 64-element aligned sub-views and a GPU batch table holds each batch's first probe and probe count, so the pipeline count does not grow with maximumPower or the number of batches. A W with spectral radius above 1 grows as radius^q and can overflow float32 for large Q.

The series require |rho| * spectralRadius(W) < 1 (|rho| < 1 for a row-standardized W) and are truncated: the log-determinant error is below n |rho|^(Q+1) / ((Q+1)(1 - |rho|)) and the multiplier error below n |rho|^(Q+1) / (1 - |rho|), so choose Q from |rho|^Q (Q = 30 is accurate to 1e-9 at |rho| = 0.5 but needs about 300 terms at |rho| = 0.9).

The traces match np.trace(np.linalg.matrix_power(W, q)) for q = 1..12 on a row-standardized lattice, a binary lattice and two directed kNN scenes (numpy 2.5.4), and the log-determinant series matches np.linalg.slogdet within the stated bound.

GPUSpatialErrorGM

Estimates a spatial error model by generalized moments, then a feasible GLS regression on spatially filtered variables.

::lens{scenario=gpu-spatial-analysis.spatial-error-gm rung=result caption="Five rows: intercept, three predictors and lambda; lambda = 0.83 with standard error 0.015."}

The spatial error model y = X b + u, u = lambda W u + e by generalized moments. Props: weights (any square CSR; no symmetry or standardization needed), predictors, response, predictorCount (1 to 15, the OLS limit and the 16-wide Cholesky; no kernel binds more than 8 storage buffers, so the previous cap of 8 was not needed), estimator, optional tileRowCount, traceMode, traceProbeCount, traceParameters (per-frame seed, as GPUSpatialWeightsTraces parameters) and output: {table, summary, status: {code}, residuals?}. For either estimator, construction requires at most 4096 tiles for the serial norm merge: ceil(rows / tileRowCount) for whole weights, or the sum of ceil(chunk.rowCount / tileRowCount) over chunks. Increase tileRowCount or combine small chunks if this limit is exceeded. The default whole-CSR layout still reaches 2^24 rows; chunk boundaries can exceed the cap even with the default tile width. CPU twins do not use tile merges and retain their existing row limits. GPUSpatialErrorGMOperation applies the whole-CSR tile-count check during lowering. The contributor captures chunk boundaries and nested weight-view references at construction, so later edits to the caller's chunk layout cannot change the validated tile count.

Default change. estimator is 'homoskedastic' by default (spreg 1.9.1 GM_Error_Hom, A1 = 'hom_sc', one iteration: Drukker, Egger and Prucha 2013, Anselin 2011), which gives lambda a standard error, z and p-value.   • Steps (both): OLS of y on [1, X] gives u; moments of u give lambda, minimized globally on a 1024-interval grid with bisection of every bracketed minimum (spreg runs a local L-BFGS-B from zero; the two agree whenever the objective has a single basin); OLS of y - lambda W y on the filtered [1, X] (the constant is filtered too, as get_spFilter does) gives the coefficients.

A solution on the bound is flagged (..._SUMMARY_LAMBDA_AT_BOUND) and ..._SUMMARY_LAMBDA_BOUND reports the bound.

The closed forms replace spreg's n x n A1, A2 and are verified against spreg's own psi, G, lambda and standard errors (the betas-lambda covariance of spreg is not formed; it changes no reported number). Pinned to spreg on a row-standardized lattice, an asymmetric kNN scene and a non-row-standardized (binary) lattice.
  • Traces are exact up to 4096 rows and Hutchinson estimates above (traceMode overrides). With stochastic traces the standard error of lambda is approximate and ..._SUMMARY_APPROXIMATION is 1.0 (betas, lambda and the betas' standard errors still use the exact moment sums).

  • summary (13, GPU_SPATIAL_ERROR_GM_SUMMARY_*): n, lambda, sigma2 = e'e / n (spreg sig2n), pseudo R2, the residual sum of squares u'u and the moment objective at the solution, then conditioning of the final filtered regression (Belsley condition number of the raw filtered [1, X], correlation condition number of the factored Gram matrix, largest predictor variance inflation factor, and a precision warning above a correlation condition number of 1e4 that never changes status), the lambda bound, the approximation flag and the at-bound flag.
  • status.code: 0 ok, 1 singular (OLS or filtered fit), 2 too few rows (n <= k + 2), 3 non-finite (including W without links).
  • residuals: u = y - X b, formed in the centered model as (y - ybar) - a0 - (x - xbar) b, so they and the filtered residuals behind sigma2 keep their accuracy when the response mean is far above them (residuals of 0.002 to 0.004 around 10,000 match spreg in float64 within 1e-4 in sigma2 and u'u).

GPUSpatialLagMaximumLikelihood

Estimates a spatial lag model by maximum likelihood, searching rho on the concentrated likelihood with a trace-series log-determinant.

::lens{scenario=gpu-spatial-analysis.spatial-lag-maximum-likelihood rung=result caption="Five rows: intercept, three predictors and rho; rho = 0.65 with standard error 0.021."}

Maximum-likelihood estimator of the spatial lag model y = rho W y + X b + e (spreg 1.9.1 ML_Lag, method='full'), with the exact log-determinant replaced by a truncated trace series. Nothing is read back. Props: weights (any square CSR), predictors, response, predictorCount (1 to 14), maximumPower (series length Q, 2 to 256, default 128), traceMode, traceProbeCount, traceParameters (per-frame seed), optional tileRowCount and output: {table, summary, status: {code, converged?}, residuals?, powerTraces?, powerSums?, infinityNorm?}. Provide powerTraces, powerSums and infinityNorm together to share the traces with a downstream GPUSpatialLagImpacts. The likelihood contributor resolves its nested trace layout at construction, starting with the trace default width and doubling it if chunk boundaries produce more than 4096 tiles. More than 4096 nonempty chunks cannot fit and are rejected at construction, before graph resources are declared. The captured layout is used for both allocation planning and the trace child; weights port maps and chunk boundaries are also captured, while GPU contents remain per-frame inputs. The GPU operation form applies these checks when lowered; CPU twins do not use trace tiling.

  • Steps: the OLS residuals e0, e1 of y and of the lag of y on [1, X] (two GPUOrdinaryLeastSquares compositions) give the concentrated likelihood -n/2 ln(s2(rho)) + ln|I - rho W|, s2 = (e0 - rho e1)'(e0 - rho e1) / n. The lag is formed about the response mean, W y = W (y - ybar) + ybar s_i, with the row sums s_i of the float32 weights carried exactly (rows without neighbours included), because a sum of w * y over the raw response is rounded to a float32 step of the response. The search evaluates u'u as S + e1'e1 (rho - rho*)^2, with S the sum of squares of e0 - rho0 e1 at rho0 = e0'e1 / e1'e1 summed per row and rho* its minimizer, not as e0'e0 - 2 rho e0'e1 + rho^2 e1'e1: where the model fits well (u'u below 1e-7 of e0'e0) that difference of three float32 sums is rounding, and the search then failed (status 3) or returned a wrong rho with status 0. The log-determinant is -sum_{q<=Q} rho^q tr(W^q) / q from GPUSpatialWeightsTraces (exact traces up to 4096 rows, Hutchinson above). rho is the global maximum on [-B, B]: one kernel evaluates the analytic derivative on 1025 grid points, bisects (32 steps) every positive-to-non-positive sign change on the derivative, and keeps the best candidate (an end point counts when the derivative points outward). It is deterministic and has no iteration budget. b = b0 - rho b1, s2 = u'u / n.
  • Variance: spreg's information matrix of (b, rho, s2) with tr1 = tr(W A) and tr2 = tr((W A)^2) as series in rho of the power traces, and tr3 = tr((W A)' W A), A = (I - rho W)^-1, from a second probe pass at the estimated rho (Horner u <- z + rho W u per probe, exact unit probes up to 4096 rows, Rademacher above; the probes of GPUSpatialWeightsTraces). The s2 row is eliminated by its Schur complement, the matrix is built on centered predictors and on W A X b about its mean (two more nodes; for a response with a large mean the raw column cancels against the intercept in float32, which gave standard errors of rho and of the intercept a half to a third of spreg's, or NaN), unit-scaled and factored with the shared Cholesky, and the intercept variance is mapped back to the uncentered model. A positive definite failure leaves the standard errors NaN (..._SUMMARY_VARIANCE_DEFINED 0) without changing status. The coefficient block equals spreg's vm.
  • Search interval and truncation. B = min(0.99, seriesLimit) / ||W||_inf with ||W||_inf the largest absolute row sum computed on the GPU (0.99 for a row-standardized W; keeps I - rho W invertible for any W, whereas spreg's fixed (-1, 1) admits explosive rho for raw weights). The series omits a tail below n s^(Q+1) / ((Q+1) (1 - s)), s = |rho| ||W||_inf (worst case, |tr(W^q)| <= n s^q; getSpatialLogDeterminantTruncationBound), and omitting it biases the likelihood toward large positive rho, so the interval also stops at the seriesLimit where the worst-case tail reaches 1e-5 n (getSpatialMaximumLikelihoodSeriesLimit: about 0.93 for Q = 128, 0.96 for Q = 256). Beyond it the fit is a boundary solution (..._SUMMARY_AT_BOUNDARY, ..._SERIES_LIMITED, converged 0); raise maximumPower when rho is near the bound. The default Q = 128 keeps the worst-case truncation below 1e-7 n log-likelihood units at |rho| <= 0.9 (below 1e-6 |LL|) at the cost of about Q (1 + probe batches) dispatches; the probe pass costs rows x Q x nnz multiply-adds in exact mode. ..._SUMMARY_TRUNCATION_BOUND reports the remainder at the estimate.
  • Approximation. Above 4096 rows the traces and the tr3 pass are Hutchinson estimates (..._SUMMARY_APPROXIMATION 1.0): rho itself then carries stochastic error (about 1e-3 with 256 probes on a 144-row lattice), unlike GPUSpatialErrorGM where only the standard error of lambda is approximate.
  • table: (k + 2) x 4 f32 rows of [coefficient, se, z, two-sided normal p]: the intercept, X, then rho last (spreg W_y). It is the layout GPUSpatialLagImpacts reads (coefficientStride: 4, rhoIndex: predictorCount + 1).
  • summary (22, GPU_SPATIAL_MAXIMUM_LIKELIHOOD_SUMMARY_*): n, rho, sigma2 = u'u / n, full log-likelihood -n/2 ln s2 + ln|I - rho W| - n/2 (ln 2 pi + 1) (spreg logll), AIC and Schwarz with spreg's k = predictorCount + 2 (rho counted), pr2 (squared correlation of y and y - u), pr2_e (of y and (I - rho W)^-1 X b), u'u, conditioning of the design (Belsley number, correlation condition number, largest VIF, precision warning above 1e4; never changes status), the bound, the approximation, converged, at-boundary and series-limited flags, the truncation bound, variance-defined, the number of local maxima found on the grid (more than 1 is multimodal) and ln|I - rho W|.
  • status.code: 0 ok, 1 singular design, 2 too few rows (n <= k + 2), 3 non-finite predictor, response or weight, no admissible interval, a residual sum of squares that reaches zero inside the search interval, or an interior rho that fails the first-order condition: with u'u and u'e1 summed per row from the published residuals and t = u'e1 / u'u, the derivative g = n t - tr(W A) of the concentrated log-likelihood and its curvature c = n (e1'e1 / u'u - 2 t^2) + tr((W A)^2) must satisfy |g| <= sqrt(0.25 c) + 4 c step, that is, rho is within half a standard error plus four float32 steps of rho of a stationary point. Only ratios of the sums are formed, so a response multiplied by 1e-10, 1 or 1e10 gives the same status and the same rho to 6e-8 (the products of two sums of the earlier form overflowed at 1e10 and rejected a correct fit). The four steps are the float32 resolution of rho and of the sums: without them the float32 nearest to the maximum failed the test when the standard error of rho is below one step (a 64-row scene with a standard error of 4.6e-9; rho is now returned within two steps, but s2 is 33 times the float64 value there, the standard errors 5.7 times and the log-likelihood 111 low, and no output flags it. The cause is the coefficients: the residuals are e0 - rho e1 of two float32 OLS fits, each with its own rounded slope, and 91% of the published residual sum of squares lies in the span of [1, x] (the published slope is one float32 step from the float64 slope). The float32 floor of the residual arithmetic is 1.04 to 1.65 times, and the published residuals with their component in the span of [1, x] removed give 2.9 times; the kernel does not refine the coefficients as the two-stage kernel does). The check catches a search that ended away from a stationary point: a rho moved by 1e-4 on a high-fit scene, or by one standard error on an ordinary one, is status 3, and one moved by a fifth of a standard error is accepted. It shares the trace series with the search and cannot tell a local maximum from the global one. The outputs are then NaN, except residuals, which keep those of the rejected rho. status.converged (optional) is 1 for an interior maximum. Two degenerate cases have a likelihood and are fitted as spreg ML_Lag fits them: a minimum of u'u that is zero but lies outside the search interval (u'u = e1'e1 (rho - rho*)^2 is positive on the interval), and e1'e1 = 0 (the lag column lies in the span of [1, X], u'u is constant and the estimate is the maximum of the log-determinant). Both were status 3.
  • residuals: u = y - rho W y - X b, as e0 - rho e1 of the two OLS fits, whose residuals sum to zero (see the OLS numerics above). GPUGeographicallyTemporallyWeightedRegression

Geographically and temporally weighted regression (GTWR; Huang, Wu and Barry 2010) at a fixed or adaptive bandwidth. Every row is fitted by weighted least squares with kernel weights on the space-time distance sqrt(ds^2 + tau dt^2), where ds is the planar distance, dt the difference of the times in ticks and tau the time scale (the tau of the Python package mgtwr, whose GTWRKernel and GTWR.fit are the oracle). The kernel is Gaussian exp(-z^2 / 2) or bisquare (1 - z^2)^2 with z = d / h, chosen at compile time. bandwidth and timeScale are per-frame (getGPUGTWRParameterValues), so a caller can move through the (bandwidth, timeScale) plane without recompiling. With adaptive: true, bandwidth is an integer count of usable neighbours, including the focal observation and zero-distance ties, from 1 to 128. The local bandwidth is the kth space-time distance multiplied by 1.0000001 (mgtwr convention). A count greater than the usable population, a noninteger count, or a zero kth distance reports SINGULAR. Masked padding never enters the neighbour list.

Set bandwidthSearch: {parameters, maximumIterations} to select both bandwidth and time scale on the GPU. Pack the six per-frame values with getGPUGTWRBandwidthSearchParameterValues({bandwidthBounds: [minimum, maximum], timeScaleBounds: [minimumScale, maximumScale], absoluteTolerance: 1e-3, relativeTolerance: 1e-3}). The outer golden-section search minimizes the time-scale profile; each profile evaluation runs an inner golden-section bandwidth search. Each scalar search evaluates both endpoints and up to maximumIterations interior pairs (default 8, maximum 32). Adaptive bandwidth bounds must be integers in [1, 128]; time-scale bounds may include zero. Equal bounds fix an axis. This is a bounded reference algorithm: the profile is assumed unimodal, and nonsmooth adaptive objectives may have other minima. It does not promise an exhaustive global optimum.

output.selectedParameters optionally receives the winning [bandwidth, timeScale] pair. output.status accepts the canonical iterationCount, converged and iterationLimitReached uint32 ports. The count is outer time-scale comparisons; convergence requires the outer interval and the winning inner interval to meet width <= max(absoluteTolerance, relativeTolerance * max(abs(lower), abs(upper))) (at least one neighbour for the adaptive inner interval). Adaptive interior comparisons use distinct counts whenever possible; the final interval of at most three counts is also considered resolved once every count in it has been evaluated. Limit flags include the winning inner search. Candidates with singular rows or nonfinite AICc cannot win by dropping observations; exact score ties choose the smaller time scale, then the smaller bandwidth. At the limit, the best finite evaluated model is fitted and published. If no finite candidate exists, selected settings are NaN and included rows report SINGULAR; no convergence is claimed. Invalid raw GPU bounds follow the same path. Per-frame settings and bounds do not recompile; row counts, kernel, adaptive mode and budgets are compile-time. estimatedCommandNodeCount includes the nested search and construction rejects combinations above 32,768 commands. Finished searches gate their later fit dispatches on the GPU.

times are float32 ticks after the origin of a temporalContext that declares float32-relative encoding with an origin epoch; the unit is whatever the context declares, and timeScale converts one tick into spatial units squared per tick squared. The local system is solved in coordinates centered on the focal row with the diagonally equilibrated Cholesky factorization shared with the GWR family, so a rank-deficient or ill-conditioned local design reports SINGULAR for that row (NaN coefficients, fitted value and hat) instead of an unstable fit; EXCLUDED marks a masked row or one with a non-finite value. summary has the layout of GPU_GEOGRAPHICALLY_WEIGHTED_REGRESSION_SUMMARY over the non-singular rows: residual sum of squares, trace of the hat matrix, AICc (the formula of GPUGeographicallyWeightedRegression, mgwr aicc: -2 llf + 2 n (tr S + 1) / (n - tr S - 2), NaN when n - tr S - 2 <= 0, so a GWR and a GTWR fit are comparable and a degenerate bandwidth cannot win a profile search; mgtwr's own aicc, -2 llf + 2 (tr S + 1) (n - 1) / (n - tr S - 1), is smaller by 2 n (k + 1) / (n - k - 2) - 2 (k + 1) (n - 1) / (n - k - 1) with k = tr S: 2.15 at n = 200, k = 60), R squared, observation count, singular row count, sigma squared, log-likelihood and included row count.

The fit is exhaustive over rows (O(rows^2 x predictors^2), at most 32,768 rows and 11 predictors), float32 and planar with a native metric (spatialContext, default planar/native; other coordinate spaces are rejected). gtwr-bandwidth-search.spec.ts compares adaptive fits and search AICc with independent NumPy fits and exhaustive grids, including ties, padding, purely spatial bounds, singular/empty candidates and iteration limits. gtwr-mgtwr.spec.ts compares coefficients, fitted values, residuals, hat diagonals and summary statistics with mgtwr 2.0.5 output for four configurations (Gaussian and bisquare, time scale 0, 1.5, 2 and 8) and checks time-shift invariance, a larger time scale changing the fit, rank-deficient designs and masked rows. mgtwr declares no licence, so it is executed as an oracle (test/oracles/gtwr-mgtwr-oracle.py) and no code is copied.

GPUMultiscaleGeographicallyTemporallyWeightedRegression

Multiscale GTWR by backfitting, following mgtwr multi_bws. A GTWR fit at the initial (bandwidth, timeScale) starts the components beta_j x_j (the intercept is component 0). Each iteration visits the components in order and smooths the partial residual beta_j x_j + err with a one-covariate local regression at that component's own bandwidth and time scale, beta_ij = sum_l w_il x_lj r_l / sum_l w_il x_lj^2, updating err before the next component (Gauss-Seidel order). iterationCount (1 to 32) is compile-time and every iteration runs; output.scores holds mgtwr's convergence score sqrt(sum (XB_new - XB_old)^2 / n / sum (sum_j XB_new)^2) for each iteration, so a caller sees where mgtwr would have stopped. Without bandwidthSearch, bandwidths are supplied by the caller (getGPUMGTWRParameterValues). With it, the initial GTWR fit and every component's partial-residual, no-intercept local regression select their bandwidth and time scale using the nested profile search above. Component AICc uses the partial response, residual sum of squares and smoother trace sum_i x_ij^2 / sum_l w_il x_lj^2. adaptive also applies to every component. The search bounds are shared by the initial and component searches. output.selectedParameters has the same 2 + 2 (predictorCount + 1) layout as the input parameters, holding the initial pair and the last pair for each component. output.status sums outer comparisons over all searches, ANDs convergence and ORs limit flags. Backfitting itself still executes its fixed iteration count and publishes its score history. Command-budget validation includes every search, so larger combinations of backfit and search budgets are refused at construction. A row whose initial local fit is singular starts from zero components, and a component smoother whose weighted x^2 sum is not positive leaves a NaN coefficient (status SINGULAR) and contributes nothing.

The spec compares the final coefficients, residuals and the whole score history with mgtwr.function.multi_bws run with fixed per-component bandwidths and time scales for two configurations that converge in five iterations.

See local variability and regression extensions for the expanded statistics, fixed, finite-grid or golden-section-selected multiscale fits, generalized local models, pooled panels and regimes.

MGWR bandwidth selection and limits

GPUMultiscaleGeographicallyWeightedRegression and its GPU/CPU operation forms accept bandwidthSelection: {criterion: 'AICc', searchMethod: 'golden-section', maximumSearchIterations: 30}. bandwidthCandidates then holds two positive finite distance bounds per component, in [interceptLower, interceptUpper, predictor0Lower, predictor0Upper, ...] order, with bandwidthCandidateCount: 2. Equal bounds select a fixed bandwidth; reversed or invalid bounds invalidate the fit. The existing finite-grid mode remains the default, as does the 'leave-one-out' criterion. Candidate/bound values can change per frame.

Each backfit component selects its bandwidth from the scalar regression on its current partial response, following PySAL mgwr multi_bw. For AICc, include the focal observation and compute n log(max(RSS / n, 1e-30)) + n log(2π) + n (n + tr(H_j)) / (n - tr(H_j) - 2). H_j is that scalar partial-response smoother, and n counts complete, unmasked rows. The GPU accumulates power-of-two-scaled residual squares and recovers RSS / n using that included count, so an overflowing intermediate RSS does not reject a representable variance. A nonpositive denominator or any failed local fit rejects the candidate. Grid ties select the first candidate; golden-section ties keep the lower interior point. Golden-section shares GWR's delta = 0.38197 and score tolerance max(1e-6, 4e-6 max(abs(scores))), with at most 64 search iterations. MGWR also evaluates the upper endpoint and keeps it if it is better than the interior winner. A feasible endpoint keeps an initially infeasible interior bracket searchable. If the search budget is exhausted, it returns the better of that endpoint and the last interior winner. The contributor retains OLS initialization (zero with full inference), its relative-contribution backfit stopping rule, and unrounded distance bandwidths; it does not reproduce PySAL's initial single-bandwidth GWR fit, SOC stopping rule, or two-decimal bandwidth rounding.

For the full MGWR model, the trace is tr(S) = sum_j tr(R_j), where R_j is the coupled component response operator propagated through the backfit, conditional on the selected bandwidth history (Li and Fotheringham, 2020, Computational improvements to multi-scale geographically weighted regression). This is the trace in inference.output.summary[0], and each tr(R_j) is in effectiveParameters. Summing independent scalar H_j traces would give a different full-model effective parameter count. Standard errors remain conditional on bandwidth history; bandwidth confidence intervals and full selection uncertainty are not provided.

Planar bisquare and explicitly truncated Gaussian fits automatically use the shared GWR grid at 1024 rows: square dimensions ceil(sqrt(rows / 8)), capped at 1024 per axis. indexGridSize overrides the dimensions, and false forces the dense path. Untruncated Gaussian and great-circle fits retain the dense fallback, including an explicit grid with an untruncated Gaussian kernel. Limits are 65,536 dense rows, 1,048,576 indexed rows, 24 predictors, 128 backfit sweeps, 32 finite-grid candidates and the shared 32,768 command-node budget. The selection score buffer needs rows * candidateWidth * 16 bytes in one storage binding (candidateWidth = 3 for golden-section: two interior points and the upper endpoint), checked against the device limit. Full inference retains its 128-row and cubic-work limits. The CPU twin uses float64 internally. Both backends honor maximumIterations (default 32); finite unfinished fits publish coefficients and predictions with status 3, while inference remains unavailable until convergence. The CPU accepts budgets above the GPU's 128-sweep cap. Near-tied scores can produce different bandwidths within float32 error. Float32 coefficient or prediction overflow produces numerical-failure code 4 and NaN outputs. The optional output.status.componentSearchIterationLimitReached has one flag per design column; it reports any exhausted golden-section search independently of backfit convergence, accumulates across sweeps, and resets each execution. Both operation constructors snapshot their sweep budgets. The website labels finite limit estimates separately from exclusions and failures.

The independent NumPy fixture generator records the initialization and stopping differences and checks scalar selection plus coupled traces.
