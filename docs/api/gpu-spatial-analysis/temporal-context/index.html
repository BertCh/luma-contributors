Temporal context

A GPUTemporalContext declares what a time column means, the way GPUSpatialContext declares coordinates. It is a description only: nothing here converts data. Import it from @luma-contributors/analysis/analysis-core or @luma-contributors/analysis/gpu-spatial-analysis.

type GPUTemporalContext = {
  unit: 'second' | 'millisecond' | 'microsecond' | 'nanosecond'; // ArrowAnalyticsTimeUnit
  epoch: 'unix' | bigint; // bigint: origin as signed Int64 ticks of `unit` after the Unix epoch
  encoding: 'float32-relative' | 'double-single' | 'int64-words';
  timeZone?: string; // as declared by the source; never parsed
  axis:
    | {kind: 'regular'; step: number | bigint | {calendarUnit: GPUTemporalCalendarUnit; interval?: number}}
    | {kind: 'irregular'};
};

unit is also the unit of durations given with the times, such as maximumGap.

Encodings

Encoding Rows Reads Epoch
int64-words One uint32x2 Int64 (low, high) row, two's complement Exact. Take differences on the words with timeWordsDifferenceToF32, then use f32 'unix' or an origin
double-single A float32 high and a float32 low part; the time is their sum About 48 bits 'unix' or an origin
float32-relative One float32, ticks after the origin Exact to 2^24 ticks from the origin An origin; 'unix' is rejected because float32 cannot hold absolute time

0n is the same instant as 'unix'; declare it for times that really are near 1970 or have no calendar meaning.

Resolving and checking

resolveGPUTemporalContext(id, context, support?) validates a context and checks it against what an operation accepts (encodings, units, axisKinds, unixEpoch). There is no default context, because a unit or epoch must be declared. It rejects an unknown unit or encoding, an origin outside Int64, float32-relative with 'unix', an empty timeZone, a non-positive or non-finite step, a fractional step on int64-words, and a bad calendar step.

getGPUTemporalContextCompatibility(source, target) and assertCompatibleGPUTemporalContexts(id, source, target) compare two columns on unit, epoch and encoding. Time zone and axis are not compared: stored instants stay comparable across both. A contributor that needs matching axes checks them itself.

Arrow uploads

makeGPUTimeVectorFromPreparedArrowColumn returns the upload with a temporalContext, and getGPUTemporalContextFromPreparedArrowColumn(column) gives the same context without a device: int64-words, Unix epoch, the column's own unit and declared time zone, and an irregular axis. A signed Int64 column prepared with a declared unit is taken to count from the Unix epoch; spread another epoch over the result if it does not.

What each family accepts today

These contributors take a context. The rest still document their conventions per prop, and the table states them in terms of this contract. A context is always optional where the time view alone fixes the encoding, and it never converts anything: it is checked against the bound views and the operation's support at construction.
