GPU Terrain operators

GPUTerrainDerivatives, GPUTerrainContours, GPUTerrainViewshed, GPUTerrainLineOfSight, and GPUTerrainCumulativeViewshed

Elevation-tile analysis composed from gpu-raster operators. GPUTerrainDerivatives computes Horn slope, aspect, and hillshade (uniform, Web Mercator, or geographic cell sizes) with an optional hillshade texture. Its border pixels use one-sided differences by default (borderMode: 'one-sided'): the surface is extended one cell by the quadratic through the three nearest samples, which makes the difference across the edge the second-order one-sided stencil (-3 f0 + 4 f1 - f2) / (2 h) of luma.gl's GPUFiniteDifference2D, exact on a plane. borderMode: 'clamp' repeats the edge sample instead and halves the gradient across the edge (a plane of slope 11.31° reads 5.71° in its border column); 'reflect', 'constant' and 'nodata' are forwarded to GPURasterGradient. North comes from the grid: rowDirection defaults to the sign of the row term grid.affine[4] (negative: rows advance south), and an explicit value that contradicts the grid throws at construction. The same rule holds for GPUTerrainCurvature, GPUTerrainVectorRuggedness, GPUReliefShading, GPUTerrainHorizon and GPUTerrainCastShadow. Columns are taken to advance east, and on a rotated 'uniform' grid azimuths are measured from the grid's up axis. GPUTerrainContours extracts marching-squares segments for several fixed or per-frame levels with one aggregate overflow flag (output.status.overflow). Every contributor takes a grid (GPURasterMetadata), reads parameters, and writes into an output bag. The grid supplies the width, height, cell size and latitude band, so the packers take it as their second argument. The three visibility contributors share one sight-line model, with cellSizeMode selecting how grid world units become ground meters:

  • GPUTerrainViewshed writes a GPU_TERRAIN_VISIBILITY code (output.visibility, or output.visibilityTexture) per pixel from one per-frame observer.
  • GPUTerrainLineOfSight tests a batch of [observerColumn, observerRow, targetColumn, targetRow] pairs. Optional per-pair heights override the defaults. It writes output.visibility and can also write output.clearance: how many metres the target could sink and stay visible.
  • GPUTerrainCumulativeViewshed makes observers the dispatch dimension, like the gdal_viewshed cumulative mode. It counts, per pixel, the observers that see it (output.visibleCount, optional output.marginalCount), with observersPerDispatch observers per node. It uses the packer of GPUTerrainLineOfSight (getGPUTerrainLineOfSightParameterValues) because the heights, distance, cell size, curvature and tolerance semantics are shared.

All three accept heightReference (default 'ground') and, for absolute observer heights, observerVerticalDatum, checked against the elevation band's verticalDatum. Targets remain ground-relative. See Heights and datums.

const grid = makeGPURasterMetadata({width, height, cellSize: 30});
graph.add(new GPUTerrainDerivatives({
  grid, elevation, parameters: parameters.importToGraph(graph), output: {slope, hillshade}
}));
parameters.write(getGPUTerrainDerivativesParameterValues({azimuthDegrees: 315}, grid));

GPUTerrainContours takes a required grid (its former optional metadata), which also sets pixelInterpretation for the vertex offset, and reports the aggregate flag in output.status.overflow. Each level keeps its own vertices, status (count, optional requiredCount and overflow) and optional draw members.

Each contour level's optional draw record is rewritten on every encoding from the capacity-clamped GPU segment count. drawLayout: 'instanced' (default) writes [verticesPerInstance, segments, 0, 0] for renderers that read segment endpoints from storage (verticesPerInstance defaults to 2; use 4 or 6 for quad-per-segment lines). drawLayout: 'line-list' writes [2 * segments, 1, 0, 0] for one non-instanced line-list draw over the vertices column used as a vertex buffer.

The three sight-line contributors accept cellSizeMode?: GPURasterCellSizeMode: 'uniform' (default) means grid world units are ground meters on a projected planar grid; 'geographic' means a degree grid; 'web-mercator' means an EPSG:3857 grid. The latter two require an axis-aligned affine and use WGS84 ground meters for maximumDistance, curvature drop c·d², tolerance bands, targetIgnoreDistance, and clearance. Elevations and heights must use meters too. A ray uses one constant ground cell evaluated at its middle row, 0.5 * (observerRow + targetRow) + 0.5. Along-ray scale change is ignored, so range boundaries and curvature drops are approximate on long rays, especially at high latitudes; the error depends on the latitude span and ray bearing.

Each sight line joins pixel positions at one-pixel steps with bilinear elevation and ignores samples with an invalid corner. There is no azimuth input and no pixel-direction conversion. Row order comes from the affine, so these contributors have no rowDirection prop. Holding the ground cell constant along a ray preserves the monotone sample distances used by pyramid skipping.

More precisely, for pixel-centre endpoints o and p, set n = ceil(max(abs(p.x-o.x), abs(p.y-o.y))). Test only o + (p-o)·k/n, k = 1, …, n−1; neither endpoint is an occluder. Ground distance is D = hypot((p.x-o.x)·cellX, (p.y-o.y)·cellY) and sample distance is D·k/n. The eye is observer ground plus observer height (unless absolute height is selected). With zero tolerance, a target is hidden only when a sampled apparent slope strictly exceeds the target's apparent slope; equality is visible. Curvature lowers both intervening terrain and the target by c·d², using each one's distance from the eye. Cumulative viewshed sums the visible codes from this same test; hidden, out-of-range and no-data observers contribute zero.

This finite sampling convention can miss relief between samples, including the bilinear hump between diagonally adjacent cells, which have no interior sample. It differs from both GRASS's angular sweep and GDAL's Wang reference-plane propagation. Matching heights, curvature and cell centres alone does not make their native 2D masks equal. For sampler-matched reference testing, resample the DEM along each ray and put sample i at height i·(z(d_i)−eye−c·d_i²)/d_i on a unit-spaced radial raster, with the target last and the observer at height zero. GDAL with observer/target offsets and curvature all zero then tests the identical slopes along one row. This preserves the discrete visibility test exactly; it does not establish equivalence to GDAL on the original 2D DEM.

  • Tolerance band. GPUTerrainViewshed takes an optional per-frame toleranceParameters ([toleranceMeters, tolerancePerKilometer, targetIgnoreDistance, targetIgnoreFraction], all 0 by default, packed by getGPUTerrainViewshedToleranceParameterValues; GPUTerrainLineOfSight and GPUTerrainCumulativeViewshed carry the same four values inside their 12-float layout) that turns the hard cut into a band β = (toleranceMeters + tolerancePerKilometer·D/1000)/D around the target slope. Codes are hidden above T + β, visible at or below T − β, and marginal (4) in between.
  • Ignored final stretch. Samples within max(targetIgnoreDistance, targetIgnoreFraction·D) of the target are ignored. This removes the self-occlusion speckle of targets just behind their own lip; mt-image uses 2 m + 1 m/km and ignores max(150 m, 2 %·d).
  • Traversal. traversal: 'pyramid' builds a min-max GPURasterExtremaPyramid and skips blocks that provably cannot change the code. Results are bit-identical to 'march' (the default).
  • Shared pyramid. Pass pyramid (a GPURasterExtremaPyramidOutput) to reuse one pyramid across GPUTerrainViewshed, GPUTerrainLineOfSight, GPUTerrainCumulativeViewshed, GPUPointHorizonProfile and GPUPointHorizonVisibility. It must cover the same grid with a bilinear footprint. Building one costs 0.3 to 0.9 ms, but the pyramid-skip kernels are still about 2x slower than 'march' for viewsheds, so prefer 'march' there.

With the default 'uniform' mode, all sight-line kernels retain their previous WGSL and variants.

Earth curvature and refraction lower terrain at ground distance d by c·d² with c = getGPUTerrainCurvatureCoefficient(k) = (1 − k)/(2R), R = 6371008.8 m. The default k = 0.13 is the geodetic standard used by mt-image. GDAL's gdal_viewshed -cc 0.85714 is the same model with cc = 1 − k, k = 1/7, so use getGPUTerrainCurvatureCoefficient(1 / 7) to match GDAL. The difference matters little in practice. Changing k by ±0.1 moves a skyline by 0.011°, 0.022° and 0.034° at 50, 100 and 150 km, and k ± 0.3 (inversions) by 0.03–0.10°. GDAL and mt-image differ by Δk ≈ 0.013, about 0.003° at 50 km. Range truncation (120 instead of 150 km: up to 0.28°) and DEM bias (30 m is 0.034° at 50 km) dominate (mt-image measurements).

graph.add(new GPUTerrainLineOfSight({
  grid, elevation, pairs, parameters: parameters.importToGraph(graph), traversal: 'pyramid',
  output: {visibility, clearance}

  curvatureCoefficient: getGPUTerrainCurvatureCoefficient(1 / 7),

GPUTerrainDerivatives

Turns an elevation grid into Horn slope, aspect and hillshade with two Sobel passes and one fused per-cell kernel.

The grid's column and row axes must be orthogonal. Both construction and getGPUTerrainDerivativesParameterValues reject shear with a grid.affine error; resample a sheared DEM first. Rotated orthogonal grids remain supported in 'uniform' mode, with azimuths relative to the grid's up axis. Latitude-dependent cell sizes require axis-aligned grids. Each pixel-axis length must remain positive and finite after float32 conversion. Orthogonality uses the normalized-axis dot product (absolute tolerance 1e-6), so rescaling the affine cannot make shear pass by underflow or overflow.

GPUPointHorizonProfile and GPUPointHorizonVisibility

A 360° horizon profile from any number of observers, ported from mt-image's horizon march.

  • Inputs. The elevation raster is the elevation prop on a grid. Observers are [column, row, height, 0]. heightReference is 'ground' (the default) or 'absolute'. In absolute mode, observerVerticalDatum declares the observer heights' datum and is checked against the elevation band's verticalDatum; see Heights and datums.
  • Outputs. In output, for each (observer, azimuth bin) the profile writes the maximum apparent-elevation tangent t = (h − h0)/d − c·d, the skylineAngle in degrees (−90 when nothing was sampled), and the crest distance. Azimuth bin i is at i·360/azimuthCount degrees clockwise from north. Sectors are set with firstAzimuth and azimuthSpan.
  • Projections.
    • 'planar': projected metres, a straight ray. The packer takes the cell size from the grid.
    • 'web-mercator': a window of the EPSG:3857 grid (square pixels, rows increasing south). The packer derives the world size worldPixelSize = 2πa/cellSize (pixels per 360°, a = 6378137 m) and the Mercator ordinate of the top edge northEdge/a from the grid, so no worldPixelSize or originY is passed. The ray is a piecewise great circle traced on a sphere of R = 6371008.8 m. Breakpoints are baked from maximumLatitude and segmentTolerance, and positions are linear in pixels between them. Distances and azimuths are WGS84 ground metres and ground bearings, by the same rule as the 'web-mercator' row scale of the raster-grid contributors (M cos(lat)/a north-south and N cos(lat)/a east-west per EPSG:3857 metre): a sphere metre along sphere azimuth A is sqrt((N sin A)² + (M cos A)²)/R ground metres at the observer latitude, and a ground bearing T is traced along normalize(M sin T, N cos T). The scale is evaluated once per ray at the observer. Tangents, the curvature drop, the per-frame maximumDistance, targetIgnoreDistance and the distance outputs are ground metres; the topology maximumDistance sizes the sample lattice in sphere metres, so a ray reaches min(1, scale) times that far (0.56% short due north at the equator).
    • getGPUPointHorizonProfileParameterValues(settings, grid) and getGPUPointHorizonVisibilityParameterValues(settings, grid) tag the words with settings.projection (default 'planar'); a contributor whose projection differs reports NaN (profile) or no-data (visibility) instead of misreading them. The lattice cellSize prop stays a topology value: it sizes the distance lattice, and on Web Mercator the true pixel size varies with latitude.
  • Sample distances. Samples sit on an exact power-of-two octave lattice: within [2^k, 2^(k+1)) the step is a power of two following mt-image's step rule max(stepFactor·d, clamp(nearFactor·d, minimumStep, cellSize·cellSteps)), from 20 m out to maximumDistance. Every distance is exact in float32. Specifically, evaluate the step rule at the octave's lower endpoint 2^k, round it down to a power of two, and clamp its exponent to [-8, k]. Keep distances 2^k + j·step inside that octave and the requested inclusive distance range. minimumDistance is in metres (default 20), not cells. Planar distances use both grid cell sizes; the scalar cellSize option controls only this sampling density.
  • Precision. Precision follows mt-image:
    • the eye is held as an integer pixel plus a float32 fraction;
    • heights are taken relative to the eye as a hi/lo pair behind an opaque() guard, against Metal fast math;
    • breakpoint offsets use the cancellation-free bp() with series atan and atanh;
    • azimuth sin/cos use an exact integer octant reduction, and degrees use an accurate atan (the WGSL builtins are only 2^-11 or about 4096 ULP accurate).
  • Traversal. traversal: 'pyramid' (the default) skips min-max pyramid blocks whose conservative bound cannot raise the running maximum. Tangent and distance bits are identical to 'march'. A shared pyramid can be passed as for the viewshed contributors.

For point visibility with zero ignore distance/fraction, only lattice samples strictly before the target contribute to occlusion. The target itself is excluded even when it lies exactly on the lattice. With zero angular and elevation uncertainty, equality is visible. Observer height is added to bilinear observer ground in ground-relative mode; target height is always added to bilinear target ground. Curvature subtracts c·d from both apparent tangents. These denser samples can detect an obstruction that the three coarse sight-line contributors miss. Native GRASS/GDAL masks can therefore differ here too; the radial reference adapter above preserves this sample set as well, including its unequal distance intervals.

GPUPointHorizonVisibility classifies targets [column, row, height, observerIndex] like mt-image's peak classifier:

  • The ray. It marches the full ray along the observer→target bearing. On Web Mercator the bearing and distance come from a cancellation-free spherical inverse, and the distance is then scaled to WGS84 ground metres as above, so a maximumDistance cut agrees with GPUTerrainLineOfSight on the same tile.
  • What it records. It keeps the occluder maximum before q = d − max(targetIgnoreDistance, targetIgnoreFraction·d) and the full skyline maximum.
  • Codes. With tol = toleranceDegrees + σz/d, a target is hidden below the occluder by more than tol, marginal from exactly tol below it up to (not including) tol above it, and otherwise visible. The classes are ordered with no gap between hidden and marginal.
  • Skyline. onSkyline is set when the target is within skylineToleranceDegrees of the skyline.
  • Details. The optional output.details holds [targetElevation°, occluderElevation°, skylineElevation°, onSkyline].

Measured against float64 oracles, the elevation error is at most 3.3e-5° (planar) and 3.0e-5° (Web Mercator).

GPUTerrainRGBDecode and GPUTerrainSpikeRepair

These contributors turn RGB-encoded elevation tiles into float32 heights with uint32 validity.

GPUTerrainRGBDecode handles two encodings:

  • Terrarium: R·256 + G + B/256 − 32768.
  • Mapbox terrain-RGB: −10000 + 0.1·(R·65536 + G·256 + B).

It reads either an rgba8unorm texture (with textureLoad) or a buffer of packed little-endian RGBA8 words, which is getImageData().data viewed as a Uint32Array. It writes heights and validity. A pixel is nodata when any of these hold, and nodata pixels hold NaN bits and validity 0:

  • its alpha is 0;
  • it matches the optional noDataRGB;
  • the optional input validity marks it invalid;
  • its height falls outside validRange (default [-11000, 9000] m, which removes blank-canvas pixels).

clampBathymetry is opt-in. It flattens heights in (−12000, 0) to sea level, which also flattens the Dead Sea and polders.

Decode before you filter. Never sample the encoded texture bilinearly or through mips, because filtering byte channels mixes carries. Decode with nearest/textureLoad, then resample the float heights.

Terrarium decoding is bit-exact in f32 for all 2^24 codes: every partial sum is a multiple of 1/256 below 2^16. Mapbox decoding is one correctly rounded multiply, f32(N − 100000) · f32(0.1). Its error is at most ½ulp + |M|·1.5e-9, which is below 0.6 mm for |h| ≤ 9000 m.

GPUTerrainSpikeRepair is opt-in. grid holds at most getGPUTerrainSpikeRepairMaximumCellCount(device) cells (4194304, 2048 × 2048 on a default device), because the per-component vote bit counts take 32 bytes per cell in one storage binding. It fixes ±256·k m Terrarium red-byte errors, such as canvas anti-fingerprinting noise:

  1. It labels 4-connected components across edges with |Δh| ≤ jump, using the analysis-domain weak-component kernel (bounded minimum-label propagation with pointer jumping) on a fixed-stride grid CSR. A label is the lowest pixel index of its component.
  2. A component that is neither the largest nor bigger than 25 % of the valid pixels is shifted by −step·k when at least 80 % of its border seams agree on a jump of step·k ± tolerance.

Run it on full-resolution decoded heights, before any filtering. Nodata is never filled or repaired. It can shift a real enclosed butte whose walls happen to measure 216–296 m, so enable it only when the source is known to be noisy.

GPUTerrainPeakProminence

Computes elder-rule prominence of every peak of an elevation grid, entirely on the GPU, from a join tree of sorted saddle edges.

::lens{scenario=gpu-terrain.terrain-peak-prominence rung=result caption="Prominence per cell in metres; the most prominent finite peak is marked, the elder peak is infinite."}

Computes eight-connected upper-excursion-set prominence (zero-dimensional persistence): a peak dies at the highest saddle connecting its component to an elder peak, and prominence is peak height minus that saddle. Higher peaks are elder; equal heights prefer the lowest cell index. Plateau members and nonpeaks have zero prominence except for the plateau's representative. Nodata is a barrier and receives NaN. Each disconnected component's surviving peak has infinite prominence and a key saddle of negative infinity; the boundary has no artificial sea level.

The GPU sorts the depression-fill spill graph's neighbor edges by descending saddle, then builds a join tree with the parallel parent-splicing helper shared by HDBSCAN. One label per cell preserves peaks inside tiles that the fill-only outlet contraction would erase. Cycle edges create unary nodes; gated ancestor doubling propagates elder peaks in logarithmic dispatch depth, and each binary merge records one losing peak. Stable saddle-edge ordering preserves parentPeak ties. There is no CPU readback or fallback. Contended splices can traverse long chains; performance measurements are pending. Storage is linear and the maximum grid size is getGPUTerrainPeakProminenceMaximumCellCount(device): the child table requires 40 bytes per cell per binding (3,355,443 cells on a 128 MiB binding limit), compared with the previous serial implementation's 16 bytes per cell. GPUTerrainSummits, GPUTerrainPeakSnap, GPUTerrainCriticalPoints, and GPUProfilePeaks

These contributors find terrain features. Summit and snap discs are metric: the packers read the cell size and latitude band from the grid they are given (per frame), in uniform, web-mercator or geographic mode, evaluated at the centre row. Nodata never contributes a height.

GPUTerrainSummits marks pixel p as a summit when all of these hold:

  • p is the strict (height, −index) maximum of its radius-r disc;
  • drop = h_p − max(ring) ≥ minimumDrop, where the ring is the disc pixels with an 8-neighbour outside the disc. Every path leaving the disc crosses the ring, so drop is a radius-limited lower bound on prominence.

Under incompleteNeighborhood: 'reject' (the default), discs clipped by the grid edge or touching nodata are rejected. output holds an optional summitMask, an optional per-pixel drop, an optional compact list summits with an optional summitDrop column, and status.radiusClamped, set when the radius was clamped to maximumRadiusPixels.

Cost is O(R) per candidate pixel in the disc radius R (pixels), not O(R²): the maximum test descends a 'cell'-footprint max pyramid (first block 2) and reads the maximum of every block that lies wholly inside the disc, and the ring is visited from per-row half-widths. A 3×3 pre-test rejects almost every pixel first. The optional pyramid prop reuses a prebuilt GPURasterExtremaPyramid.output (footprint: 'cell', incompleteNeighborhood: 'ignore' only); results are bit-identical to the previous full disc scan.

GPUTerrainPeakSnap takes at most getGPUTerrainPeakSnapMaximumCandidateCount(device) candidates (6710886 on a default device), because it keeps five result words per candidate in one storage binding. It moves caller candidate points, given as [column, row], to the highest valid pixel within a per-candidate or per-frame radius. It keeps the original point in four cases:

  • the maximum lies on the disc ring (a flank, not a summit);
  • the move would exceed maximumMove;
  • the height would change by more than maximumHeightChange;
  • there is no valid data.

Each candidate gets output.snapStatus from GPU_TERRAIN_PEAK_SNAP_STATUS, beside output.positions, output.heights and the optional output.snapDistance. mt-image's distance rule min(250, 60 + 0.004·d) m can be supplied through candidateRadii.

Optional candidateHeights supplies absolute catalogue elevations. candidateVerticalDatum requires candidateHeights and is checked against the elevation band's verticalDatum; see Heights and datums.

GPUTerrainCriticalPoints classifies each pixel as regular, peak, pit, saddle, boundary or noData by counting sign changes around its ring. Equal heights are ordered by index (simulation of simplicity). There are two rings:

  • 8 is the classic Peucker–Douglas ring.
  • 6 is the Freudenthal triangulation, which keeps the Euler relation peaks − saddles + pits consistent.

output.classes is required; output.signChanges (per pixel) and output.counts (per class) are optional.

GPUProfilePeaks finds peaks along 1-D profiles in CSR spans, for example GPURasterProfile sampleValues + lineSampleOffsets, or a horizon profile with wrap: true. For each candidate it:

  • tests for a local maximum over ±2 samples;
  • computes windowed topographic prominence;
  • refines the position with a parabola.

Non-maximum suppression within suppressionRadius runs in GPU rounds (at most maximumSuppressionIterations) and reaches exactly the greedy (prominence-descending) result. If it does not converge, output.status.converged is 0, undecided candidates carry the GPU_PROFILE_PEAKS_UNRESOLVED_* sentinels and optional output.peaks.status.candidateOverflow is 1. output.peaks.status.overflow reports final peak-list capacity only. The optional output.status.iterationLimitReached is 1 in that case. minimumProminence is set per frame and minimumSide at compile time.

The CPU twin and operation forms honor the same explicit suppression budget (default 16). Both operation forms capture that budget and their declared output maps once at construction, including inherited getters. Later JavaScript property mutations do not change the operation. Display only peakMask === 1 as a kept peak; the unresolved mask sentinel means suppression is incomplete and must qualify a peak-count readout.

The three mask states are 1 kept (measured prominence), 0 absent (NaN prominence), and 0xffffffff undecided (+Infinity prominence). Undecided rows are not drawable peaks. The terrain explorer counts every kept peak in its chart and readout; its 64-marker limit applies only to map markers. A truncated suppression run is labeled incomplete. CPU rows are visited in source order within a round; the GPU may decide a different subset at a small budget because its atomic updates happen in invocation order. Both suppress unresolved rows from the compact result and mark candidate loss. The old overflow bit-2 constant is replaced by GPU_PROFILE_PEAKS_CANDIDATE_UNCONVERGED (value 1).

Cells within skipRadius + 1 of the border are invalid, as in GRASS. A line of sight with no valid sample after the skip gives digit 0 (flat) in every mode, where GRASS anglev2 gives +1 from its initial ±90° angles. Outputs forms, ternary, pattern and outputValidity go into output. The flatness threshold, flatDistance and zFactor are per-frame settings (getGPUGeomorphonsParameterValues(settings, grid) takes the cell size and latitude band from the grid); searchRadius and skipRadius size the line-of-sight loops and are compile time. North comes from the grid: rowDirection defaults to the direction grid.affine[4] states (negative: rows advance south) and an explicit value that contradicts the grid throws. It fixes the digit order of pattern; forms and ternary are mirror-invariant and do not depend on it.

The instance's searchRadius is advisory for tiling: it measures row-based ground distance, and east-west reach exceeds it when north-south cells are larger than east-west cells. Cell sizes can change per frame. Geomorphons exposes no requiredHalo and cannot be supplied directly as a GPURasterHaloStage; the caller must bound both axes over every row and parameter update.

GPUTerrainTopographicPosition and GPUTerrainWeissLandforms

GPUTerrainTopographicPosition evaluates any number of square scales (up to 64) in O(1) per pixel from one summed-area table: TPI over the annulus (innerRadius, radius], the deviation from mean elevation (DEV) over the full window, and Lindsay et al.'s (2015) DEVmax with the radius at which it occurs. A float32 summed-area table cannot do this: on a 512×384 tile at 3800 m its window means are off by 5.4 m. Elevations are instead quantized (quantum, default 1/256) into an exact 64-bit modular table built with GPUScanUint64, GPUScan, and GPUTranspose; variances are formed relative to the centre cell in integer arithmetic. Measured: TPI within 2.2 mm (the quantization) and DEV within 2.4e-4 of the float64 definition, and within 4.6e-6 m / 7.3e-7 of the quantized oracle. Windows are clipped to the raster and to valid cells.

GPUTerrainHorizon, GPUSolarShadowMask, GPUTerrainCastShadow, GPUSolarIrradiance, GPUReliefShading, GPUTextureShading, and GPUSolarPosition

Cartographic relief and terrain light in data space, for "sun and shadow" maps on DEM tiles. Every style and sun value is a per-frame parameters write; none of them recompile the graph. Each class takes the raster grid (its width and height size the kernels; the cell size and the latitude band of the packers come from it), packed parameters, and a caller-owned output bag. Outputs are float32 rasters, each with an optional r32float or rgba32float storage texture (channel 0); validity outputs are named outputValidity.

  • GPUTerrainHorizon marches directionCount (4 to 64) azimuth sectors per pixel, one node per sector, over a baked step schedule (maximumRadius pixels, optional geometric stepGrowth) with bilinear samples, z factor, earth curvature, and an optional ground maximumDistance. It writes a pixel-major horizon map (horizon[pixel * directionCount + sector], degrees, sector d at azimuth d * 360 / directionCount), the sky-view factor 1 - mean(sin(max(h, 0))), and positive openness mean(90 - h), all in output. Sky-view-only use needs no output.horizon buffer. There are two sky-view factors and they are not interchangeable. output.skyViewFactor is the solid-angle factor of Zakšek et al. (2011), 1 - mean(sin(max(h, 0))): the visible fraction of the hemisphere, made for relief visualization. output.irradianceSkyViewFactor is the cosine-weighted factor of Dozier and Frew (1990) for a horizontal receiver, mean(cos²(max(h, 0))): the fraction of isotropic diffuse irradiance received, which is what GPUSolarIrradiance needs. A uniform 30 degree horizon gives 0.50 and 0.75; an infinite plane of slope s gives (1 + cos(s)) / 2 in the second. The irradiance factor is reduced from the horizon map (the quantised one when output.horizon is 'unorm16', error below 3e-5; a transient float32 map when output.horizon is not bound). Sector azimuths are ground azimuths on any cell shape: on anisotropic cells ('geographic' off the equator, or non-square grid cells) each ray's pixel step is normalize(groundDirection / groundCell) at the pixel's own row, so a 45 degree sector at 60 N steps about two columns per row instead of along the pixel diagonal (a 26.6 degree ground ray). The cell size is not re-evaluated along a ray; at 60 N and 30 km that leaves a 0.25 degree bearing and 0.14% distance error. Options:
    • algorithm: 'sweep' replaces the per-pixel march with an exact upper-hull sweep (Stewart 1998 style) over digital lines through pixel centres: amortised O(1) per pixel and sector, equal to brute force over the same samples, 4x faster at radius 256 and 36x at full-tile radius on 1024² (16 sectors). It is nearest-pixel sampling of the ray, not an exact horizon of the surface: each sample takes the elevation of a pixel centre on the digital line, whose lateral offset from the ray through the pixel's own centre is below one pixel (up to 0.86 px at line slope 0.3), and its distance is measured along the ideal ray (k · hypot(1, slope) cells), not to that centre. A sample one cell ahead and 10 m higher on 10 m cells reads 41.8° at line slope 0.5, where centre-to-centre geometry gives 45.0° (side neighbour) or 35.3° (diagonal). Sky-view factors differ from the bilinear march by about 0.01 on rough terrain. The sweep has a large fixed cost per pixel and sector: it wins at large radii (1024² at radius 1023: 41 ms against about 1300 ms; 512² at full radius: 36 against 109 ms) and loses at small ones (512² at radius 128: 60–125 ms against about 20 ms). Prefer the march for small radii and the sweep near the full tile radius. One line family has one pixel slope, so on anisotropic cells the sweep uses the ground cell of row height / 2 for every row; on a 'geographic' tile the other rows see sectors rotated by up to about tan(lat) * halfSpan / 2 radians (0.44 degrees at the edges of a 1 degree tall tile at 60 N). For mosaics, select parameterLayout: 'sweep' and pack sweepOrigin: [column, row] in settings to anchor digital-line phase relative to the common sweepSourceGrid. Placement and reference cells update per frame without changing shader source. A level number does not determine exact anisotropic downsampling; supply overview pixel coordinates. Standard settings keep the local sampling model and refuse a sweep halo even when their view has spare capacity.
    • horizonFormat: 'unorm16' halves the horizon map (two 16-bit codes per uint32, 0.00275 degree steps, code 0 = nodata; unpackGPUTerrainHorizonUnorm16 decodes on the CPU). GPUSolarShadowMask and GPUSolarIrradiance read it.
    • output.negativeOpenness is openness of the inverted DEM (Yokoyama), and output.anisotropicSkyViewFactor is RVT's weighted SVF 1 - sum(w sin h+) / sum(w), w = (1 - wMin) cos((a - A)/2)^level + wMin, computed exactly as RVT's sky_view_factor_compute. anisotropyAzimuthDegrees (A) uses RVT's direction convention, so the same number means the same direction as RVT's asvf_dir: angles run counterclockwise from north (90 west, 270 east), and the default 315 is RVT's default, which is compass north-east. a is each sector's RVT angle, (360 - t) mod 360 for compass sector azimuth t. anisotropyLevel is RVT's integer a_poly_level with RVT's signed power (presets: low 4 with minimum weight 0.4, high 8 with 0.1). Parameter slots 8-10 hold them per frame (parameters must then hold 12 floats). This is the only counterclockwise angle in gpu-terrain; sun azimuths already match RVT's compass shadow_az. In compass terms, independent of RVT: the sector at compass azimuth (360 - A) mod 360 gets the largest weight, so A = 315 weights the north-east sky and A = 90 the west. This is checked against unmodified rvt-py 2.2.1 (test/oracles/terrain-sky-view-rvt.py): RVT direction i has angle i * 360 / n and looks at the pixel offset (-cos, -sin) * r over (rows, columns) of a north-up array, which is counterclockwise from north; a wall to the north, west, south, east or north-east of a pixel darkens it most at A = 0, 90, 180, 270, 315, in RVT and here, on north-up and rows-north grids. RVT does not wrap a - A, so odd levels are not periodic in A; the kernel follows.
    • Agreement with RVT in numbers: RVT samples whole pixels (1 to the radius on the axes, (k, k) on the diagonals, a rounded staircase in between, each at its centre-to-centre distance) and reflect-pads the array by the radius. Where the kernel reads the same samples (the march with 4 sectors, the sweep with 4 or 8, any plane with up to 8) the sky-view factor and the anisotropic factor agree with RVT to 3e-7 and both openness outputs to 3e-5 degrees, away from the edge band. Otherwise the two differ by sampling, not by definition: on a plane of gradient 0.5 with 16 sectors the march equals the closed form (openness 90), RVT reads a sky-view factor 0.022 and an openness 3.3 degrees lower, and the sweep 0.019 and 2.6 degrees lower. Inside the edge band a ray here stops at the edge, where RVT sees mirrored terrain.
    • Breaking change: anisotropyAzimuthDegrees used to be a compass azimuth, so the default 315 weighted the north-west sky. It now weights the north-east sky, as RVT does. To keep a previous compass azimuth t, pass (360 - t) mod 360. Non-integer levels now throw.
  • GPUSolarShadowMask reads the horizon map and a per-frame sun: it interpolates the horizon at the sun azimuth and writes output.sunVisibility, the solar-disk area fraction above the horizon (soft penumbra from the disk's angular radius, hard when 0). With slope and aspect from GPUTerrainDerivatives it also writes output.illumination = ambient * svf + sun * sunVisibility * max(cos(incidence), 0). horizon, slope, aspect, and skyViewFactor are inputs. One frame costs two reads per pixel.
  • GPUTerrainCastShadow casts one sun's shadow with no horizon map: an exact sweep along the per-frame sun azimuth gives the horizon in that direction, then the same solar-disk penumbra as GPUSolarShadowMask; it writes output.sunVisibility, output.horizonAngle, and output.outputValidity. The CPU packer getGPUTerrainCastShadowParameterValues(settings, grid) computes the line geometry, so moving the sun never recompiles. The packer also stores the sun's ground direction and takes no row direction or cell size mode: the contributor mirrors the line for its rowDirection: 'north' and, on anisotropic cells, turns the direction into a pixel slope with its own cellSizeMode and the ground cell of row height / 2. Use it when only one sun matters and a full horizon map is too large. This middle-row model is local to the window. Seamless mosaics require explicit parameterLayout: 'sweep', shared source-grid/reference settings, and per-frame window origins; getHaloStage() then returns the chosen radius. Standard settings refuse a halo claim even with a padded parameter view. See the cast-shadow API section below for its 32-value layout. The sweep follows a Bresenham-style digital line family through cell centres, rather than bilinearly sampling an arbitrary continuous azimuth. For native r.sunmask -z parity on finite square metric grids, use cardinal azimuths, positive altitude, zero curvature, angularRadiusDegrees: 0, and a radius covering the whole domain. The comparison then reduces, away from exact grazing, to max((z_i-z_0)/d_i) > tan(altitude). The GPU hard step requires altitude > horizonAngle, so equality is shadowed; GRASS requires terrain strictly above the solar ray, so mathematical equality is sunlit. Exact grazing therefore needs a separately specified tie convention. The -z flag makes GRASS include zero-elevation terrain. Other azimuths can use different digital lines; this is a sampling difference, not a floating-point error allowance.
  • GPUSolarIrradiance integrates a sun path over a horizon map: output.sunHours (disk-visible hours) and output.insolation (Wh/m², direct normal irradiance times visibility times cos incidence, plus an optional diffuse term diffuseIrradiance * skyViewFactor * duration). Bind the horizon's output.irradianceSkyViewFactor as skyViewFactor, not its solid-angle output.skyViewFactor, which understates diffuse energy (50 instead of 75 Wh/m² for 100 W/m² over one hour under a uniform 30 degree horizon). The diffuse term is for a horizontal receiver: slope and aspect enter the direct term only, and no (1 + cos(slope)) / 2 factor is added because a horizon measured on the same terrain already contains the receiver's own slope. Terrain-reflected radiation is not modelled. getGPUSolarIrradianceSunTable samples getSolarPosition over a day or a date range (Meinel clear-sky DNI with Kasten–Young air mass by default). samplesPerNode splits long tables across dispatches.
  • GPUReliefShading computes a hillshade from up to 8 lights with fixed weights or the USGS multidirectional oblique weighting (lights: 'mdow', per-pixel sin^2(aspect - azimuth) as in GDAL -multidirectional). It writes output.hillshade, and blends a Swiss/Imhof relief (output.relief luminance and packed RGBA8 output.color, plus output.outputValidity) from the hillshade, an optional sky-view factor, an optional texture shade, an elevation tint ramp of up to 8 stops, and a warm-lit/cool-shaded aspect tint. Imhof options: lightWeighting: 'imhof-swing' (with the imhofSwing: true prop) swings each light toward the slope's side by up to imhofSwingDegrees (default 65), an optional curvature raster adds curvatureStrength * curvature, and contrastStrength with contrastLowElevation/contrastHighElevation raises contrast with elevation. Zero values keep the previous output bit for bit.
  • GPUTextureShading approximates Leland Brown's texture shading (fractional Laplacian |f|^alpha) with a cascade of separable Gaussian levels (sigma_k = baseSigma * 2^k) summed as weighted band differences. Nodata uses normalized convolution. detail (alpha), the band weights, and gain are per frame; it writes output.textureShade and output.outputValidity. hasNodata: false (default true) promises an all-valid elevation and blurs one channel instead of value plus validity, which is exact and about halves the blur cost. downsampleLevels (default true) computes levels with incremental sigma of at least 4 pixels on a 2x decimated grid and upsamples bilinearly; output stays within 1% of the exact output range (measured 0.1-0.27%), and false restores the exact full-resolution cascade.
  • GPUSolarPosition evaluates the NOAA solar position for every row of a longitude/latitude column at one per-frame instant. It has no grid (it takes positions): parameters holds the time and output the azimuth, altitude (with optional refraction), and a daylight flag. getSolarPosition is the float64 CPU version used to drive the shadow mask. Both use the NOAA daily spreadsheet's Meeus-based approximation, without observer parallax, rather than NREL SPA. NOAA's published accuracy is about one minute for sunrise/set within ±72° latitude and ten minutes outside; NOAA does not give a universal 0.01° angular guarantee. Float32 orbital-angle error increases with time from J2000, and azimuth is ill-conditioned near zenith/nadir. Time is transported as separate whole days and day fraction. daylight compares geometric sun-center altitude with a strict > threshold (default −0.833°), independently of the optional refraction applied to altitude. GPUSimpleLocalRelief, GPUMultiScaleRelief, GPULocalDominance, and GPUReliefBlend

Archaeological and micro-relief visualizations with Relief Visualization Toolbox (RVT; Kokalj and Somrak 2019) parity. The float64 test oracles follow RVT-py's formulas, including edge padding, NaN handling and Python's half-even rounding.

  • GPUSimpleLocalRelief (SLRM; Hesse 2010): ve * (z - mean(z)) over a (2r + 1)² window with edge-clamped coordinates and nodata excluded. On grids up to getGPUTerrainSummedAreaMaximumCellCount(device) cells (about 3344 x 3344 on a default device) the mean is an O(1) box query over an exact 64-bit summed-area table of elevations quantized to quantum (a power of two, default 2^-16), with RVT's edge replication applied as edge-strip weights and the deviation formed from exact integers; the error against RVT is at most quantum / 2 (zero for |z| >= 128) plus a few float32 ULP, at any radius up to 23170. The GPU selects the first finite valid elevation, snaps it to the quantum, and subtracts it before building the table. Only offsets from that anchor of magnitude 2^31 * quantum or more (32768 by default) are invalid; absolute elevation is unrestricted. Larger grids use a separable O(radius) filter with anchored, centre-relative sums, so any radius keeps sub-millimetre precision at alpine elevations. The radius is a per-frame setting: maximumRadius (compile time) sizes requiredHalo and bounds the loops, and getGPUSimpleLocalReliefParameterValues({radius}) picks any integer in [1, maximumRadius] per frame with the same pipelines (an omitted radius uses maximumRadius).
  • GPUMultiScaleRelief (MSRM; Orengo and Petrie 2018): RVT's radii from resolution, featureMinimum, featureMaximum and scalingFactor (getGPUMultiScaleReliefRadii). RVT's sum of consecutive low-pass differences telescopes, so the contributor runs only two mean filters, which share one summed-area table on grids within the cell cap (same quantum option and bounds as SLRM). cellSizeMode (default 'uniform', unchanged square windows) accepts 'geographic' and 'web-mercator' on axis-aligned grids: the RVT index ladder is unchanged, each nonzero radius k^s becomes k^s * resolution ground metres, and every row converts it to rectangular pixel half-widths with its WGS84 ground cell (rounded, at least 1). The summed-area path evaluates these rectangles exactly; the separable path (large grids) averages rows filtered with their own horizontal radius. requiredHalo is the largest coarsest half-width over all rows.
  • GPULocalDominance (Hesse 2016): the mean dominance of the observer (observerHeight above the cell) over an annulus of baked shifts. Distances are in pixels, as in RVT.
  • GPUReliefBlend (VAT): up to five float32 layers, bottom to top, each stretched clamp((x - min)/(max - min)), optionally inverted, and blended (normal, multiply, screen, overlay, soft light, luminosity) with an opacity. Presets GPU_RELIEF_BLEND_VAT_ARCHAEOLOGICAL (hillshade; slope 0-50° inverted, luminosity 50 %; positive openness 68-93°, overlay 50 %; SVF 0.7-1, multiply 25 %) and GPU_RELIEF_BLEND_VAT_FLAT. Feed it from GPUReliefShading, GPUTerrainDerivatives and GPUTerrainHorizon. Percent-clip stretches need a histogram, so pass min and max (for example from GPURasterStatistics).

At 1024²: SLRM r=20 takes 3.3 ms, MSRM at radius 100 takes 5.4 ms, local dominance with the RVT defaults (264 taps) takes 84.5 ms, and a four-layer VAT blend takes 1.2 ms. All style values are per-frame parameters. Each contributor takes grid instead of width and height and writes into output (relief, dominance, blend, color, and outputValidity); the blend layers stay an input. The blend layer limit is GPU_RELIEF_BLEND_MAXIMUM_LAYER_COUNT and the local dominance offset limit GPU_LOCAL_DOMINANCE_MAXIMUM_SHIFT_COUNT.

GPUTerrainFlow

Turns an elevation grid into filled elevation, D8 directions, cell classes, upstream-cell accumulation and a stream mask.

::lens{scenario=gpu-terrain.terrain-flow rung=result caption="Upstream cells per cell after the fill; the outlet with the most upstream cells is marked."}

Hydrology on an elevation tile: optional Planchon–Darboux depression filling with a per-frame epsilon, D8 flow directions (ESRI codes, cell-size-aware diagonal distances, uniform, Web Mercator, or geographic cells) with flat, pit, and outlet classes, flow accumulation in cells or ground area optionally weighted by a per-cell runoff view, and a stream mask with a per-frame threshold. With fillEpsilon 0, filling is a tiled spill graph (Barnes 2016): tile-local fill with outlet labels, a Borůvka spanning tree of the spill graph, and bottleneck paths to the grid boundary, in O(log n) gated GPU rounds whatever the basin shape, bit-identical to the Planchon–Darboux fill (and to pysheds fill_depressions); output.status.fillIterationCount then reports Borůvka rounds. The 32 × 32 fill tile requires 12,320 bytes of workgroup storage: three 4,096-byte arrays and two flags, each rounded to 16 bytes under WebGPU's limit calculation. Devices below that limit use 16 × 16 tiles, requiring 3,104 bytes of workgroup storage. The fill is the greatest solution of W = max(Z, min W(n) + epsilon), the minimax elevation to the boundary. With fillEpsilon 0 that equation has lower solutions too (any level between a pit and its pour point), so a relaxation restarted from a stale surface is not guaranteed to reach the fill; both paths here start from above and reach it. A fillEpsilon above 0 selects, per frame on the GPU, the GPU-gated tiled min-relaxation, which is also used on grids whose 8 · (cells + 1) bytes exceed one storage binding. D8 'cells' accumulation without runoff is tree contraction on the Euler tour of the receiver forest: every cell enumerates its children in fixed direction order, and gated pointer jumping ranks the 2 n tour edges in ceil(log2(2 n)) + 1 rounds, so a cell's count is an exact integer (written as float32) for any stem length and maximumAccumulationIterations does not apply. Weighted accumulation (runoff, 'area') and the other routings are a deterministic pull over dependency order with downstream walking, bounded by maximumAccumulationIterations. Everything stops early on the GPU and reports convergence flags, so nothing is read back and accumulation is bit-reproducible. maximumFillIterations and maximumFlatIterations default to 512 (up to 1024); after 96 plain tiled iterations each phase adds directional row and column sweeps so serpentine and spiral basins converge. Check output.status.fillConverged and output.status.flatsConverged for longer ones. The optional one-row outputs output.status.fillIterationCount, output.status.flatsIterationCount (the sum of the three flat relaxations) and output.status.accumulationIterationCount report the iterations executed, including the final unchanged one, so a budget can be tuned (the SF terrain used 14 of 256 fill and 2 of 128 accumulation rounds). Every unrolled loop has one gate node per four rounds; rounds after convergence inside a group are idempotent no-ops, so results and counts are unchanged and the graph has about a third fewer nodes.

The grid supplies the width, height, cell size and latitude band, so the settings carry only the algorithm values (fillEpsilon, streamThreshold, flowExponent) and the packer takes the grid as its second argument. The grid may be rotated but not sheared: GPUTerrainFlow, GPUTerrainHydrologicIndices and GPUTerrainFlowFractions measure the diagonal D8 step as sqrt(x² + y²) of the two cell sizes, so they throw at construction when the two pixel axes of the affine are not orthogonal, as GPUCostDistance does.

When maximumAccumulationIterations runs out on the pull path, unresolved cells keep NaN accumulation, and their streams word is GPU_TERRAIN_FLOW_STREAM_UNRESOLVED (0xffffffff), never 0: the unresolved cells are the downstream trunk, so 0 would silently drop the main river. Every consumer of a stream mask (height above drainage, stream order, stream network, flow distance, the catchment summary and tiled flow) reads it the same way: a nonzero word is a stream cell, so a mask of Strahler orders works too, and the unresolved word is a cell of unknown status, never a stream cell. GPUTerrainHeightAboveDrainage and GPUTerrainStreamOrder propagate the unresolved word.

const grid = makeGPURasterMetadata({width, height, cellSize: 30});
graph.add(new GPUTerrainFlow({
  grid, elevation, parameters: parameters.importToGraph(graph), fillDepressions: true,
  output: {flowDirections, accumulation, streams, status: {fillConverged, accumulationConverged}}
}));
parameters.write(getGPUTerrainFlowParameterValues({fillEpsilon: 0.01, streamThreshold: 500}, grid));

Weighted and non-D8 accumulation walks downstream after each publication for at most 1024 steps (TERRAIN_FLOW_MAXIMUM_WALK_LENGTH). That is a performance cliff, not a correctness limit: a drainage path longer than 1024 cells needs further gated rounds, so convergence within maximumAccumulationIterations (default 64, at most 1024) can fail on very long unbranched stems and leaves their cells unresolved (NaN). Exact D8 'cells' accumulation without runoff uses an Euler tour and is not affected.

resolveFlats: true routes flow across flats without changing elevations (Barnes, Lehman, and Mulla 2014). Hop distances toward the flat's draining edge and away from its higher edge are GPU relaxations over equal-height cells. Each drainable flat cell drains to the equal-height neighbor whose 2 * towardLower + (flatMaximum - awayFromHigher) is strictly lower. Pair it with fillDepressions and fillEpsilon: 0 to drain filled depressions as true flats; output.status.flatsConverged reports the three relaxations. flowRouting selects how accumulation and streams split flow: 'd8' (default), 'd-infinity' (Tarboton 1997 facets), 'mfd-freeman' (Freeman 1991, tan(beta)^p, p = 1.1) or 'mfd-quinn' (Quinn et al. 1991, contour-length weighted, p = 1). Set p per frame with flowExponent. Non-D8 accumulation uses the same deterministic pull, with each donor's fraction recomputed from the surface, so it is reproducible bit for bit. flowDirections and cellClasses stay D8.

flatContinuation opts into 64 rounds per pass per execution (override with maximumFlatIterations). Supply lower, higher, and maximum, each with a zero-initialized uint32 state of getGPURasterRelaxationContinuationStateLength(grid) words and a float32 values view with one element per cell. All six views must be distinct imported buffers, since transients can alias between executions. Completed stages stay frozen; the maximum pass starts only after the higher-edge distances converge. status.flatsIterationCount is cumulative across executions. Outputs retain the unresolved contract until all three stages converge. Keep inputs unchanged while resuming, or set GPU_RASTER_RELAXATION_RESTART_WORD in any stage state to restart all three. The execution after complete convergence also restarts all three, as cost distance does.

Outputs may share one buffer over disjoint byte ranges. For example, status.fillConverged and status.accumulationConverged can be two one-row views of an 8-byte summary buffer. Outputs that one pass writes together (filledElevation, flowDirections and cellClasses; accumulation and streams) must start in different 256-byte binding windows. No output may share a buffer with an input.

GPUTerrainHeightAboveDrainage, GPUTerrainWatersheds, GPUTerrainStreamOrder, and GPUTerrainHydrologicIndices

Products derived from GPUTerrainFlow outputs. Each takes a grid and D8 flowDirections, plus streams or accumulation where needed, and writes into an output bag. The direction codes are ESRI by default (1 east, then powers of two clockwise), which is what GPUTerrainFlow, ArcGIS, pysheds and WhiteboxTools with --esri_pntr write. A grid from another tool needs the compile-time directionEncoding prop: 'whitebox' for the WhiteboxTools default pointer (1 north-east, then powers of two clockwise) and 'taudem' for a TauDEM D8 grid (1 east, then 2 to 8 counter-clockwise). Without it a Whitebox grid is read 45 degrees off with no error, because all its codes are valid ESRI codes, and most TauDEM codes are read as terminal cells. In every encoding 0 is a terminal cell, 0xffffffff a cell without data and 0xfffffffe an unresolved direction, so map the tool's own no-data value to 0xffffffff.

Direction codes are raster offsets, not compass bearings. In every encoding "south" means the next row (row + 1), "north" the previous row and "east" the next column. No hydrology class reads the row sign of the grid affine (grid.affine[4]), and GPUTerrainFlow writes its flowDirections by the same rule, so producer and consumers agree on any grid. On a north-up raster (rows advance south), which is how ArcGIS, WhiteboxTools and TauDEM write their grids, the names are true compass directions. On a grid whose rows advance north, code 4 of GPUTerrainFlow points geographically north. A tool's direction grid held with its rows flipped to advance north still carries the tool's compass codes and would be followed mirrored north to south with no error: flip the rows back, or exchange the north and south codes, before passing it in.

GPUTerrainFlowDistance, GPUTerrainStreamNetwork, GPUTerrainCatchmentSummary and GPUTerrainTiledFlow take the same prop. The inputs of the four products stay inputs; the convergence words are output.status.converged, output.status.iterationLimitReached (1 when the cap ran out before convergence) and output.status.iterationCount, and the iteration caps are maximumIterations.

  • GPUTerrainHeightAboveDrainage: HAND (Rennó et al. 2008), the height of each cell above the first stream cell on its D8 path, with an optional output.drainageCells index output. A path that first meets an unresolved stream word gives NaN and GPU_TERRAIN_DRAINAGE_UNRESOLVED. It also accepts D-infinity fractions; the HAND guide defines the fractional recurrence, branch-contamination rules, drainage codes and mode-specific budgets.

  • GPUTerrainWatersheds: labels every cell (output.labels) with its nearest downstream pour point (nested pour points give nested watersheds). Without pour points it labels drainage basins by their outlet or pit cell.

  • GPUTerrainStreamOrder: Strahler order on the stream mask (output.streamOrder), with an optional output.status.iterationCount. Unresolved stream words and the stream cells below them keep the unresolved order 0xffffffff.

  • GPUTerrainHydrologicIndices: computes, from contributing area in m² (accumulationUnits: 'area', any routing), into output.slope, output.specificCatchmentArea, output.wetnessIndex and output.streamPowerIndex:

    • specific catchment area a = A / b;
    • topographic wetness ln(a / tan β);
    • stream power a · tan β;

    with tan β the D8 descent slope clamped to a per-frame minimumSlope (default 0.001).

HAND and watersheds resolve D8 paths by GPU pointer jumping, which needs about log₂(path length) gated rounds. Stream order is Strahler by levels on the Euler tour of the stream forest: one list ranking, then per level a scatter, a prefix scan (GPUScan) and a gather, at most floor(log2(n)) levels, each gated on the GPU; maximumIterations bounds only the pull rounds used when the 2 n tour words exceed one storage binding (grids above 4096 x 4096 cells), and status.iterationCount reports the ranking rounds. A receiver cycle (caller-supplied directions only) leaves every cell of its component at 0xffffffff and clears converged. Every iterative contributor stops early on the GPU and can publish output.status.converged.

Chain the contributors by wrapping a flow output with makeGPURasterBand(view, grid) where a downstream contributor takes a band (the elevation of HAND and the hydrologic indices); the direction, stream and accumulation views feed the other inputs directly.

::lens{scenario=gpu-terrain.terrain-flow-field rung=result caption="Wind speed from an 8 m/s south-westerly; slopes facing the wind slow it."}

Capped loops and compile cost

  • A loop stopped by its iteration limit never writes a value that reads as converged (library rule 9): unresolved cells carry NaN or a *_UNRESOLVED constant, see each contributor's TSDoc.
  • A loop index never reaches WGSL text: gated rounds, horizon sectors, cumulative-viewshed batches, point-horizon chunks and jump-flood steps read their position from a GPU word, so every iteration of a kernel shares one pipeline (default GPUTerrainFlow with fill and flats compiles 15 relaxation pipelines, not about 60).
  • GPUTerrainCumulativeViewshed sizes each dispatch to about 2^28 sight-line samples (GPU_TERRAIN_CUMULATIVE_VIEWSHED_SAMPLES_PER_DISPATCH); a large grid splits one observer across dispatches.
  • GPUPointHorizonVisibility stops the occlusion test one ground pixel before the target by default; mt-image's 150 m is GPU_POINT_HORIZON_MT_IMAGE_TARGET_IGNORE_DISTANCE.
  • GPUSimpleLocalRelief and GPUTerrainVectorRuggedness compile for maximumRadius and read the window radius per frame from parameters, so changing the radius does not recompile.
  • D-infinity and MFD accumulation compute each cell's routing once (routing-prepare) instead of re-deriving every donor's facets in every round.
