Analysis modules

@luma-contributors/analysis is an extension of luma.gl. It holds only the geospatial and analysis operations; the GPU infrastructure they run on (GPUCommandGraph, GPU Core operations, GPUData/GPUVector/GPUTable, GPU Dataframe, GPU Graph Algorithms, GPU Project, GPU DGGS, GPU Trace, physics and simulation, renderers) is owned and documented by luma.gl. Operations here are built from the public @luma.gl/core, @luma.gl/shaders and @luma.gl/graph APIs.

Run your first computation

The CPU variogram walkthrough fits generated data without a GPU. Follow it with the complete point-density GPU walkthrough to create a device, allocate views, submit work, read typed results and release resources.

Entries

Entry Use it for
@luma-contributors/analysis/gpu-spatial-analysis Spatial weights and statistics, joins, density, cells, lines, geometry, trajectories, and regression.
@luma-contributors/analysis/gpu-network CSR network analysis: reachability, service areas, accessibility, flow aggregation, and edge bundling.
@luma-contributors/analysis/gpu-terrain Elevation-tile analysis: slope, contours, viewshed, hydrology, solar shadows, and relief shading.
@luma-contributors/analysis/raster-analysis Raster analysis: fill nodata, tile reprojection, fractional coverage, focal pairs, spectral indices, regions, contours, and statistics.
@luma-contributors/analysis/dataframe-analysis Analysis contributors over luma.gl GPU Dataframe columns: profiles, group statistics, joins, and standardization.
@luma-contributors/analysis/geospatial-analysis Geospatial contexts, datum grid transforms and point buffers layered on luma.gl GPU Project.
@luma-contributors/analysis/pointcloud-analysis Point cloud neighborhoods, features, ground classification, registration, and change.
@luma-contributors/analysis/computation-record Recorded executions of a computation as plain data, for the lens views.
@luma-contributors/analysis/analysis-core Shared kernels and contracts used by the analysis entries.

Conventions

Contributors declare work on a caller-owned GPUCommandGraph and return command nodes; callers own the frame loop, command submission and readback. Entries are WebGPU-first; individual pages state backend, capacity and precision limits.
