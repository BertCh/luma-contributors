# Kepler with resident luma compute

This example mounts the actual Kepler 3.3.0-alpha.18 application. A Kepler table factory routes native filters to `@luma.gl/kepler`, and native Point, Line, Arc and GeoJSON layer overrides render borrowed GPU geometry through `@deck.gl-community/gpu-layers`. Deck owns the WebGPU device and submission; the compute effect encodes selection before rendering in the same frame.

All workflows live in Kepler’s existing UI. There is no separate luma support panel:

- **Layers → Analysis** selects a dataset, field, operation and population. Classification, standardization, rates, clustering, interpolation and spatial statistics share this entry point; outputs remain available in native layers and tables.
- **Add Data → Prepare data** opens Arrow files, prepares native datasets, assigns geometry roles and offers sample datasets. **Add Data → SQL** prepares query results through the same publication workflow.
- Datasets opened with Kepler **Load Files** (CSV, GeoJSON, Arrow and saved maps) are prepared automatically. Each native dataset is materialized once with exact column types (integers beyond 32 bits become exact category labels, never rounded numbers), coordinate, geometry, H3, S2/geohash/A5 and trip roles are read from its native layers (or from Kepler's field and point-pair detection when it has none), Float64 fields use a documented Float32 rounding policy with measured error, and the resident dataset replaces the native one under the same ID so its layers, filters and tooltips are kept. The roles, precision policy and any excluded fields are listed under **Automatic preparation** in the sidebar header; a failure leaves the native dataset untouched and says why. `?autoPrepare=0` restores the manual flow: select **Add Data → Prepare data → Prepare <dataset>**, assign roles, check schema and precision, then publish (unprepared native layers then show a preparation notice instead of running incompatible WebGL filter shaders on the WebGPU map).
- **Filters**, native time playback, layer styling, legends and **Charts** remain the controls for their respective tasks.
- **Share → Export Data** exports selected source or analysis values directly. **Share → Export Map** saves and restores configurations or portable workspaces directly.
- **Share → Export Image** uses Kepler’s native PNG preview, filename, aspect ratio, resolution, transparency, legend and chart options. Capture reuses the current WebGPU device and resident buffers.
- Native map popovers inspect one resident row or aggregate cell. Device recovery and status appear in the existing sidebar header.

`src/native-workflows.tsx` binds host workflows to Kepler’s injected factories. Extend the owning workflow when adding functions: new analysis operations belong in Layers, source adapters in Add Data, and output formats in Export Data. The GPU session remains independent of component mount/unmount; changing native tabs does not upload source buffers again. `scripts/native-navigation.mjs` provides the matching browser-test entry points.

Image export temporarily renders the existing map at the requested size, snapshots submitted Deck and basemap canvases, and composes the native overlays. It restores the live viewport after capture, cancellation or failure. Output is bounded to 8,192 pixels per side and 16 megapixels; captures time out after 30 seconds. Remote basemaps must permit canvas export through CORS. Capture failures appear in the native preview; the exporter does not substitute a placeholder map. The focused `scripts/native-image-export.mjs` workflow checks downloaded pixels and retention of the device and source uploads.

From the repository root:

```sh
nvm use
yarn install
yarn workspace luma.gl-examples-kepler-compute start
```

Open `http://localhost:5318/` in a browser with WebGPU. `?rows=10000` changes the deterministic fixture size (default 100,000; maximum 1,000,000). The background map is local and requires no token or network tiles.

The initial source is an Arrow table imported through `KeplerComputeSession`. Scalar source columns stay resident across numeric, categorical, and minute-of-day controls. The additional Arrow Timestamp column retains exact signed 64-bit time words; select it in Kepler’s native Filters tab to compile millisecond controls to exact GPU time windows. Filtering, distributions and playback use Kepler’s native controls. Each native histogram excludes only its own filter ID, including when multiple filters target the same field. Per-layer spatial masks are independent; native table and analysis selection use Kepler’s targeted-layer union, including hidden targets. Inspection reads a bounded page or one hovered source row. Analysis supports population selection, standardized values and classification, GPU colors, bounded summaries, and saved recipes.

The table bridge deliberately reports unsupported execution rather than scanning source rows for a plausible substitute. Kepler still retains its original CPU source rows for ingestion and application compatibility. This example does not claim arbitrary Kepler layers, exporters, or arbitrary SQL execute on the GPU. The optional DuckDB-WASM panel runs SQL on explicitly registered retained source Arrow and publishes a result as a native resident table only when requested. The prepared-result workflow also supports explicit coordinate roles and precision choices. GPU display selection does not silently alter the SQL relation.

Native Group By now has a bounded resident execution path wired to the original panel; GPU and full native workflow qualification is still pending. It groups all source rows independently of map filters, using one unordered string dictionary key and up to 16 count/sum/average/minimum/maximum measures. Count includes null measure rows; the other methods require prepared Float32 numeric fields and produce null for all-null groups. Null keys form one group, and groups follow first source occurrence. Float32 arithmetic is the declared numerical policy, with nonfinite numeric inputs or results rejected. Limits are 1,000,000 source rows, 4,096 dictionary slots including null, 1 MiB key text and 4 MiB materialized results. Zero measures produces distinct keys. Unsupported configurations remain editable with explicit SQL guidance; SQL is never an automatic fallback.

Group By publishes a separate table-only result, adopts its dedicated GPU output buffers, and retains bounded result Arrow for inspection, export and recovery. It does not upload the result again or repack the original source. Native output field names, analyzer types and historical lineage survive portable bundles. Completed results are independent snapshots and remain usable after source removal; pending work is cancelled when its source or operation changes. Native Join (attribute) runs a bounded resident executor when both inputs are resident: LEFT, INNER and FULL joins on one key, with native row order (left order, duplicate right matches in right order, unmatched right rows appended for FULL), exact-string key matching in which null and empty keys never match, and native output naming (right columns prefixed with the right dataset label, collisions suffixed). Keys are prepared string dictionaries or Int32/Uint32/integral-Float32 numbers compared by their native `String(value)` form; a Float32 key must be an integer within ±16,777,216 because a non-integer cannot be proven to equal the original number. Keys are canonicalized, sorted and matched on the GPU, with a 16-byte summary read back before allocation; payload values and validity are gathered on the GPU into dedicated buffers and published as a separate table-only result with bounded Arrow, lineage and portable-bundle persistence. No input or output row cap (uint32 row indices, memory reservation and device limits apply), 32 output columns; Int32, Uint32, Float32 and dictionary-string payload columns only, with empty inputs or results refused. Native Spatial Join runs a bounded resident executor for published longitude/latitude points (left) against a published polygon or multipolygon column (right) with the intersects (boundary included) and within (boundary excluded) predicates. It returns one row per left row in left order with the left geometry fields, a matched-polygon count and Count/Sum/Average/Minimum/Maximum aggregations of right numeric fields (nulls skipped, null when nothing is defined). `GPUSpatialPredicateJoin` produces the pairs under an explicit Float32 policy: polygon vertices are rounded to Float32 like the resident points, so a point within Float32 resolution of an edge can classify differently from native double geometry, and uncertain classifications, candidate or pair overflow (at most 1,048,576 pairs) and mixed or invalid polygon rows are refused. No point, polygon, vertex or pair cap; points join in chunks of 1,048,576 on one prepared polygon index. Other predicates (equals, crosses, overlaps, touches), H3, polygon-left or point-right geometry, and Median and Count unique aggregations are rejected with SQL guidance. Merge of the polygon geometry column (the panel default) is a bounded CPU step: the GPU join's matched pairs are read back (counted, at most 4,194,304 pairs) and unioned with native `mergeGeometries` semantics (none give null, one keeps its geometry, several polygons or several multipolygons become one MultiPolygon, a mix a GeometryCollection) into a GeoJSON Feature string column. It needs a result of at most 262,144 rows and is refused above that with an uncheck-merge message; the other aggregations stay on the GPU. Join and Spatial Join never fall back to SQL or retained rows. Native Suitability (the pinned 3.3.0-alpha.18 operation: numeric fields with weights in [0, 1], range or z-score standardization, normalized or raw weights, a null score when any weighted value is missing; it has no constraints or rasters) runs a bounded resident executor over one resident source. The weighted columns are read back once, packed row-major and scored by `GPUCompositeScore`; its per-column statistics are read back (a few bytes) to refuse constant columns, which native leaves unstandardized but the scorer would zero. The score and the carried columns are published as a separate table-only result in source row order with native naming (carried fields, then a real score field with unique naming), `derivedDataset` lineage and portable-bundle persistence. Scores are Float32 (integers beyond ±16,777,216 are refused), and raw weights scale the normalized score by the weight total. Raw data standardization, weights outside [0, 1] or all zero, non-numeric fields, more than 16 weighted fields, constant weighted columns, and weighted fields missing in different rows (scorer statistics cover rows where every field is defined, native statistics cover each column) are refused with guidance. Limits are 16,777,216 rows (kernel limit), 32 output columns and memory reservation, with Float32, Int32, Uint32 or dictionary-string carried columns and empty inputs refused. Cancelled or stale runs publish nothing. GPU and native browser qualification is pending. Mixed resident and nonresident inputs are rejected with SQL guidance; ordinary nonresident operations keep their native behavior. This host owns one device and one Deck. Dual and Swipe split maps (up to two views) draw both viewports in that Deck from the same resident buffers, each half keeping its own basemap; `?views=1` forces the original single-view host, which rejects split and swipe actions and restored configurations before allocating a second view or replacing workspace sources. Each view has its own view state, so unlocked (unsynchronized) split viewports, per-view hover, click and pan/zoom, labels and elevated points work in both halves; closing either map keeps the Deck and device. Wheel zoom pivots at the pointer in each view, pitched and rotated maps and GlobeView (one seamless globe in Swipe, one per view in Dual) split correctly, touch pan and pinch work per view, the native polygon draw tool and Select Geometry operate in either view, and Swipe or Dual state (divider, per-map layers, unsynchronized viewports) is kept inside exported portable bundles.


## Additional sources

The Resident datasets panel opens Arrow IPC files or prepares datasets loaded through native Kepler Add Data. It previews selected fields, nullability, dictionary encoding and measured Float64 conversion error before upload. Longitude/latitude roles are explicit; leaving them empty creates a table-only dataset. A separately selected GeoJSON/GeoArrow column retains geometry independently of scalar normalization. Source names, row identities and Arrow batch boundaries are preserved, and native Arrow compaction is disabled for this host. Native row ingestion is explicitly bounded.

Multiple resident datasets coexist with the fixture. Each has its own native filters, GPU table pages, source revision and optional map layer. Mixed GeoJSON point, line and polygon primitives gather masks and styles from original feature rows. Source replacement and native deletion retire consumers and style resources before releasing geometry or source storage. Stale SQL previews cannot be committed. Saved state records all resident source manifests. Portable bundles explicitly include retained source Arrow for another session; reference-only URL links reconstruct only the fixture. Bundle restore completes schema, normalization and coordinate/geometry validation before replacing sources. GPU allocation failure during replacement is not an atomic rollback to the previous workspace.


## Resident geometry and styles

`resident-layers.ts` registers native Kepler layer types, so changing the layer selector uses the same GPU source buffers and selection mask. Its resolver declares the exact uploaded coordinate columns, precomputed geometry bounds, source-feature identity and optional GPU visual-channel results. The sample supplies point and connection coordinates; the publication workflow prepares GeoJSON paths, polygon fills/outlines and multigeometry source mappings once during ingestion. Every geometry vector and mask must retain the same source-feature row order and chunk boundaries. Multigeometry expansion must preserve empty source rows or provide an explicit feature-to-source identity mapping and aligned feature mask.

The overrides bypass native row formatting, metadata scans and tooltip accessors for resident datasets, including Kepler's `hasLayerData` rendering gate. Unregistered datasets retain native behavior. Constant colors, opacity, point meter radii and billboard setting, connection thickness, arc source/target colors, and GeoJSON fill/stroke visibility and opacity follow native controls. Native color and size field controls resolve to revisioned GPU style plans with bounded native legends; changing coordinate columns requires a matching geometry binding. Unsupported resident types and configurations are hidden with a diagnostic. Grid and hexagon overrides use separate resident aggregation adapters with native cell-assignment contracts, scoped GPU reductions, classification, and aggregate-cell inspection.

This is a planar geometry path. GeoJSON polygon extrusion preserves XYZ and independent height/base-offset fields, embedded property defaults, offset-only modes and wireframe rendering. Prepared feature metadata exposes native Height, Fill and Radius controls without scanning original rows. Point outlines and connection endpoint colors use explicit resident channels. Paths use resident previous/next vertices for native miter joins and cap controls; Trips uses rounded joins/caps and an explicit native timing mode. Optional analytic antialiasing has a documented bounded edge-coverage difference from native Deck; the default is disabled. The implementation verification document distinguishes primitive checks from completed native UI workflows.

Ordinary point layers support bounded scalar text labels through the native label field, size, color, font weight, anchor and alignment controls. Labels preserve original row masks and source batches, including empty batches and missing strings. Field/font changes prepare a private bitmap atlas and glyph layout once; filtering and display controls reuse those buffers. Native trilinear atlas sampling and radius offsets are retained. The admission limits are 100,000 source rows, 4,096 batches, 256 Unicode scalars per label, 250,000 glyphs, 512 distinct characters and 8 MiB of source preparation. Timestamp formatting, rich values, multiline text, collision avoidance, backgrounds, SDF outlines, globe and labels on other layer families remain unsupported. The native browser workflow verifies visible glyphs, labels without point fills, same-layer style buffer reuse, null/filter behavior and fenced field replacement; primitive comparisons separately verify native bitmap rasterization.

Under Deck GlobeView, resident point, line, arc, icon, point label, GeoJSON, H3, Trips, heatmap and grid/hexagon/cluster aggregate layers project through the shared project module and cull at the horizon (verified by `scripts/globe.mjs`). The WGSL `GPUGlobeDepthDiskLayer` replaces Kepler's GLSL depth disk so far-side basemap tiles are depth-occluded; the GLSL atmosphere and halo layers remain omitted. GeoJSON long edges follow Deck's globe preparation: when the viewport carries a globe resolution the host derives, once per published source, a globe variant of the prepared geometry (antimeridian longitude unwrapping, linear 5-degree edge subdivision of paths and outlines, and polygon cuts on a 5-degree grid) from the retained source, reserved in the memory registry and released with the publication; source rows, batches and picking are shared with the planar geometry. Aggregate cells are preprojected Web Mercator and are inverse-projected in the shader, so their float32 precision is that of the common-space coordinates. The globe heatmap frames the density texture from the data bounds (or the padded visible region when zoomed in) and drapes it over a tessellated sphere mesh with the native ramp and threshold mapping. Line and arc layers draw native target arrowheads (shape, pixel size and target color) through `GPUArrowHeadLayer`, which derives each head from the borrowed source/target buffers and orients it to the final projected segment; globe heads follow the great-circle tangent; altitude is not covered. Resident point, line, arc, path and polygon layers highlight the hovered primitive in the fragment stage by comparing its picking id with Deck's highlighted id, using the native `highlightColor` and disabled while brushing. Highlights follow primitive ids, so a GeoJSON feature highlights only the hovered primitive; inspection uses the resolver's source-row callback and bounded GPU readback. Pickable layers retain the renderer's explicit 16,777,215-feature limit; larger sources must be split into picking batches. The resolver borrows all vectors, and owns no source or mask buffer lifetime.

## Resident heatmap

The planar heatmap adapter retains the pinned native WebGPU density framing, zoom controls, maximum reduction and color ramp. Its weight pass reads borrowed source chunks and the layer selection mask, with no CPU attribute generation or row readback. A missing weight field contributes one per valid point. Prepared Float32 weight fields use native linear, square-root or logarithmic DOMAIN scaling into `[0, 1]`; null weights contribute zero while retaining native MEAN count semantics. Selection changes reuse source and normalized output buffers. Density runs in the compute effect after selection and weight encoding, before the display pass. Readiness waits for the current density revision and a successful display draw, including during native image capture.

Admission requires blendable `rgba16float` textures at the native 512×512 resolution, and the host reserves working memory and holds source leases through retirement. Heatmaps do not provide source-row picking. Globe mode uses the native data-bounds density frame and a WGSL sphere mesh; other weight scales are explicitly unsupported. Native half-float accumulation limits still apply. The pinned WebGPU kernel differs from Kepler's GLSL-only heatmap overrides; this adapter targets the installed WebGPU path. Focused GPU and native browser acceptance are tracked separately in the implementation document.

## H3 cells

Select an H3 index column to retain exact Uint64, bigint, hexadecimal-string or decimal-string identities. Number inputs are rejected because they cannot preserve H3 identity. Initial preparation validates cells and builds variable boundaries once, preserving source batches, missing rows and invalid-row diagnostics. Invalid cells retain their table rows and omit geometry. GPU positions use Float32 coordinates: the preview reports measured center/boundary rounding, and cells whose boundaries collapse at that precision reject the source before publication. Exact IDs do not imply Float64 geometry precision.

Native H3 controls choose canonical polygon boundaries or the viewport-centered column footprint using the pinned Kepler/deck.gl rules. Geometry selection observes the native CPU-equivalent filter population; ordinary GPU range filters do not silently change that branch. The column footprint follows the native ten-kilometer center cache. Fill, outline, coverage, height and extrusion consume resident masks and visual-channel outputs. Native high-precision polygons ignore mapped coverage, matching the pinned renderer. Polygon selection uses the cell center with native open-boundary containment; fill and outline picking retain the original source row.

## Timed paths

Select a geometry column and enable **Timed paths (Trips)** to publish one GeoJSON LineString per source row with `[longitude, latitude, altitude, time]` vertices. Timestamp encoding, optional epoch-millisecond origin, and maximum Float32 time error are explicit. Source timestamps and batch boundaries are retained; GPU times are relative to the admitted origin. Invalid paths retain their source table rows and are omitted from rendering, and a source with no valid paths is rejected.

The native Trips layer registers its prepared animation domain without rescanning source rows. Native playback, trail length, mapped colors and widths, scalar/time filtering, and source-row picking use resident buffers. Interactive playback can produce fractional timestamps, so an exact zero-error policy may reject an intermediate frame; choose an explicit positive budget when needed. Saved source manifests and portable bundle restore retain the policy. Polygon selection targeting Trips remains unsupported until its native spatial predicate is audited. Native Trips scenegraph markers (gallery or custom glTF/GLB URL) render through `GPUTripMarkerLayer`: the model is fetched once with loaders.gl (images included) and post-processed by `@luma.gl/gltf`, and Deck's `ScenegraphLayer` draws it with native `_lighting: 'pbr'` and `_animations: {'*': {speed: 5}}`, so textures, PBR materials and glTF animations render. Each marker's position, heading (or roll/pitch/yaw datum fields) and color are evaluated by compute passes on the GPU at the current animation time (a binary search over the resident, retained-origin timestamps) into the instance buffers `ScenegraphLayer` reads, so playback, scalar/time filters and grouped-trip filtered path copies never touch the CPU. Native `sizeScale`, adjust roll/pitch/yaw, invert flags, model angles/scale and the marker color (constant, trip color, or the table-mode per-timestamp color at the bisected vertex) apply. Roll, pitch and yaw datum fields read published numeric columns gathered per vertex (grouped tabular trips only, as native datums exist only there; a field without a published numeric column reports a reason and leaves trails only). The globe projection is not covered here. Native has no multipart timed trajectory either (its trip detection samples the first coordinate's fourth component, which a MultiLineString does not supply), so multipart timed paths stay unsupported by design, as do implicit timestamp inference and tabular grouping outside the explicit ID/time/lon/lat roles. Native H3 polygon-branch hover brushing runs per vertex in the solid-polygon and path shaders (visibility is interpolated and discarded below 0.5, like Deck's `brushing_isVisible`).

## Compatibility boundary

- `vite.config.ts` resolves this repository's luma 10 sources and one Deck 9.4 family. It uses the repository's existing patched Deck core package.
- Kepler's public application table factory and component injector provide the table and map-container seams.
- `kepler-compute-transform.ts` patches the pinned Kepler `updateFilterPlot` function before its internal calls build CPU row-index arrays, and preserves numeric categorical domains during native restore. The same source hook runs in the development dependency optimizer and production transforms. It validates the expected source shape and fails on upstream drift. A stable upstream asynchronous plot adapter would remove this patch. For filters linked across datasets, the hook composes plots per dataset: each resident table writes its own bins, native code computes any CPU datasets, and a time plot without a complete plot type receives native's default (the interval chosen for the merged domain) once for every dataset. Native draws a line chart for the first dataset only; a resident first dataset reduces a Float32 y axis per time or numeric bin on the GPU over the same keys as the histogram. Numeric range plots use native's edges: the d3 `ticks` thresholds of the filter domain (the merged domain of linked datasets) or the configured numeric interval, computed on the CPU and applied by exact comparisons of the stored Int32, Uint32 or Float32 words, so resident and CPU series share their edges, the zero-width bin at an upper tick and d3's treatment of nulls (compared as zero) and NaN (outside every bin). Average, sum, minimum and maximum stream through a grouped dataframe reduction. Median (d3's linearly interpolated 0.5 quantile) and standard deviation (d3 `deviation`, the square root of the sample n-1 variance, computed by `GPUGroupStatistics` as a corrected two-pass reduction) are exact: rows are stable-sorted by bin, so they cost a declared 96 bytes per row of working memory and are limited to 4,194,304 rows. Null and non-finite y values are skipped as d3 skips null and NaN (so infinite y values differ from d3, which keeps them); a bin with no value has no median, and one with fewer than two has no deviation. Grouped series (`plotType.groupBy`) on a prepared string dictionary field (at most 4,096 labels, 20 groups plus Others) rank labels by their first (bin, row) on the GPU as native discovers them, then count and reduce per series; the native builder draws the chart from those values. Numeric and boolean group fields, other native aggregations (mode, variance, unique count) and y fields that are not Float32 are reported unsupported. `scripts/native-linked-filters.mjs` drives the native synced-dataset selectors with two resident datasets and one CPU dataset against native oracles (bin edges and counts, numeric intervals, every line aggregation, grouped series); `scripts/native-numeric-charts.mjs` checks the same edges, intervals and median/deviation series on a published range filter.
- The `compat` modules preserve real upstream math 5 and compression 4/5 implementations where Kepler's dependencies still import older exports. They are migration adapters, not replacement algorithms.
- The native map editor applies a GLSL-only `PathStyleExtension` dash to every sublayer. The host replaces it with `EditorWGSLDashExtension` (`src/editor-dash-extension.ts`), which injects WGSL into Deck's path layer on WebGPU (segment-relative `widths` dashes, butt/round caps, gap picking; no `dashJustified`, `dashMode: 'path'` or offsets; hard dash edges; only path sublayers). If a shader/pipeline error is raised the extension is disabled and later editor layers fall back to solid strokes. The WGSL anchors are text matches on Deck 9.4's `path-layer.wgsl` and are checked by `modules/kepler/test/editor-dash-extension.node.spec.ts`; browser verification is pending.
- Kepler's distance fog and surface fog run as WGSL shader passes (`src/effects-wgsl-fog-passes.ts`, `src/effects-wgsl-effects.ts`) and Light & Shadow is replaced by a plain Deck `LightingEffect` with the same lights; shadow maps are not rendered on WebGPU (Deck's shadow module is GLSL-only) and a visible message says so. Other GLSL-only effects are skipped with a visible message (`src/effects-webgpu-policy.ts`); the 15 image post-processing effects use `@luma.gl/effects` WGSL. Effect state is untouched, so saved settings round trip.
- `src/basemap-context.ts` manages an optional external MapLibre style URL: failures keep the local background and all data, report a message and preserve declared attributions. It is exposed through the dev test hook (`setBasemapStyleUrl`, `getBasemapState`); `src/basemap-picker.ts` registers a validated style in Kepler's native map-style picker (hook `addBasemapStyle`) and `src/basemap-attribution.ts` shows the active style's attribution. `src/tile3d-diagnostics.ts` backs the 3D tile checks in `scripts/tile3d-effects.mjs` (hooks `getTile3DDiagnostics`, `pickTile3D`, `getDeviceResourceCounts`, `getEffectReplacements`).
- Source precision is explicit: this fixture uses float32 coordinates/values, uint32 category codes, exact minute offsets, and Arrow millisecond timestamps with UTC metadata. The time adapter rejects unsafe or lossy native endpoints; it never casts epoch timestamps to float32.
- Source ingestion, resident graphs, spatial masks, analysis and aggregate resources use explicit registry reservations. Larger fixtures may exceed the configured device/session budget and fail visibly.

The development-only `window.__keplerComputeTest` hook drives native actions and bounded readback for `scripts/smoke.mjs`. Production builds omit it.

The analysis panel selects a resident dataset and a prepared Float32 field. Z-scores with sample or population variance, deviation from mean, mean absolute deviation scaling, range adjustment, range standardization, quantiles, equal intervals and natural breaks use either all valid rows or the dataset's current selected population. Multiple source batches contribute to one global calculation using explicitly reserved GPU working memory; source batches remain unchanged, and result colors and table fields retain their original row alignment. Analysis is allocated on demand for published datasets. Exact natural breaks requires at most 1,024 total source rows and reserves its quadratic workspace explicitly; approximate refinement remains available for larger sources. Other numeric storage formats and additional analysis families are not yet exposed by this panel.

Excess risk selects event and population fields and computes observed / expected from the pooled ratio of their totals. Both fields' validity masks apply before pooling; missing values and nonpositive populations are excluded. The same all/selected population control determines the reference population. Results stay aligned with source rows, appear in the native table, and retain both input fields in saved recipes. Zero expected counts produce NaN; finite negative event values retain the underlying contributor's documented behavior.

Rate summaries distinguish rows included in the result summary, defined outputs, undefined outputs and source rows excluded by the combined mask. The mask combines input validity and, when applicable, selection and coordinate/geometry validity. An included row can still produce an undefined result, for example under an invalid denominator or island policy; these counts do not identify individual causes. Defined outputs can include infinity, which triggers a visible range warning. Coordinate and polygon exclusions describe the whole source and may overlap the combined exclusion count. These diagnostics reuse the existing compact GPU summary without additional readback.

Spatial rates use explicitly selected Float32 coordinate columns and binary source-wide weights: directed k-nearest neighbors (1–32 neighbors, the default), or every other valid point within an inclusive distance band in meters. Distance bands support up to 65,536 source rows and explicitly reserve 1–1,048,576 directed neighbor slots. A pair consumes two slots. Insufficient capacity prevents map/table publication and reports the required slot count; it never silently drops neighbors. In geographic mode, the radius search includes neighbors across the antimeridian; Float32 rounding can affect points near the radius boundary. Geographic mode uses spherical great-circle distances with longitude within ±180° and latitude within ±90°. The graph covers all coordinate-valid source rows. Rate-input validity and selected-population filters remove observations without refilling their neighbor slots. Each rate pools its own events/population with eligible neighbors and applies the configured scale; islands are undefined or use their own rate. Invalid coordinates always produce undefined results. Recipes preserve coordinate roles, metric, topology kind, neighbor count or radius/capacity, rate scale and island policy, and replay preflights all four input fields. Compact diagnostics report links and invalid coordinates; source batches stay unchanged.

Point rates, hot spots, Local Moran and Quantile LISA also support already-projected XY coordinates in meters. Choose projected mode explicitly, bind prepared Float32 X/Y fields, declare the CRS identity, and provide inclusive source-wide bounds in that coordinate space. Distances are Euclidean in the supplied coordinates; CRS metadata is a declaration, not a reprojection or CRS-database validation. Missing, nonfinite and out-of-bounds coordinates are excluded and counted. Bounds and radius must admit finite Float32 squared distances. The same kNN, distance-band capacity and inference limits apply. Saved recipes and cache identity retain X/Y roles, CRS and bounds; geographic recipes keep their original shape. Float32 rounding of large false eastings or northings can lose short separations, and the host does not recenter or transform the source.

Projected coordinates affect analysis only. Map layers continue to use separately prepared longitude/latitude or geographic geometry. A source containing only projected XY can produce table analysis without acquiring an invented geographic position; provide geographic display geometry when a map overlay is needed.

Point hot spots apply the existing Getis–Ord contributor directly to the original point rows and the same binary kNN or distance-band weights. Configure minimum eligible neighbors, self weight, multiple-testing correction and whether isolated points remain in the global moments. Isolated points never receive a score. Self weight 1 gives Gi*; 0 uses the contributor's Gi convention. Inference is analytic and two-sided. The native table exposes z-scores, unadjusted p-values, corrected significance bins and eligible-neighbor counts. Selection removes observations from the fixed graph without finding replacement neighbors. Separate diagnostics report invalid coordinates and eligible rows whose scores are undefined.

Local Moran's I uses original point rows and the same cached binary kNN or distance-band graph. Explicit controls select minimum neighbors, island treatment, significance level and multiple-testing correction. Inference defaults to a two-sided normal approximation to conditional randomization moments. Optional two-sided conditional permutations use an explicit uint32 seed and 1–9,999 draws, bounded to 4,096 source rows and minimum-neighbors 1. The existing kNN limit remains 32. Distance-band permutation inference supports at most 64 active neighbors per row; denser neighborhoods fail explicitly instead of being truncated. This method samples without replacement from the eligible population while holding the focus observation fixed. Its smallest unadjusted p-value is `min(1, 2 / (permutationCount + 1))`; correction applies to finite tested p-values. The fixed source-wide neighbor graph is filtered for selected-population fits without replacement neighbors. Determinism applies to the same source ordering and seed; no GeoDa random-stream parity is claimed. Map colors show corrected significant high–high (red), low–high (light blue), low–low (blue) and high–low (orange) association; gray combines nonsignificant and undefined inference. Seven source-aligned table fields retain local I, z-score, centered spatial lag, raw and adjusted p-values, quadrant code and neighbor count. Local I uses `(n - 1) * centeredValue * spatialLag / sumSquaredDeviations`. Kept islands contribute to global moments with zero I and lag, but never receive analytic inference; constant values have undefined I. The summary separates undefined local I from included rows without inference under the selected method. Z-scores always describe the analytic approximation, while raw/adjusted p-values and map quadrant significance follow the selected inference. Permutation output publication waits for current successful completion status. Saved recipes retain the coordinate fields, topology and inference settings. Other weight transforms are not exposed.

Quantile LISA counts joins within one selected quantile of a single Float32 field on the same original point graph. Its type-5 quantiles include the lower boundary and exclude the upper boundary; tied values stay together, so quantile sizes can differ and classes can be empty. Numeric nulls and invalid coordinates are excluded before quantiling; islands remain in the quantile distribution but are excluded from inference. Controls expose quantile count, selected quantile, a nonnegative safe-integer seed, 1–9,999 permutations and significance level. Inference uses the existing contributor's legacy directed pseudo p-value `(min(upperTailCount, P - upperTailCount) + 1) / (P + 1)` without multiple-testing correction. This rule is anti-conservative, does not guarantee two-sided error control, and can report significance for tied or constant memberships. Uniform Philox sampling is reproducible for identical inputs but does not reproduce GeoDa's random stream or sampling. The map separates significant, unreported and isolated rows; six table fields expose pseudo p-value, observed join count, quantile membership, class, legacy tail count and significance. Untested tail counts use `4294967295`. Bounds, valid-row and island counts return as compact diagnostics; capacity errors prevent publication. Saved recipes explicitly retain the type-5, legacy-directed, uncorrected, islands-excluded contract.

Inverse-distance interpolation produces a separate north-up EPSG:4326 grid from original geographic sample rows. Controls specify longitude/latitude fields, degree bounds, width/height, spherical search radius in meters, distance power, nearest-sample limit, minimum samples and optional modified-Shepard taper. The initial host limit is 4,096 source rows and 16,384 cells, with at most 256 cells per axis. Radius-expanded bounds must stay clear of poles and the antimeridian because the contributor does not wrap its geographic search boxes. Numeric nulls, infinities and invalid coordinates are omitted. Exact cell-center hits use the smallest eligible source row and override the minimum-sample threshold; other sparse cells are nodata. Selected-population interpolation rebuilds its sample index and may choose replacement neighbors, independently of the fixed topology used by spatial statistics. A GPU color scale writes a resident nearest-sampled RGBA texture for a geographic BitmapLayer, with transparent nodata. Its cell-indexed inspector reads at most 16 rows per page, including cell center, value and contributing count; these cells never masquerade as original source rows. Saved recipes retain the full grid and population contract. An explicit GeoTIFF download reads at most 16,384 Float32 values (64 KiB) from the current grid. It writes one north-up, uncompressed numeric band in EPSG:4326 with PixelIsArea georeferencing, NaN nodata and the source revision and complete recipe in ImageDescription. The export retains its read and CPU memory reservation until the download is prepared and rejects a changed source, selection or grid. It exports values, not palette colors or sample counts, and does not claim cloud optimization, overviews, reprojection or multiband support. This IDW mode does not provide kriging variance, parameter fitting or cross-validation.

Ordinary kriging uses the same geographic source/grid limits and pole/antimeridian admission as IDW, with up to 16 retained nearest samples. Controls require a manual spherical, exponential or Gaussian variogram: nonnegative nugget and partial sill with a positive total, and a positive effective range in meters. Nugget and sill use squared response units. This mode does not fit a variogram or perform cross-validation. The prediction map stays separate from source-row layers; the bounded cell inspector reports prediction and kriging variance in squared response units. Variance describes the declared model, not empirically validated error or a confidence interval. Exact hits return the mean of retained duplicate observations with zero variance, even below the minimum distinct-position count; duplicates occupy neighbor slots before coalescing. The nugget represents microscale variation, not measurement error.

Kriging rejects nonfinite inputs and publishes a cell only when its prediction and nonnegative variance are finite. Compact diagnostics distinguish insufficient/invalid neighborhoods from rejected numerical solves; these counters do not explain every final nodata cell and must not be added as independent causes. The inspector does not invent per-cell neighbor counts or failure reasons. Separate prediction and variance GeoTIFF downloads include an explicit band metric, response-unit exponent and complete recipe provenance. Both use the same north-up EPSG:4326 and fenced readback policy as IDW. Host memory admission accounts for planned graph scratch before compilation, along with owned output buffers, texture and parameter buffers; driver-private shader memory is not measured.

Geographic DBSCAN clusters up to 4,096 original source rows using exact bounded OPTICS extraction with spherical great-circle meters. Longitude/latitude inputs can cross the antimeridian; this all-pairs operation does not use the fixed neighbor cache. Epsilon is a positive Float32 distance and minimum samples includes the focus row (1–256). Invalid coordinates and nulls are excluded; an unrelated numeric measure does not affect clustering. Selected population recomputes density and cluster membership. Cluster IDs are deterministic for an unchanged source order and population, but are not persistent identities across filters. Gray represents valid noise (`-1` in the primary table field); other colors cycle every 15 clusters. Raw labels and predecessor row IDs use `4294967295` for missing values, and non-core distances or root reachability can be infinite. Four additional table fields preserve raw labels, core distance, reachability and predecessor source row; OPTICS visit ordering remains a separate rank-to-row buffer. Compact diagnostics report clusters, noise, valid and excluded rows, and an incomplete traversal blocks publication. Float32 coordinate precision limits short-distance accuracy; this small-frame reference path does not claim indexed-CPU performance or native viewport-cluster parity.

Ordinary least squares fits a Float32 response from one to 15 ordered Float32 predictor columns, with an intercept and up to 65,536 original source rows. Missing or nonfinite inputs are excluded as complete cases, including Arrow validity for every field; a selected population is refitted and excluded rows stay missing rather than receiving held-out predictions. The map and table expose source-aligned residuals and fitted values only after a successful solver status. Singular or constant predictors and too few complete rows prevent publication. The compact report includes coefficients, classical Student-t inference, fit statistics, specification tests and conditioning, with nonfinite statistics shown as undefined. Standard errors use RSS/(n−p), including the intercept in p, and assume independent homoskedastic errors without robust or spatial covariance correction. Positive ridge penalties use original squared predictor units, do not penalize the intercept and do not standardize columns; these reports retain estimates, RSS, R² and conditioning while suppressing classical inference, adjusted R² and likelihood criteria. Float32 precision warnings remain visible even when a fit succeeds. The fixed 64-row reduction tile and saved ordered predictor list make the computation policy explicit.

Dorling cartograms lay out up to 1,024 source-aligned circles from explicit projected Float32 X/Y coordinates and a nonnegative area-value field. The declared CRS and meter bounds remain in the recipe. Area scale converts a value to projected square meters, with radius `sqrt(value * areaScale / pi)`; zero values remain stationary zero-radius circles, and missing, negative or invalid-coordinate rows are excluded. The selected population recomputes the layout without replacing source geometry or uploading source data again. Controls expose 0–256 relaxation passes, origin attraction and overlap tolerance in projected meters. Zero passes return the initial layout. Compact diagnostics distinguish convergence from an exhausted iteration budget and report remaining penetration and displacement; finite unconverged layouts remain available. This is a bounded heuristic, with no GeoDa coordinate parity or guaranteed separation. Float32 spacing at large coordinate magnitudes can prevent movements smaller than the requested tolerance; the host reports that limitation and does not silently recenter coordinates.

Cartogram tables preserve source rows and batches with derived center X/Y, radius and source IDs. Arbitrary projected CRSs are table-only. Exact `EPSG:3857` results also use a separate Web Mercator circle overlay, with positions and radii scaled into Deck common coordinates; these are projected-plane units, not ground distance or equal-area measurements. Globe and non-Web-Mercator views refuse that overlay. The host checks the full circle extents, including radii, against the finite Web Mercator world; layouts extending beyond it remain available in the table with an explicit overlay-unavailable reason. A bounded overlay inspector shows the original source identity and computed circle values; clicking pins the inspection, and stale results are cleared. Native selection continues to refer to the original dataset and display geometry. The overlay does not invent geographic coordinates or replace a native source layer. Result buffers and pending table/picking reads retain their execution and source lifetime through completion.

The reusable `addKeplerPointWeights` binding exposes GPU CSR weights and source provenance. The host caches this topology by dataset revision, coordinate fields, coordinate system, declared projected CRS/bounds where applicable, distance metric, units and topology parameters (neighbor count or radius and storage capacity); the binary/all-coordinate-valid population policy is fixed. Filtering, numeric-field changes, rate scale, and inference settings reuse completed weights across rates, hot spots, Local Moran and Quantile LISA. The most recent entry survives disabling analysis, and retired programs retain older entries until their submissions and reads finish. Persistent outputs and retained build scratch are charged to the session memory budget. Cache builds become reusable only after submission is acknowledged; abandoned recordings do not advertise completed weights. The first exact search uses a fixed global grid and can approach quadratic work for dense clusters; reuse avoids repeating it but does not remove that initial complexity.

Polygon analysis uses a published GeoJSON geometry role and the original Float64 XY coordinates retained during ingestion. Queen contiguity matches an identical vertex; rook contiguity matches an identical whole undirected edge. Original coordinates are interned into exact integer equality tokens before GPU upload, so Float32 rounding cannot invent adjacency. Z is ignored; there is no snapping, noding, tolerance, antimeridian normalization or partial-edge equivalence. Holes and polygon parts in GeometryCollections participate. Nonpolygon, empty and malformed rows stay aligned with the source and are excluded from the analysis population; valid isolated polygons follow the selected island policy. The host supports up to 4,096 source rows and 65,536 inspected vertex occurrences, including ring closures. Larger sources remain renderable with an explicit analysis-unavailable reason.

Polygon spatial rates, Getis–Ord hot spots and Local Moran reuse a source-wide, symmetric binary queen/rook graph. Selection and numeric validity filter the population without rebuilding topology. Local Moran exposes the same analytic or conditional permutation inference, with at most 64 active neighbors for permutation inference. Controls explicitly reserve up to 262,144 directed neighbor slots and 1,048,576 candidate pairs. Neighbor overflow reports the required slot count; candidate overflow reports only a lower bound and asks for more candidate capacity. Either failure prevents map/table publication. Original geometry retention, bounded CPU preparation, GPU inputs, cached CSR results and build scratch are charged to the session budget. Saved recipes preserve the geometry role, rule, capacities and statistic settings; replay preflights geometry separately from prepared Float32 measures before changing native state.

Polygon Quantile LISA reuses the same exact queen/rook topology and source-aligned result columns. Finite valid polygon rows, including valid islands, define the type-5 quantile distribution; nonpolygon rows are excluded before computing boundaries. The first and last quantiles have unbounded outer endpoints. Inference excludes islands and requires positive joins among members of the selected quantile. Its directed legacy pseudo p-value, lack of correction, tie behavior and random-stream limitations are identical to the point mode described above. Selection recomputes quantile boundaries on the selected valid polygons and filters the fixed graph. Source rows are bounded to 4,096, with at least three rows and fewer quantiles than source rows. The summary reports the included finite population; filtering and ties can leave quantiles empty. More than 64 active neighbors or invalid quantile capacity prevents publication.

Grid hot-spot analysis requires an explicitly configured rectangular, row-major lattice. Width × height must equal the complete source row count; arbitrary longitude/latitude points are not treated as adjacent grid cells. Choose rook or queen neighborhoods, radius in cells, minimum neighbors, self weight and multiple-testing correction before applying the grid. Filtering preserves lattice row identities. The native table exposes Gi* z-scores, unadjusted two-sided p-values, corrected significance bins and neighbor counts; map colors show z-scores. Compact diagnostics report required links, undefined rows and any capacity failure. Saved recipes preserve the lattice and inference settings. Lattice permutation inference is not exposed.

The native Export Map dialog records source references, native map configuration, semantic selections and active analysis recipes. Replay can regenerate the fixture and rebuild GPU buffers; portable bundles include uploaded sources. Page export and all-selected export are separate, explicitly requested bounded readback operations.

Exports select a resident dataset and either prepared GPU JSON, original-source Arrow/CSV, or computed analysis JSON/Arrow/CSV. Original Arrow keeps source types, timestamps, geometry and dictionary domains. Analysis exports preserve computed scalar types and nulls in Arrow, plus original row identities and recipe/revision metadata; CSV includes a companion metadata JSON download. The selected export rows are independent of the recipe’s all/selected reference population. Changing results or source revisions cancels publication of an in-progress analysis export. Combined Arrow/CSV exports append current computed fields to selected original rows without re-reading source columns from the GPU. Colliding computed names receive an _analysis suffix and an explicit name map in the export metadata.

Device loss immediately detaches rendering and clears stale inspection, counts and analysis results. Healthy checkpoints retain original Arrow references, native configuration and analysis recipes in page memory. The **Recover GPU workspace** button creates a replacement Deck device, reimports original dataset IDs and restores filters and recipes before activating rendering. Device creation has a 30-second timeout; cancellation retains the checkpoint for an explicit retry. Recovery never starts automatically and does not write or upload source rows. Closing or reloading the page loses these in-memory checkpoints; export a portable bundle when persistence is required.

Stream prefixes require explicit preview permission. Analysis, SQL and other complete-population consumers reject open, cancelled and failed streams by default. The current save/recovery schema rejects those unfinished populations; a rejected stream checkpoint retains the last valid complete checkpoint and reports that limitation. Completed streams use normal save/export/recovery. Registry device-loss recovery keeps stream status with retained CPU sources; it does not silently convert a prefix into a finite dataset. A marked partial-stream bundle format is not yet supported.
