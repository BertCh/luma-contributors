# Block relationships implementation note

This inquiry uses archived source feature IDs 342227 (source row 21), 815550 (row 1118) and 815551 (row 1119) from the bundled Chicago building-footprint dataset. The source properties list 16 W Erie St, 14 W Erie St and 22 W Erie St; these are archived attributes rather than verified current addresses. Each selected feature retains its polygon rings and source ID.

The compute scene projects the selected coordinates into the dataset's local planar metre frame centered near the three footprints. It uses GPU geometry measures and `GPUBoundsFilter` for an analyst-controlled square query. `GPUSharedPaths` compares the ring set with itself; the application reads back the runs, drops self-building and duplicate reverse line pairs, and uploads the unique cross-building shared runs to `addBuildingAdjacencyRecipe`. The recipe receives GPU `GPUShapeDescriptors` axial orientations and its own graph outputs are copied into application-owned readback buffers.

For the tessellation comparison, `GPUBufferSurface` applies either a zero-distance pass or a hypothetical negative 0.4 m inset. The scene packs its actual GPU output rings into segment rows, then invokes `addBuildingTessellationRecipe` with an analyst-defined convex enclosure, a selectable 16/128-site cap and the selected 4/8/16 m sample spacing. Result polygons and statuses are copied from recipe graph views before asynchronous readback. Areas are planar shoelace summaries of the GPU-readback ring coordinates in square metres.

The visibility graph uses 16 synthetic observer probes positioned just outside the selected footprint group, the original building rings as obstacles, an analyst-defined convex enclosure, and a selectable 25/55/100 m maximum edge length. Its copied edge list has a separate 8/120 capacity, while all dense graph metrics still use the complete valid probe-pair graph. Readouts select GPU outputs for degree, reachability, hop integration, raw and normalized choice, relative-asymmetry variants and the pyramid, Teklenburg, Penn and maximum-depth summaries. The displayed enclosure, inset distance and observer coordinates are scenarios; they do not represent parcels, access, height-aware sightlines, current occupancy or real people.

References for method context: [momepy morphological tessellation](https://docs.momepy.org/en/v0.11.0/user_guide/elements/tessellation.html), [momepy tessellation API](https://docs.momepy.org/en/v0.10.0/api/momepy.morphological_tessellation.html), and Turner et al., [From isovists to visibility graphs](https://discovery.ucl.ac.uk/160/1/turner-doxa-osullivan-penn-2001.pdf). These references motivate the constructs; the local GPU recipe contracts define the implementation behavior.
