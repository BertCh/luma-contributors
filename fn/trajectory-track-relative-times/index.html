Int64 epoch-millisecond words to float32 ticks after each track's own first fix.

Reading the result

A float32 cannot hold a current epoch in milliseconds; it is off by tens of seconds. Differences taken on the words are exact, so a track is exact while it spans fewer than 2^24 ticks. The output feeds float32 trajectory paths such as time-ratio simplification.

Parameters

PropTypeDescription
timestamps*GraphDataView<"uint32x2">Int64 word timestamps, (low, high) per row.
trackOffsets*GraphDataView<"uint32">Track-to-row offsets with one terminal entry.
temporalContextGPUTemporalContext | undefinedOptional declaration; must be int64-words.
and 1 more required: output

Returns

FieldTypeDescription
outputGraphDataView<"float32">Ticks after the first row of each track.

Example

import {GPUTrajectoryTrackRelativeTimes} from '@luma-contributors/analysis/gpu-spatial-analysis';

// graph: GPUCommandGraph; timestamps: uint32x2 words of epoch milliseconds
graph.add(new GPUTrajectoryTrackRelativeTimes({
  timestamps,
  trackOffsets,
  output: relativeTimes
}));
const compiled = await graph.compileAsync();
compiled.encode(device.commandEncoder, {parameters: undefined});
// relativeTimes is the float32 time column other trajectory operations read
