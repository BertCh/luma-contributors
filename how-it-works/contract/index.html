The contributor contract

Every operation follows the same rules, so every operation composes and fails the same way.

In short
  • A contributor is one class: props in, a validating constructor, kernels out.
  • Bad props fail at construction, by name. A kernel cannot throw, so it writes status.
  • A checker keeps every operation on the same rules.

One shape

Every operation is a class with a props type and an output type. The constructor checks the props once; getCommandNodes returns the kernels without touching the graph.

Fail early, by name

These are the library's validators, running here. Each message starts with the contributor and names the prop and the limit. Nothing is checked per frame or per row.

The rules

Thirteen rules, in five families. Each links to the page that explains it.

Shape

  • rule 1One class per operation

    A contributor is a class with Props and Output types; a recipe composes contributors.

  • rule 12Registered

    Every exported contributor has an entry in the operator catalog.

  • rule 13One public home

    The contract is imported from analysis-core, and no luma.gl symbol is re-exported.

    How it works: upstream first

Parallel by construction

  • rule 2No loop over rows

    Totals, counts and compaction use scan, reduce, sort and compaction, never one invocation looping over the data.

    How it works: building blocks
  • rule 3Candidates by index

    Neighbours come from a grid index or a sort, not from all pairs.

    How it works: building blocks
  • rule 4Rounds with a budget

    Rounds are gated on the GPU, and a search that hits its limit still publishes its result.

    How it works: iteration

Parameters and context

  • rule 5Per-frame parameters

    A number that changes no buffer shape lives in a parameter buffer, so changing it does not recompile.

    How it works: scheduling
  • rule 6Declared context

    Coordinates, raster grids and time come from a declared context, not from literals in a shader.

Data conventions

  • rule 7One no-data rule

    A mask filters input rows; validity flags output rows; both are uint32.

    How it works: data on the gpu
  • rule 8One output layout

    Variable-length output is a compact output: ids, a clamped count and an overflow flag.

    How it works: data on the gpu
  • rule 11Shared numerics

    Random numbers, order-independent sums and exact tests come from shared code, not copies.

Status and limits

  • rule 9Named status

    Status uses the port names of the contract; a contributor never reads it back.

  • rule 10Named limits

    Construction throws an Error that starts with the contributor ID and names the prop and its range.

Status, not exceptions

Construction can throw. The GPU run cannot, so a kernel records what happened in named ports and the caller chooses whether to look.
