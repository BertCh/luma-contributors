Loops without readback

Rounds are laid out in advance and gated on the GPU. A finished search runs zero workgroups.

In short
  • An iterative search is written into the graph when the graph is built: maximumIterations: 256 gives 256 relax kernels, one per round.
  • Each round writes the next round's workgroup count on the GPU. An empty queue dispatches zero workgroups, so the CPU never asks whether the search is done.
  • When the budget runs out, the result is still published, with converged = 0.

A loop without readback

A shortest-path search repeats one round: relax the roads out of every node whose cost just improved, until nothing improves. On the CPU you would write while (!done), but done lives in a GPU buffer, and a readback is asynchronous: the CPU waits for the GPU to finish before it can submit the next round.

A contributor never reads status back (contract rule 9), so the rounds are laid out ahead of time. This code produced the run on this page; the highlighted line builds 256 rounds.

A recorded search

This run searched 1,199 intersections of the Chicago Loop from one start, with travel time as the cost and localIterations = 1, so each round moves one road further. Each round relaxes the queue of nodes whose cost improved in the round before.

A node lights at the last round whose queue it joined: its cost is final from then on (the record's lastImprovedRound stamp). A node can be queued more than once, so a bar can count more nodes than the map lights at that round.

Zero workgroups

Every push that opens a new 256-entry chunk of the next queue adds one workgroup to the next round's indirect dispatch. A round that received no pushes dispatches zero workgroups, and so does every round after it: that is the gate.

Round k reads its count from reachability-dispatch-even or reachability-dispatch-odd and writes round k + 1's into the other, because one buffer cannot be an indirect argument and a storage write in the same dispatch. The round index sits in the same 256-byte slot, never in the shader text, so one compiled pipeline serves all 256 rounds.

Contributors without a queue gate on a state word instead (createWGSLDispatchGate): once a one-thread kernel disarms it, every later round launches nothing.

When the budget runs out

The number of rounds is fixed when the graph is built. If the search needs more, the result is still published: nodes settled by then keep their cost, the rest are not final yet, and status says so.

The budget is checked once, at construction. Too many rounds throws network-reachability maximumIterations must be an integer in [1, 1024]; a contributor whose kernel count grows with a prop exposes estimatedCommandNodeCount and throws past 32,768, as in network-cost-table estimated command node count must be at most 32768.

Graph size grows with the budget: this search needed 37 rounds, and its graph holds 272 nodes because it was built for 256.

Where else

90 of 427 recorded runs have gated kernels: 11,203 of 37,919 kernels over all records. Regionalization, triangulation and terrain flow gate the most.
