Scheduling

Compile fixes the order once. Each frame only encodes it, and one small buffer changes the answer.

  1. Buffers
  2. Build
  3. Compile
  4. Encode

  6. Read back
In short
  • Compile orders the kernels and creates the pipelines once. The graph cannot change after that.
  • Each frame only encodes that fixed order and submits it.
  • Numbers that do not change a buffer size or a loop bound live in a small parameter buffer: a write changes the answer without compiling again.

Once, then every frame

Compiling a graph does the planning; encoding it does none. Kernel density, compiled once, runs every frame, and a new bandwidth is a write into its parameter buffer.

compile once, encode every frame
import type {Device} from '@luma.gl/core';
import {GPUCommandGraph, type GraphDataView} from '@luma.gl/graph/gpu-core';
import {
  getGPUKernelDensityParameterValues,
  GPU_KERNEL_DENSITY_PARAMETER_LENGTH,
  GPUKernelDensity
} from '@luma-contributors/analysis/gpu-spatial-analysis';
import {GPUParameterBuffer} from '@luma-contributors/analysis/analysis-core';

// Construct: props are validated here, once.
const parameters = new GPUParameterBuffer(device, {
  id: 'kde-parameters',
  format: 'float32',
  length: GPU_KERNEL_DENSITY_PARAMETER_LENGTH, // 9 float32 values
  values: getGPUKernelDensityParameterValues({bandwidth: 400}, grid)
});
graph.add(
  new GPUKernelDensity({
    positions,
    parameters: parameters.importToGraph(graph),
    grid,
    indexGridSize: [32, 32],
    indexBounds: extent,
    output: {values: density}
  })
);

// Compile, once: order the kernels, create the pipelines. The graph freezes.
const compiled = await graph.compileAsync();

// Every frame: record the fixed order and submit it. Nothing is re-planned.
function encodeFrame(): void {
  const commandEncoder = device.createCommandEncoder();
  compiled.encode(commandEncoder, {parameters: undefined});
  device.submit(commandEncoder.finish());
}

// Between frames: a new bandwidth is a buffer write, not a recompile.
function setBandwidth(bandwidth: number): void {
  parameters.write(getGPUKernelDensityParameterValues({bandwidth}, grid));
}

The rule behind this: a prop that changes a buffer size or a loop bound is fixed at compile time; any other number is read from a parameter buffer every frame.

One shared pass

Encoding opens a compute pass and keeps it open while the next kernel is also a compute kernel; a copy or render node closes it. Timing queries, or coalesceComputePasses: false, give each kernel its own pass.
