# Oracle fixture generators

Maps each file in `fixtures/` to the script that produced it. Fixtures are checked in and are not regenerated by tests. See `requirements.txt` for the pinned library set recorded in fixtures and generators.

Names in parentheses are the number of fixtures in the family; `N` stands for a numeric index (grid size, seed, tile or case number). Paths are relative to this directory. Generators are run from the repository root, for example `python modules/graph/test/oracles/<generator>`, with the interpreter from `requirements.txt`.

## How the mapping was derived

- **Literal**: the generator source names the fixture file (or a full-name f-string expands to it). 540 of 746 fixtures.
- **Inferred**: the generator builds the fixture name dynamically (`f'...-{case}-{index}.json'`), so the family was matched by the name stem and topic against the generator source. Confidence is lower; the generator for the same wave (`parity-wpN-*`) with the matching topic is listed. Ambiguous cases list every candidate.
- **Unresolved**: no generator found. Provenance is only what the fixture itself records (`versions`, `command`, `source`).

Other oracle sources not producing `fixtures/`: `*.R` (R/terra/gstat/blockCV/landscapemetrics), `geometry-straight-skeleton.cpp` and `interpolation-cgal.cpp` (CGAL 6.0.1 with Boost 1.87.0), `parity-wp6-round8-spatstat.mjs`, and `upstream-golden/` (vendored upstream golden outputs, see its README).
