# Oracle fixture generators

Records historical mappings from files in `fixtures/` to candidate generator scripts. These mappings are not a current execution inventory. Fixtures are checked in and are not regenerated by tests. See `requirements.txt` for the pinned library set recorded in fixtures and generators.

Execution is governed by [scripts/oracle-fixtures.json](../../../../scripts/oracle-fixtures.json),
which records generator kind, interpreter profile and exact test-relative input/output paths.
This prose is provenance, not a runtime output detector. `oracle-fixture --list` shows executable
fixture families; inventory and unconfigured entries fail explicitly instead of comparing nothing.
Every declared output must be regenerated in staging before comparison or copy-back, including
under `--write`. See [script gates](../../../../dev-docs/script-gates.md) for commands, exit codes,
the separate pyxccd environment, explicit visibility tools/audit paths and source inventory usage.
Embedded `generator` fields name the runnable manifest owner, including outputs written through
imported helper functions. Recorded source paths are repository-relative and their SHA-256 digests
cover exact input bytes. Refresh contours before stitched contours so the latter records the new
upstream digest; provenance-only corrections preserve numerical payloads and recorded versions.

Names in parentheses are the number of fixtures in the family; `N` stands for a numeric index (grid size, seed, tile or case number). Paths are relative to this directory. Generators are run from the repository root, for example `python modules/analysis/test/oracles/<generator>`, with the interpreter from `requirements.txt`.

## How the historical mapping was derived

- **Historical literal**: the generator source names the fixture file (or a full-name f-string expands to it). 542 of the historical 748 fixtures mapped; this is not the current census (see Counts).
- **Historical inferred**: the generator builds the fixture name dynamically (`f'...-{case}-{index}.json'`), so the family was matched by the name stem and topic against the generator source. Confidence is lower; the generator for the same wave (`parity-wpN-*`) with the matching topic is listed. Ambiguous cases list every candidate.
- **Historical unresolved**: no generator found. Provenance is only what the fixture itself records (`versions`, `command`, `source`).

Historical notes on other oracle sources not producing `fixtures/`: `*.R` (R/terra/gstat/blockCV/landscapemetrics), `geometry-straight-skeleton.cpp` and `interpolation-cgal.cpp` (CGAL 6.0.1 with Boost 1.87.0), `parity-wp6-round8-spatstat.mjs`, and `upstream-golden/` (vendored upstream golden outputs, see its README).
